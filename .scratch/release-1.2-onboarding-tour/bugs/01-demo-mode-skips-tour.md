# Баг Б-1 — Демо-режим не запускает Приветственный тур (онбординг помечен завершённым при регистрации)

Type: bug
Status: open
Найдено при: релиз 1.2, тикет 02 (проверка входа в тур через демо-режим — Out of Scope тикета, вынесено в баг)
Затрагивает: демо-вход (`LoginView.vue` «Демо-режим»), онбординг-гейт (`main.js:186`)

## Доказательство расхождения

Заявка Павла, шаг 1 тура: «Пользователь переходит по ссылке, например из репозитория,
на демо-версию» — то есть демо-режим мыслится как один из входов в Приветственный тур.
Фактически демо-вход **минует тур целиком**:

- `web/src/components/LoginView.vue:70-97` — `startDemo(slug)` регистрирует демо-аккаунт
  через `POST /api/v1/demo/register`, затем `enterDemo()` уводит на `#/today` + reload.
  Ни `startTour()`, ни маршрут `/onboarding/tour` не вызываются;
- `api/src/main/java/ru/wolf/api/demo/DemoRegisterService.java:71` — демо-пользователь
  создаётся **с** `onboardingCompletedAt(Instant.now())`, то есть онбординг помечен
  завершённым уже в момент регистрации;
- онбординг-гейт `web/src/main.js:186-190` пускает пользователя дальше только если
  онбординг **не** завершён; для демо-аккаунта `isOnboardingCompleted` = true, поэтому
  редиректа на `/onboarding/profile` (и, соответственно, на тур) не происходит.

Итог: демо-пользователь попадает сразу на `/today` с загруженным профилем, Приветственный
тур ему не показывается. Вход по инвайту (`RegisterView.vue:45` → `/onboarding/profile` →
`load-profile` → `/onboarding/tour`) тур запускает штатно — расхождение только у демо-входа.

## Почему это важно

Заявка релиза 1.2 прямо называет демо-версию точкой входа в тур. Сейчас единственный путь
к 15-шаговому онбордингу — регистрация по инвайту. Гость, пришедший «по ссылке из
репозитория» через демо-режим, методологию через тур не увидит, что расходится с
постановкой.

## Область (что НЕ входит в этот баг)

- Тикет 02 релиза 1.2 сознательно оставил починку демо-входа за рамками (Out of Scope:
  «Вход через демо-режим — только проверка, починка (если понадобится) отдельным багом»).
- Приветственное окно тура (шаг 2 заявки, «шаг 1 из 15») реализовано движком тикета 01 и
  показывается на штатном пути входа по инвайту — этот баг его не касается.

## Возможные направления решения (на приёмку владельца)

Решение требует продуктового выбора — фиксируется владельцем, здесь только варианты:

- **A.** Демо-аккаунт создавать с `onboardingCompletedAt = null` и вести через
  `/onboarding/tour` (демо-гость проходит тот же тур; данные профиля уже загружены —
  шаги-действия тикета 09 §4, вариант A, вырождаются в информационные, как при повторном
  запуске).
- **B.** В `enterDemo()` явно вызывать `startTour({ firstRun: true })` и уводить на
  `/onboarding/tour`, не трогая модель (онбординг остаётся завершённым, тур — как
  повторный запуск из шапки).
- **C.** Оставить как есть (демо = быстрый осмотр без тура), но тогда убрать из текста шага
  1 упоминание демо-версии как входа в тур — расхождение снимается на уровне формулировки.

## Закрывает

Проверку тикета 02 «вход через демо-режим приводит к запуску тура». Ответ: не приводит —
зафиксировано багом, а не починено молча (`docs/agents/issue-tracker.md`).
