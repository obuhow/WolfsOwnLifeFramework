# Тикет 09 — Шаг 16: финальное окно и выход из тура

Status: resolved
Blocked by: 01 (resolved)
Type: task

Шаг заявки: 16 (финал Приветственного тура). Сквозная нумерация: **15 из 15**.

> В заявке «Действие: **Сохранение первой рутины**», но шаг про План нагрузки (заявочный 15)
> идёт **после** рутин. Порядок исправлен: финал наступает по завершении шага про План
> нагрузки, а не по сохранению рутины (grill реш. H).

## Вопрос

Показать финальное окно с итогами и вывести пользователя из тура в полный интерфейс.

## Доказательство контекста

Механика выхода **уже существует** (релиз 0.6, тикеты 03/04):

- `OnboardingTour.vue:301-311` — `finish()` различает два случая:
  - **первый вход** (`isFirstRunTour()`) → `router.push('/onboarding/final')` — Финальный
    выбор «Оставить»/«Очистить» демо-данные (тикет 0.6-04, `OnboardingFinalChoice.vue`).
    Комментарий в коде объясняет почему: «гость обязан решить судьбу демо-данных сам, и
    `onboarding_completed_at` проставит уже выбранная им ветка»;
  - **повторный запуск из шапки** → `await completeOnboarding()` +
    `router.push({ path: '/calendar', query: { view: 'week' } })`. Показывать «Очистить»
    нельзя — «пользователь давно живёт в системе, и кнопка удалила бы его настоящие данные»;
- `exitLabel` (`:92`) — «Завершить» на последнем шаге, «Пропустить» на остальных.

То есть кнопка «Завершить тур» из заявки — это существующая кнопка выхода; менять развилку
не нужно, нужно нарастить финальное окно.

## Что сделать

### 1. Финальное окно (`placement: 'center'`, движок тикета 01)

Последний элемент `STEPS`: модальное окно по центру, без выреза (затемнение целиком).
Завершение — нажатие кнопки «Завершить тур» (не клик по интерфейсу).

Текст (заявка; 🐺-пункты покрыты ADR-0008, реш. A):

> 🐺 **Потрясающе! Вы заложили фундамент своей системы.**
>
> 🐺 Вы создали первый проект и поняли, как оценивать его трудоёмкость.
> 🐺 Зафиксировали время в Ежедневнике.
> 🐺 Настроили поддерживающую рутину.
>
> Дальше система начнёт работать на вас. Нажмите «Завершить тур», чтобы настроить профиль под
> себя и начать охоту за своими целями.

Правки против заявки: «Проект»/«Рутину» с заглавной в перечислении итогов оставлены
строчными там, где это не термин-ссылка (стилистика; на существо не влияет — при
несогласии владельца вернуть). Восклицательный знак в последней фразе снят под тон
«Уютно. Тихо. Под вашим контролем».

Счётчик: «шаг 15 из 15».

### 2. Кнопка «Завершить тур»

Переиспользовать существующий контрол выхода (`:342`), задав на последнем шаге подпись
«**Завершить тур**» (сейчас «Завершить»). Кнопка «Пропустить» на финальном шаге не нужна —
это и есть завершение.

### 3. Развилка выхода — не менять

`finish()` работает как есть: первый вход → `#/onboarding/final`; повторный запуск →
`/calendar?view=week`. Тексты заявки («настроить профиль под себя») согласуются с Финальным
выбором — там гость решает судьбу демо-данных.

### 4. Поведение шагов-действий при повторном запуске тура (открытый вопрос тикета 01 §5)

При повторном запуске из шапки тур ведёт пользователя **создавать** проект, дело, запись
времени и рутину в его **настоящем** аккаунте — то, что уместно для демо-гостя, для
работающего пользователя означает мусорные сущности.

Решить в рамках этого тикета одним из способов и зафиксировать в `## Answer`:

- **A (рекомендуемый):** при повторном запуске шаги-действия (`await: 'event'`) вырождаются
  в информационные: подсказка показывается, но шаг засчитывается по кнопке «Далее» без
  требования создать сущность. Текст остаётся объясняющим;
- B: при повторном запуске тур идёт по прежнему 6-шаговому маршруту «обзор меню» (сценарий
  0.6), а 15-шаговый — только для первого входа;
- C: предупреждать в первом окне, что тур создаст реальные записи, и давать выбор.

Вариант A сохраняет ценность тура как справки и не мусорит данными.

### 5. Проверка очистки данных, созданных туром

Финальный выбор «Очистить» (тикет 0.6-04) должен удалять и то, что гость создал **во время
тура** (проект, дело, записи времени, рутину), а не только загруженный демо-профиль. Если
окажется, что очистка их не затрагивает — **завести баг** в `bugs/` этого релиза с
доказательством (запрос/ответ API, состояние БД), а не дочинивать молча (`docs/agents/issue-tracker.md`).

## Testing Decisions

- Финальное окно: по центру, счётчик «шаг 15 из 15», три 🐺-пункта итогов, кнопка
  «Завершить тур».
- **Первый вход:** «Завершить тур» → `#/onboarding/final` (Финальный выбор доступен).
- **Повторный запуск из шапки:** «Завершить тур» → `/calendar?view=week`,
  `onboarding_completed_at` проставлен (`POST /api/v1/onboarding/complete`).
- **Поведение по варианту A:** при повторном запуске шаги-действия не требуют создания
  сущностей; после полного прохода в аккаунте **не появилось** новых проектов/дел/рутин
  (сверить количества до и после через API).
- **Очистка:** первый вход → полный проход тура (созданы проект, дело, записи, рутина) →
  Финальный выбор «Очистить» → проверить через API, что созданные туром сущности удалены.
  Если нет — баг с доказательством.
- Область исключения ADR-0008: 🐺 присутствует **только** в узлах оверлея; на странице под
  оверлеем эмодзи нет.
- Мобильный 390×780: финальное окно не выходит за границы вьюпорта, кнопка достижима.
- `npm run build` зелёный.

## Answer (resolved, 2026-09-01)

Status: resolved.

- **Финальное окно (`n: 15`, `await: 'finish'`, `placement: 'center'`)** — в движке т.01:
  три 🐺-пункта итогов (ADR-0008), счётчик «шаг 15 из 15», кнопка «Завершить тур»
  (`.tour-finish`). Затемнение целиком (`hole: null`).
- **Развилка выхода не менялась** (`finish()`): первый вход → `#/onboarding/final`
  (Финальный выбор), повторный запуск → `completeOnboarding()` + `/calendar?view=week`.
- **§4 — поведение шагов-действий при повторном запуске: выбран вариант A.** При повторном
  запуске (`!isFirstRunTour()`) шаги `await: 'event'` вырождаются в информационные:
  `isInfoStep` показывает кнопку «Далее», шаг засчитывается ею без требования создать
  сущность. Так тур сохраняет ценность справки и НЕ мусорит настоящий аккаунт
  проектами/делами/записями/рутинами. Навигационные шаги (`nav`/`click`) при повторе
  работают как есть — навигация мусора не создаёт.
- **§5 — очистка данных, созданных туром: проверено, баг НЕ нужен.**
  `UserPurgeService.purgeProfileData` (`api/.../user/UserPurgeService.java`) явно удаляет
  `timeEntryRepository` (:136), `deloRepository` (:138), `projectRepository` (:139) и
  `routineRepository` (:122) пользователя — то есть ВСЕ проекты/дела/записи/рутины аккаунта,
  и загруженные из демо-профиля, и созданные во время тура. Финальный выбор «Очистить»
  (0.6-04) вызывает этот сервис. Orphan-free гарантирует `ProfilePurgeIT`. Данные тура
  очищаются — расхождения нет.
- **Единое имя**: заголовок Финального выбора приведён к «Приветственный тур завершён»
  (`OnboardingFinalChoice.vue`), точка входа — «Открываю Приветственный тур…»
  (`OnboardingTourEntry.vue`) — правки тикета 01 §6.
- `npm run build` и `npm test` зелёные.
