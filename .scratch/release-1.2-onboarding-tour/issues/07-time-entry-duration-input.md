## Вопрос

При клике по **свободному** слоту недельной сетки Ежедневника дать возможность указать
длительность («1 ч 30 м», «90 минут», «1.5 ч») — запись создаётся на N последовательных
15-минутных слотов, а не на один.

## Доказательство контекста

- `web/src/components/WeekView.vue:736` — `onCellClick(slot, span = 1)` →
  `POST /api/v1/time-entries/grid-click` (`:742`);
- для пустого слота открывается picker выбора Дела: `:765-771` — `pickerSlot`, `pickerMode`
  (`'delo' | 'adhoc' | 'create'`), `pickerDeloId`, `pickerAdHoc`, `pickerFilter`.
  **Поля длительности в picker нет** — запись создаётся на один слот;
- модель: глоссарий `CONTEXT.md`, «**Запись времени**» — «Конкретный факт или план в **одной
  15-минутной ячейке**… В одной ячейке — не больше одной Записи». Изменение модели **не
  требуется**: длительность материализуется в N Записей (формулировка внесена в статью
  глоссария прожаркой релиза 1.2);
- бэкенд: `api/.../timeentry/TimeEntryService.java` уже умеет ветки `EXTEND` / `SHRINK` /
  `SPLIT` по краям (`:333-345`, `:376-395`) — то есть создание последовательных слотов
  укладывается в существующий контракт, но **N слотов одним запросом** контракт
  `grid-click` не предусматривает. Способ реализации выбрать при работе:
  - вариант A: N последовательных вызовов `grid-click` с фронта (без изменений API);
  - вариант B: новый параметр `slots`/`durationMinutes` в `grid-click` (изменение контракта +
    IT-тесты).
  Вариант A предпочтителен как минимальное изменение (правило «наименьшее изменение,
  сохраняющее модель»); при выборе B обосновать в `## Answer`.

## Что сделать

1. **Поле длительности в picker** пустого слота (`WeekView.vue`): рядом с выбором Дела —
   ввод длительности с разбором человеческого формата: «1 ч 30 м», «1ч30м», «90 м»,
   «90 минут», «1.5 ч», «1:30». По умолчанию — **15 минут** (текущее поведение, чтобы
   пользователь, который просто подтвердил выбор Дела, получил ровно то же, что и сейчас).
2. **Округление вверх до кратности 15 минут** с явной подсказкой в UI («шаг 15 минут»):
   «20 м» → 30 м. Некратные значения молча не искажать.
3. **Кнопка подтверждения** — заявка шага 11 говорит «нажмите галочку подтверждения».
   Существующая кнопка подтверждения picker'а сохраняется; отдельную «галочку» вводить не
   обязательно, но подтверждающий контрол должен быть достижим с клавиатуры и иметь
   `aria-label`.
4. **Занятые слоты не перетирать:** если диапазон длительности упирается в существующую
   Запись, создать записи **до** препятствия и сообщить об этом пользователю нейтральным
   текстом (без красного/тревожного оформления — контракт 0.3). Молчаливая перезапись
   запрещена: «в одной ячейке не больше одной Записи».
5. **Событие для тура:** после успешного создания диспатчить
   `document.dispatchEvent(new CustomEvent('wolf:time-entry-saved', { detail: { slots } }))`
   — нужно движку тура (тикет 01, шаг 11). Вне тура ни на что не влияет.
6. **Совместимость с «Карандаш+»** (тикет 1.1-07): форма длительности работает **только по
   клику по свободному слоту вне активного режима «Карандаш+»**. Когда тумблер включён, клик
   по слоту означает ±15 мин и picker открываться **не должен**. Если 1.1-07 к моменту
   работы ещё не влит — оставить точку расширения и отметить в `## Answer`.

## Answer (resolved, 2026-09-01)

Status: resolved. **Вариант A** (N последовательных вызовов `grid-click` с фронта, без
изменения контракта API) — минимальное изменение, модель Записи не трогаем.

- **Разбор формата** вынесен в `web/src/durationParse.js` (`parseDuration`/`durationToSlots`)
  — тестируемо отдельно. Понимает «1 ч 30 м», «1ч30м», «90 м», «90 минут», «90 мин»,
  «1.5 ч», «1,5 ч», «1:30», голое «90». Округление **вверх** до кратности 15 («20 м» → 30),
  минимум 15. Пустой/непонятный ввод → 15 (регресс на «один слот»). Юнит-тест
  `web/durationParse.test.mjs` в `npm test`.
  - Замечание по реализации: для кириллических единиц вместо `\b` (он в JS определён для
    ASCII `\w`) используется негативный lookahead `(?![a-zа-я])` — иначе «1 ч 30 м» не
    парсился.
- **Поле длительности** добавлено в picker свободного слота (`WeekView.vue`), в режимах
  «Дело» и «ad-hoc», по умолчанию «15м». Подсказка «Шаг 15 минут — округляется вверх».
- **Создание N слотов**: `submitPicker` в цикле шлёт `grid-click` на последовательные
  15-минутные слоты; занятые ячейки **не перетирает** — при упоре в существующую Запись
  останавливается и показывает нейтральное уведомление `pickerNotice` (без красного —
  контракт 0.3): «Создано слотов: N. Дальше время уже занято…».
- **Событие тура**: после успешного создания диспатчится `wolf:time-entry-saved`
  (`detail.slots` = сколько создано) — один раз, только при `created > 0`.
- **Совместимость с «Карандаш+»** (1.1-07, влит): когда `quickEditMode` включён, клик по
  свободному слоту, дающий `NEED_PICKER`, **не открывает** picker (±15 мин остаётся за
  бэкендом) — два способа сосуществуют, не пересекаясь на одном клике.
- **Бэкенд не изменён** (вариант A): `TimeEntryService`/`grid-click` те же; `TimeEntryApiIT`
  править не требуется.
- `npm test` и `npm run build` зелёные; `wolf:time-entry-saved` в бандле.
