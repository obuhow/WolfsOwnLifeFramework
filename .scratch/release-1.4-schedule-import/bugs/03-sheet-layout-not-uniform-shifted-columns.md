# Б-3 — Раскладка сетки не одинакова на всех листах: последние два сдвинуты на две колонки

Type: bug
Status: resolved
Найдено при: release-1.4 (импорт «Расписание.xlsx»), реализация тикета 01 — в результатах
прод-парсера появилась «активность» с названием `0` (95 ячеек), все на двух последних листах.
Регрессия в: не регрессия — **неполнота артефакта разведки**. `spike/RESULT.md` описывает
одну раскладку («время — колонка C», «активности — колонки D–J») как свойство файла; она
верна только для 9 листов из 11. Спайк этого не заметил, потому что искал даты по всей
строке 1 без привязки к колонкам, а `spec.md` и `issues/01` зафиксировали C/D–J как жёсткий
контракт формата.

## Симптом

При жёстко заданных колонках (время C, дни D–J) два последних листа дают мусор вместо
данных:

```
=== Топ-10 активностей ===
     237  Отдых
     228  Уезжаю на отдых
     168  Java
     108  Муз курсы
     104  Сон
      95  0        ← мусор
      ...
=== Диагностика подозрительных активностей ===
  2026-08-05 00:00 лист=3-9 августа  активность=«0»
  2026-08-06 00:00 лист=3-9 августа  активность=«0»
  ...
```

Двойной ущерб: в импорт попадают несуществующие Записи времени с названием `0`, а реальное
содержимое этих двух недель теряется.

## Доказательство расхождения

Сканирование всех листов (в каких колонках стоят серийники дат, подписи дней и дробь
времени):

```
лист            дата-серийники   подписи дней     время
1-7 июня        DEFGHIJ          DEFGHIJ          C
8-14 июня       DEFGHIJ          DEFGHIJ          C
15-21 июня      DEFGHIJ          DEFGHIJ          C
22-28 июня      DEFGHIJ          DEFGHIJ          C
29-5 июля       DEFGHIJ          DEFGHIJ          C
6-12 июля       DEFGHIJ          DEFGHIJ          C
13-19 июля      DEFGHIJ          DEFGHIJ          C
20-26 июля      DEFGHIJ          DEFGHIJ          C
27-02 августа   DEFGHIJ          DEFGHIJ          C
3-9 августа     BCDEFGH          BCDEFGH          A     ← сдвиг на 2 влево
10-16 августа   BCDEFGH          BCDEFGH          A     ← сдвиг на 2 влево
```

Сырой дамп листа «3-9 августа» подтверждает: `r0` = серийники в B..H (`46237`…), `r1` =
подписи «Понедельник»…«Воскресенье» в тех же B..H, время — дробь в колонке A, а в колонке J
живёт посторонний блок «Задачи на неделю» / «Крестики-нолики Java» / «AI.Безопасность» /
«KNAV». Именно из этой зоны и приходил `0`, когда парсер читал D–J.

Побочно на этих же листах обнаружен **маркер пустоты «-/-» (202 ячейки)**, которого нет в
списке активностей спайка — очевидный аналог «Неизвестно» (46 ячеек). По решению И-C
(«пусто = неизвестно» не материализуется) он тоже не должен становиться Записью.

## Как закрыт

Тикет 01, ветка `release-1.4/feature/01-grid-format-parser`, коммит `df3d472`.

- раскладка определяется **для каждого листа отдельно** (`detectLayout`): колонки дней = те,
  где в строке 1 стоит серийник даты; колонка времени = соседняя слева от первой из них;
- берутся только **семь самых левых** колонок с датами, поэтому боковые блоки справа
  («Задачи на неделю») не могут стать восьмым днём;
- «-/-» добавлен в `SKIPPED_ACTIVITIES` рядом с «Неизвестно»;
- регресс-тест `detects_the_grid_columns_per_sheet_instead_of_assuming_them` строит лист
  именно в сдвинутой раскладке (время в A, дни B–H, посторонний блок в J) и требует, чтобы
  разобрались реальные ячейки и не попал `KNAV` из бокового блока; маркер «-/-» закреплён в
  `skips_empty_cells_and_the_unknown_marker`.

## Влияние на эталонные числа тикета

После исправления Б-1..Б-3 прод-парсер на реальном файле даёт:

| Показатель | Спайк (`RESULT.md`) | Прод-парсер (факт) |
|---|---|---|
| Недель | 11 | 11 |
| Ячеек-активностей | 1943 | **2117** |
| Уникальных активностей | 67 | **78** |
| Диапазон дат | 1 июня – 16 авг | 2026-06-01 – 2026-08-16 |

Расхождение объяснимо целиком: спайк терял содержимое двух сдвинутых листов и при этом
считал «Неизвестно» (46) как активность, а «-/-» (202) не встречал вовсе. Чек-строка тикета
01 со сверкой «1943 записи, 67 активностей» исправлена на фактические числа — см. правку в
`issues/01-grid-format-parser.md`.
