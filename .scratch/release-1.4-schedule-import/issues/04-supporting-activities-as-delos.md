# 04: Поддерживающие активности как Дела с пометкой

**What to build:** Поддерживающие активности (Сон, Еда, В дороге, Питание, Обед…) при импорте
становятся Делами, но помечены как «поддерживающие» — чтобы их можно было отличать и
группировать при взгляде (разговорно «Рутина»), не путая с Делами-единицами работы. «Сон» не
дублируется — переиспользует существующее Дело механизма «Ночные часы».

**Blocked by:** 01

**Status:** resolved (`<feature-branch>`) — флаг в схеме, сущности, API и логике резолва;
«Сон» без дубля; покрыто unit + IT тестами.

- [x] Новый флаг «поддерживающее» у сущности `Delo` (миграция **V43**)
- [x] При маппинге активности пользователь может пометить создаваемое Дело как «поддерживающее»
      (поле `supporting` в `CreateDeloRequest`/`UpdateDeloRequest` и ответах)
- [x] «Сон» (и вариации регистра) → привязывается к существующему Делу «Сон» (Ночные часы), без создания дубля
- [x] Флаг доступен в ответах API Дела (`DeloResponse.supporting`, `DeloDetailResponse.supporting`) для группировки в отображении и в контексте агента
- [x] Поддерживающие Дела остаются обычными Делами для модели (Записи времени ссылаются на них как на Дела; отдельной сущности Рутина не вводим)
- [x] Тест: импорт активности из списка поддерживающих → Дело с флагом; «Сон» → без дубля
- [x] Решение О-2: новый boolean-столбец, а не переиспользование тега/поля — обосновано в `Answer`

## Реализация (О-2)

Новый столбец `delo.supporting BOOLEAN NOT NULL DEFAULT FALSE` (V43__supporting_delo_flag.sql), а не
переиспользование `execution_mode` / `recurrence_*`. Обоснование: у `Delo` нет подходящего
семантического поля для «класса активности»; булев флаг даёт явный, индексируемый признак для
выборок (`WHERE supporting`) и честную сериализацию в API без перегрузки существующих полей. Решение
И-B соблюдено: отдельной сущности «Рутина» нет, поддерживающие — те же Дела.

## Что изменилось

- `Delo.supporting` (boolean, default false) + миграция V43.
- `DeloResponse` / `DeloDetailResponse`: добавлено поле `supporting`. Для обратной совместимости
  вызовов тестов/кода оставлены доп. конструкторы без флага (делегируют `supporting=false`).
- `CreateDeloRequest` / `UpdateDeloRequest`: опциональное `Boolean supporting`.
- `DeloService`: пробрасывает `supporting` при create/update и в оба `toResponse`.
- Новый класс `SupportingActivities` (пакет `importxlsx`): нормализация (trim + схлопывание
  пробелов) и классификация класса 1 по списку из grill И-A (Сон, Еда, В дороге, Питание, Обед,
  Завтрак, Ужин, Полдник, Душ, Гигиена, Отдых, Прогулка). `isSleep(...)` выделяет «Сон» для Т-1.
- `XlsxImportService.resolve`: при создании Дела для неизвестной активности —
  - «Сон» (любой регистр) → переиспользует существующее Дело «Сон» (Ночные часы) без дубля;
    если оно уже есть без флага, проставляет `supporting=true` при первом использовании;
  - прочие поддерживающие → Дело с `supporting=true` (если пользователь не переопределил явно);
  - рабочие Дела → `supporting=false`.

## Тесты

- `SupportingActivitiesTest` (unit): нормализация, классификация класса 1, «Сон» case-insensitive.
- `XlsxSchedulePreviewApiIT`:
  - `resolving_sleep_uses_existing_sleep_delo_without_duplicate` — «Сон» (в нижнем регистре в
    файле) резолвится в существующее Дело «Сон» без дубля, флаг `supporting=true`, Записи DONE
    привязаны к тому же Делу;
  - `resolving_supporting_activity_marks_delo_supporting` — «Еда» → `supporting=true`, «Java» → `false`.

Проверено на свежем Testcontainers Postgres (IT) + unit. Смежные `DeloApiIT`, `RecurrenceApiIT`,
`importer.*` — зелёные (не сломаны добавленные конструкторы DTO).
