# 07: Агрегация подряд идущих ячеек одного Дела в одну Запись времени

**What to build:** При `apply` импортированной недельной сетки подряд идущие 15-минутные
ячейки одного Дела с одним статусом сохраняются в БД как одна Запись времени с непрерывным
интервалом. Пользователь должен увидеть в Ежедневнике и в данных одну запись «Дело 09:00–11:00»,
а не восемь записей по 15 минут.

**Blocked by:** 02, 03, 05

**Status:** resolved (`a6b79a2`, выравнивание теста `59620b1`)

## Контракт группировки

- Источник остаётся 15-минутной сеткой: каждая заполненная ячейка парсится и учитывается в
  preview, но перед записью в БД соседние ячейки группируются.
- Группа строится внутри одного календарного дня, если следующий слот начинается ровно в момент
  окончания предыдущего (`+15 минут`), имеет ту же нормализованную активность, то же Дело и тот
  же статус.
- Пустой слот, маркер `-/-`/«Неизвестно», разрыв, смена активности, смена Дела, смена статуса
  или переход через полночь начинают новую группу.
- `startAt` группы равен началу первой ячейки, `endAt` — концу последней. Схема БД и сущность
  `TimeEntry` не меняются: используются существующие `startAt`/`endAt`.
- Для неизвестной активности одинаковые нормализованные ячейки одного непрерывного участка
  образуют одну `UNKNOWN`-Запись и один логический вопрос по активности, а не вопрос на каждый
  15-минутный слот.

## Взаимодействие с конфликтами

- Конфликт по-прежнему считается на уровне исходной 15-минутной ячейки.
- `SKIP_ALL`: занятые слоты не трогаются; свободные участки по обе стороны занятого слота
  сохраняются разными Записями и никогда не пересекают существующую запись.
- `OVERWRITE_ALL`: занятые слоты заменяются данными файла и могут войти в общий непрерывный
  интервал с соседними ячейками того же Дела.
- `CANCEL`: не создаёт ни Запись, ни прогон импорта.
- Повторная загрузка того же файла остаётся идемпотентной по хешу.

## Testing decisions

Тестировать через публичные HTTP-контракты и чтение пользовательских Записей времени:

1. три слота `09:00`, `09:15`, `09:30` одного Дела → одна запись `[09:00, 09:45)`;
2. тот же набор с пустым `09:15` → две записи;
3. смена активности и переход `23:45` → `00:00` → отдельные записи;
4. неизвестная активность → одна `UNKNOWN`-запись на непрерывный участок и один вопрос;
5. `SKIP_ALL` с занятым средним слотом → две свободные записи по сторонам;
6. `OVERWRITE_ALL` с тем же случаем → одна запись после замены;
7. повторное применение того же файла → без новых записей.

## Реализация

- `ScheduleEntryGrouper` — чистая логика группировки: сортировка кандидатов по `startAt`,
  продолжение группы только при совпадении дня, встык по времени (`endAt` предыдущей ячейки ==
  `startAt` следующей) и совпадении ключа активности, Дела и статуса. Дубликат слота (две
  активности в одной ячейке) отклоняется до группировки, а не молча теряется.
- `XlsxSchedulePreviewService` строит одну `TimeEntry` на группу: `startAt` первой ячейки,
  `endAt` последней, Дело и статус из первой ячейки; вопрос по неизвестной активности
  заводится один на группу. Схема и DTO не менялись — агрегированная Запись живёт на
  существующих `startAt`/`endAt`.
- `SKIP_ALL` фильтрует занятые слоты **до** группировки, поэтому занятая ячейка физически
  разрезает непрерывный участок: свободные части сохраняются разными записями и не пересекают
  существующую.
- `OVERWRITE_ALL` заменяет только занятые 15-минутные части существующих Записей; непокрытые
  фрагменты длинной записи сохраняются отдельными интервалами, поэтому перезапись не стирает
  факт за пределами импортируемых ячеек. Уникальный индекс `(user_id, start_at)` учитывается:
  удаления сбрасываются на диск до восстановления фрагментов.
- Preview отдельно показывает исходные ячейки (`totalCells`) и число Записей после группировки
  (`timeEntriesToCreate`, семантика `SKIP_ALL` — безопасный дефолт apply). В БД preview не пишет.
