# 06: WeekView — визуальное отображение непрерывных интервалов

**What to build:** В недельном календаре одна агрегированная Запись времени с интервалом
(например, «Java 09:00–11:00») показывается одним блоком, а не набором плиток по 15 минут.
Тикет 07 отвечает за агрегацию при импорте и хранение в БД; этот тикет отвечает только за
отображение и редактирование уже существующих интервалов.

**Blocked by:** None (может выполняться независимо; для полного сценария полезен тикет 07)

**Status:** resolved (`web/src/weekViewBlocks.js`, `web/src/components/WeekView.vue`)

- [x] Запись времени с `startAt`/`endAt` больше 15 минут отображается одним блоком с корректным
      диапазоном времени.
- [x] Для уже существующих легаси-данных соседние 15-минутные Записи с одним Делом и статусом
      могут визуально отображаться одним блоком, не меняя БД.
- [x] Разрыв, пустой слот, смена Дела или смена статуса завершает визуальный блок.
- [x] Клик по продолжению блока сохраняет точный 15-минутный подслот для режима редактирования;
      изменение подслота не редактирует запись с неверным началом.
- [x] `npm run build` и тесты `WeekView` зелёные; существующий календарь не ломается.

## Notes

В коде уже есть частичный механизм построения блоков (`weekViewBlocks.js`), но его критерий
продолжения основан на том же `entry.id`. Он корректно отображает одну длинную Запись, однако
не решает визуальное объединение старых соседних 15-минутных записей с разными `id`. При
реализации не дублировать этот механизм, а расширить его на согласованный контракт.

## Реализация

- Единый контракт слияния — `entryMergeKey(entry)` в `web/src/weekViewBlocks.js`: ключ
  `d:<deloId>:<status>` для записи с Дедом, `a:<adHocText>:<status>` для ad-hoc текста,
  `null` — слияние невозможно. Локальный дубль этого ключа из `WeekView.vue` удалён: в
  компоненте остался только вызов модуля (механизм больше не описан в двух местах).
- `buildDayBlocks` продолжает блок, пока следующая ячейка покрыта либо **той же записью**
  (`id`), либо записью **с тем же ключом слияния**. Это ровно два нужных случая: одна длинная
  Запись из тикета 07 и легаси-хвост из соседних 15-минутных Записей с разными `id`.
- Блок измеряется по фактическим краям содержимого: `startAt` первой покрытой записи →
  `endAt` последней покрытой записи. Раньше подпись бралась из одной записи, поэтому визуально
  слитые легаси-строки давали диапазон длиной 15 минут вместо реального интервала.
- Каждая ячейка-продолжение (`kind: 'cont'`) несёт **свою** покрывающую запись и свой
  `startAt`: клик по подслоту попадает в точную 15-минутную ячейку и не правит соседнюю
  легаси-строку. Пустой слот, разрыв, смена Дела, текста или статуса рвут блок.
- Сетка ввода не менялась: 15 минут остаются шагом, БД при визуальном слиянии не трогается.

## Проверка

- `web/weekViewBlocks.test.mjs` — 6 сценариев контракта: (1) четыре соседние легаси-строки
  одного Дела и статуса → один блок `span=4` с подписью `Java 09:00–10:00`, каждая
  `cont`-ячейка несёт свой `entry.id`; (2) смена статуса рвёт блок; (3) смена Дела рвёт блок;
  (4) пустой слот рвёт блок; (5) ad-hoc текст сливается по тексту и статусу; (6) одна длинная
  Запись остаётся одним блоком, `cont` сохраняет её `id`.
- Прогоны в дереве релиза: `node weekViewBlocks.test.mjs` — OK; `npm test` (весь набор web) — все
  файлы зелёные; `npm run build` — сборка проходит (dist собран).
