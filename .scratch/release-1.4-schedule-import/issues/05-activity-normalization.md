# 05: Нормализация вариаций написания в две ступени

**What to build:** Разные написания одной активности не плодят лишние вопросы и Дела, но при
этом система не стирает молча различия, которые пользователь мог делать специально.

**Status:** resolved (`2f371f0`, исправление `946f461`)

- [x] **Ступень 1 (тривиальная, авто и молча):** обрезка пробелов, приведение регистра —
      «Сон»/«сон», «Java »/«Java» → одна активность
- [x] **Ступень 2 (смысловая, через подтверждение):** «в спортзал»/«Спортзал»,

- [x] Механизм `activity_mapping` позволяет разным текстам ссылаться на одно Дело — переиспользуется
- [x] Различающиеся по смыслу активности («Проект»/«Проект игры») НЕ склеиваются автоматически
- [x] Тест: пара вариаций регистра сворачивается авто; смысловая пара требует подтверждения; несвязанные не трогаются

## Реализация

- `ActivityTextNormalizer` задаёт автоматический ключ сравнения: trim, схлопывание пробелов и
  регистр без изменения отображаемой подписи активности.
- Preview и apply группируют варианты с одним автоматическим ключом; существующий
  `activity_mapping` ищется по нормализованному ключу.
- Для старых mapping-записей с несколькими внутренними пробелами есть fallback-поиск по тому же
  Java-ключу; обычный trim/case-вариант остаётся быстрым SQL-поиском.
- Смысловые варианты не угадываются: они остаются неизвестными до вызова существующего
  resolve-flow, после явного выбора Дела создаётся отдельный mapping на то же Дело.
- Список вопросов по неизвестным активностям отдаёт одну запись на нормализованный ключ; все
  записи времени при подтверждении переводятся из `UNKNOWN` в `DONE`.
