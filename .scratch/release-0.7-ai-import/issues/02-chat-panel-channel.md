# Канал чат-панель: карточка предпросмотра и подтверждение

Status: open
Blocked by: 01

## Question

Реализовать первый (приоритетный) канал импорта — текстовый ввод в чат-панели интерфейса с карточкой предпросмотра.

## Что сделать

1. Новый компонент чат-панели (встроенный в существующий интерфейс, точное место — плавающая панель или раздел «Управление потоком», см. решение по месту при реализации) с текстовым полем ввода, вызывающим `ImportParserService.parse` через новый эндпоинт `POST /api/v1/import/parse`.
2. Карточка предпросмотра — редактируемые поля для каждого кандидата сущности, визуально в тихом контракте 0.3 (без ярких рамок/иконок предупреждения, поля с нижним правилом как в остальном интерфейсе). Несколько сущностей в одном сообщении — одна общая карточка-список с одним подтверждением на всё.
3. Однозначные поля (`CONFIDENT`) отображаются как уже заполненные, не требуют отдельного клика на каждое; поля `NEEDS_CONFIRMATION` визуально выделены как черновик (например, приглушённым цветом текста — не красным) до правки или подтверждения.
4. Занятый слот — три кнопки-варианта (Заменить / Сдвинуть / Создать поверх) прямо в карточке, без отдельного модального окна.
5. Если `unparsed: true` — бот отвечает одним уточняющим вопросом текстом («Не понял, что за дело — уточни в паре слов?»), не создаёт черновую карточку из пустоты.
6. Подтверждение → `POST /api/v1/import/confirm` с финальными значениями полей → создание сущностей (Дело/Проект/Рутина/правило повторения).

## Testing Decisions

- Ввод фикстур из тикета 01 в браузере → карточка с ожидаемым разбиением на однозначное/черновое → подтверждение → запись видна в Ежедневнике/на Дорожной карте.
- Занятый слот в браузере — все три варианта кликабельны и дают ожидаемый результат.
- `unparsed` сценарий — уточняющий вопрос без создания сущностей.
- Гейт: сборка → пересоздание контейнера → сверка хэшей с `web/dist` → аутентификация в браузере → инспекция DOM.

## Out of Scope

Telegram и Max каналы (тикеты 03, 04) — используют тот же бэкенд-контракт, но не эту UI-реализацию.
