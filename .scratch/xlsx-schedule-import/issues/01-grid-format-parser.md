# 01: Парсер формата недельной сетки Excel

**What to build:** Детерминированный парсер, который читает реальный `Расписание.xlsx`
(недельная сетка) в промежуточную модель — список записей `(дата, время начала, текст
активности)` — готовую к материализации в Записи времени. Парсер знает конкретный формат
владельца и не полагается на прежние (неверные для этого файла) допущения `XlsxImportService`.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

Формат подтверждён спайком (`spike/RESULT.md`, `sample/ANALYSIS.md`):
- лист = неделя; имя листа («1-7 июня») даты НЕ содержит;
- **row 1** — даты-серийники Excel в колонках D–J; **row 2** — заголовки дней;
- дни **Вс–Сб**: колонка D = воскресенье (сдвиг на 1 относительно Пн-Вс);
- время — колонка C (дробь суток), день начинается ~07:00;
- активности — колонки D–J в строках-слотах (где C — время-дробь);
- внизу листа блок «Факт» (часы по категориям) — игнорировать.

- [ ] Excel-серийник → дата с компенсацией бага 1900-високосного (серийник 46174 → верная дата)
- [ ] Время из дроби колонки C → `LocalTime`, кратное 15 минутам
- [ ] Правильное сопоставление колонок D–J дням недели (D = воскресенье)
- [ ] Активности берутся только из строк-слотов; блок «Факт» и строки вне сетки не попадают
- [ ] Пустые ячейки и «Неизвестно» → в модель не попадают (пропуск)
- [ ] Юнит-тест на образце (`sample/Расписание.xlsx`): 11 недель, ожидаемое число записей и уникальных активностей (сверка со `spike/RESULT.md`: 1943 записи, 67 активностей)
- [ ] Реализация на Apache POI внутри feature `importxlsx` (POI уже в зависимостях), логика эквивалентна `spike/xlsx_spike_parse.py`
