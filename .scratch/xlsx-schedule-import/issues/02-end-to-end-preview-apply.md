# 02: Сквозной импорт happy-path (preview → apply)

**What to build:** Полный путь пользователя: на странице `/import/xlsx` загружаю
`Расписание.xlsx` → вижу **сводку предпросмотра** (сколько недель, заполненных ячеек,

появляются мои реальные Записи времени. Первый момент «я вижу своё полугодие в WOLF».

**Blocked by:** 01 (снят: парсер смёржен в `develop`)

## Previous implementation (obsolete after decision update)

Исторически это было реализовано отдельными классами `XlsxSchedulePreviewService` + `dto/ImportPreviewResponse`,
`dto/ImportApplyResponse` (слоистость 0.9: тонкий контроллер, сервис, DTO-records). Парсер
тикета 01 переиспользован как есть — `ScheduleCell` под это и делался, правок в нём не
потребовалось.

Исторические тесты старого контракта давали: `XlsxScheduleGridParserTest` 14/14,
`XlsxSchedulePreviewApiIT` 8/8, `XlsxImportApiIT` 2/2 — зелёные на реальном PostgreSQL
(Testcontainers). `npm run build` зелёный (`index-B7M2ItiI.js`).

### Решения, принятые в тикете

- **И-D (новое решение владельца)** — один непрерывный блок одного Дела = одна Запись
  `DONE` с `startAt/endAt`. 15 минут — шаг сетки; склейка соседних ячеек выполняется до
  записи в БД. Разрыв или смена Дела создаёт отдельную строку.
- **И-F** — время из Excel трактуется как локальное время пользователя, UTC-конверсий нет
  (WOLF хранит `LocalDateTime`). Проверено ассертом: 07:00 в файле → `startAt` T07:00,
  `endAt` T07:15.
- **И-C** — пустая ячейка **не** материализуется. Прежний импорт создавал на каждую пустую
  ячейку Запись `UNKNOWN`, из-за чего полупустая неделя выглядела полуполной; это
  зафиксировано регресс-тестом `blank_cells_create_nothing_and_reimport_is_idempotent`.
- **Конфликтующий интервальный блок** при применении не перезаписывается, а считается
  (`skippedOccupied`). Стратегии «пропустить/перезаписать/отменить» — объём тикета 03; до него безопасное
  поведение по умолчанию — не трогать существующий факт.

### Отступление от тикета: парсер старого пути удалён

Тикет в разделе «Совместимость» spec.md требовал решить: поддержать оба формата или
заменить. **Выбрана замена.** `XlsxImportService.upload()` удалён вместе со своими
допущениями — дата из имени листа, дни A–G, слоты от 00:00. Для реального файла владельца
все три неверны, а `parseWeek` при неудаче молча подставлял `2026-04-06`, то есть прежний
импорт «работал» на выдуманной неделе. В репозитории других XLSX-форматов нет, поэтому
дублировать парсер было бы поддержкой формата, которого не существует.

`XlsxImportApiIT` переписан под фактический формат сетки; его прежнее ожидание «пустая
ячейка → Запись `UNKNOWN`» отменено решением И-C.

### Обратная совместимость `ImportResponse` (пункт 8)

Пункт закрыт осмысленнее, чем «добавить поля»: `ImportResponse` со всеми прежними полями
(`id`, `status`, `totalCells`, `mapped`, `unknown`, `pendingQuestions`) сохранён и
по-прежнему отдаётся `GET /import/xlsx/{id}` — то есть на ресурсе **прогона**, где эти поля
и имеют смысл. Ответ `POST /import/xlsx` теперь имеет форму preview (п. 1 требует «preview
без записи»), поэтому `id`/`status` в нём отсутствуют: до нажатия «Применить» сущности ещё
не существует, и выдумывать её идентификатор было бы хуже, чем его не иметь. UI обновлён
согласованно, внешних потребителей у эндпойнта нет.

## Decision update

Прежняя материализация N×15 слотов отменена. Тикет снова требует реализации apply и
регрессионных тестов для интервальных блоков: один нормализованный Delo/content + один
статус + непрерывные соседние ячейки → одна строка с `startAt/endAt`.
