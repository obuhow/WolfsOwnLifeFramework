# Баг Б-3 — версия в шапке не соответствует релизу (показывает 0.6.0)

Type: bug
Status: resolved
Найдено при: релиз 1.0 (живой сайт, шапка)
Регрессия в: `release-0.6-demo-onboarding`, тикет 08 (Отображать версию WOLF в шапке),
Status: resolved

## Доказательство расхождения

Тикет 0.6-08 поднял единый источник правды до `0.6.0` и зафиксировал его в
`web/package.json` + `api/build.gradle`. Но после релизов 0.7/0.8/0.9 нумерация
**не поднималась**, хотя фактическая версия системы ушла в 0.9 (слой архитектуры
замерджен в `develop`, см. `wayfinder-release-0.9-layered-arch`):

```text
grep -n '"version"' web/package.json
  "version": "0.6.0",            ← неизменно с релиза 0.6

grep -n "version" api/build.gradle
  version = '0.6.0'              ← неизменно с релиза 0.6
```

Шапка берёт версию из `__APP_VERSION__` (`web/vite.config.js:14-17` →
`pkg.version` из `web/package.json`), выводит `v{{ appVersion }}` (`App.vue:282,394`).
Следовательно, на живом сайте после 0.7–0.9 пользователь видит **v0.6.0** — версия
врёт относительно фактического состояния продукта.

Тикет 0.6-08 в `Answer` явно пишет: «Дальнейшие релизы обновляют оба файла синхронно».
Это правило нарушено три релиза подряд.

## Почему это важно

- Версия в шапке — единственный сигнал пользователя о том, какой релиз перед ним.
  Расхождение «0.6.0» при реальном 0.9+ сбивает с толку при баг-репортах
  («у меня 0.6, а в релизе 0.9…»).
- Нарушает задокументированное правило синхронного бампа (0.6-08 Answer).

## Что сделать

1. Поднять `web/package.json` → `"version": "1.0.0"`.
2. Поднять `api/build.gradle` → `version = '1.0.0'`.
3. Убедиться, что при каждом будущем релизе бамп делается синхронно (занести в
   чеклист релиза / README).
4. Браузерная приёмка: пересборка `web` → в шапке `v1.0.0`.
5. Решить, оставлять ли `resolved` у 0.6-08 — баг не в самом механизме отображения
   (он работает), а в несоблюдении правила бампа; статус меняет владелец.

## Как закрыт

Закрыт в тикете `issues/01-bump-version-1.0.0.md` (бамп обоих файлов + приёмка в шапке).
