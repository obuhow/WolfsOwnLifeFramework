# Grill-with-docs — сессия прожарки терминов релиза 1.0

Проведена против `CONTEXT.md` (глоссарий) и `docs/adr/`. Цель — убедиться, что термины,
используемые в тикетах релиза 1.0, совпадают со словарем проекта, и зафиксировать новые
понятия, которых в словаре ещё нет.

## Термины из заявки → статус в глоссарии

| Термин (из заявки)            | Глоссарий `CONTEXT.md`                | Решение |
|-------------------------------|---------------------------------------|---------|
| Финальный срок проекта        | «Проект … опционально имеет сроки»   | ✅ покрыто полем `endDate`; нового термина не нужно, оставляем «сроки»/«дата окончания» |
| Распределение времени         | «Проект … плановые часы»; `planDistribution` | ✅ покрыто enum `PlanDistribution` (NONE/EVEN_ALL_DAYS/EVEN_WEEKDAYS) |
| Вложенные проекты             | «Проект … Может содержать вложенные проекты (подпроекты — тот же тип)» | ✅ термин есть; решение — раскрывать `parent_id` в Утреннем обходе |
| Утренний обход                | «Утренний обход (страница)»          | ✅ есть |
| Синхронизация данных          | «Синхронизация данных» + «Внешний идентификатор» | ✅ есть; CSV-экспорт опирается на тот же `DataSyncContract` |
| Демо-профиль                  | ❌ **отсутствует**                    | ➕ добавлен |
| Демо-пользователь             | ❌ **отсутствует** (есть только «Seed-аккаунт admin») | ➕ добавлен |
| Демо-режим                    | ❌ **отсутствует**                    | ➕ добавлен |
| Администрирование (страница) | навигация, не домен                   | ⚠️ оставляем как название вкладки, в глоссарий не выносим (не сущность) |
| Приветственный тур            | навигация/онбординг                   | ⚠️ оставляем как название ссылки |

## Новые записи, внесённые в `CONTEXT.md`

1. **Демо-профиль** — декларативное описание предзаполненного набора данных
   (`assets/profiles/<slug>.json`): области жизни, проекты (со сроками относительно
   «сегодня»), Дела, цели, рутины, заметки. Загружается в аккаунт при первом входе
   (онбординг) или повторно из Настройок. _Avoid_: реальные данные пользователя.
2. **Демо-пользователь** — временный аккаунт, созданный из демо-профиля гостем через
   демо-режим; логин вида `GoodEnoughDemoUser-<Буква><N>` (A1…Z1, A2…), пароль совпадает
   с логином; удаляется администратором вручную. Отличается от seed-аккаунта `admin`
   (исторический однопользовательский вход, ныне заблокирован). _Avoid_: рабочий аккаунт,
   авто-удаляемый по расписанию.
3. **Демо-режим** — точка входа на неавторизованном экране: кнопка «Демо-режим» открывает
   выбор демо-профиля и создаёт демо-пользователя. _Avoid_: онбординг (тот требует уже
   аутентифицированного пользователя).

## Открытые вопросы к владельцу (не блокируют тикеты)

- **Безопасность**: новый `POST /api/v1/demo/register` (permitAll) создаёт пользователя
  с паролем = логин. Противоречит ли это ADR-0001 (персональные данные одного пользователя)?
  Решение: демо-пользователи изолируются по tenant (своё пространство) и помечаются
  префиксом логина + флагом для админ-фильтрации; брутфорс ограничивается префиксом
  `GoodEnoughDemoUser-` (не угадываемые имена). Зафиксировано в `issues/07`.
- **CSV vs XLSX**: канонический раунд-трип — `wolf-data` workbook (xlsx). CSV-экспорт
  добавляется как человекочитаемый + импортируемый (тот же `DataSyncContract` по колонкам);
  импортёр расширяется приёмом csv-набора. См. `issues/09`.

## Вывод

Словарь проекта покрывает 6 из 9 терминов заявки. Три отсутствующих (демо-семейство)
добавлены в `CONTEXT.md`. Расхождений с существующими ADR не выявлено; один
security-релевантный вопрос по демо-регистрации вынесен в тикет 07 как решение владельца.
