## Problem Statement

Релиз 1.0 — не функциональный прирост, а «укладка»: закрываем перенесённые техдолги
предыдущих релизов и правим баги, обнаруженные на живом сайте после релизов 0.6–0.9.
Часть из них — чистые недоделки вертикального среза (поле есть в модели, нет в форме),
часть — рассинхрон имени релиза и того, что показано в шапке, часть — невыложенный в
контроллер эндпоинт при наличии сервис-метода. Плюс пять доработок, которые пользователь
(Павел) сформулировал по итогам использования: вложенность проектов в Утреннем обходе,
порядок ссылок в шапке, демо-режим для неавторизованного гостя, инструкция по HTTPS,
и CSV-экспорт всех сущностей рядом с Синхронизацией.

Отдельно проведена сессия **grill-with-docs** (доменная прожарка терминов релиза против
`CONTEXT.md`): подтверждены существующие термины, выявлены отсутствующие
(«Демо-профиль», «Демо-пользователь», «Демо-режим») — внесены в глоссарий.

## Релизная нумерация (закрывает Б-3)

Фактическая версия системы после релизов 0.7/0.8/0.9 — **0.9** (слой архитектуры
замерджен в `develop`). Файлы `web/package.json` и `api/build.gradle` при этом остались
на `0.6.0` (см. доказательство в `bugs/03-header-version-not-bumped.md`). Релиз 1.0
поднимает единый источник правды до `1.0.0` в обоих файлах синхронно (тикет 01).

## Обнаруженные баги (живой сайт, релиз 1.0)

Живут в `bugs/01`–`bugs/05` со сквозной нумерацией релиза. Б-5 в заявке **не описан**
(оставлен пустым) — заведён как `needs-info` заглушка, требуется уточнение от Павла.

- **Б-1** — при создании проекта нет поля финального срока (`endDate`).
- **Б-2** — переключатель распределения времени («Равномерно по дням / по будням»)
  всегда заблокирован, видна только подпись «Нужны даты и плановые часы». Корень — Б-1.
- **Б-3** — версия в шапке не соответствует релизу (показывает 0.6.0 при фактическом 0.9+).
- **Б-4** — кнопки «Привязать Telegram» / «Привязать Max» в Настройках дают HTTP 403:
  фронт шлёт `POST /bot/{telegram,max}/link`, а контроллеры не выкладывают этот маппинг.
- **Б-5** — не описан (заместитель).

## Доработки

1. **Вложенность проектов в Утреннем обходе.** Родитель и дочерний проект раскрываются
   иерархически (Проект WOLF → WOLF MVP), а не на одном уровне.
2. **Ссылка «Приветственный тур»** — между «Документация» и «Настройки» в шапке.
3. **Демо-режим для неавторизованного гостя** + вкладка «Администрирование» для
   пользователя с ролью ADMIN, с выдачей инвайтов и просмотром/удалением пользователей.
   *(В заявке этот пункт поименован «Доработка 2» второй раз — перенумерован в Доработку 3
   во избежание коллизии; см. `issues/07-demo-mode-public.md`.)*
4. **Инструкция по подключению HTTPS-сертификата** (документ, не код).
5. **Экспорт всех сущностей БД в CSV** в формате, пригодном для обратного импорта,
   рядом с «Синхронизация данных».

## Out of Scope

- Новые функциональные экраны планирования/аналитики — релиз 1.0 только правит и закрывает.
- Миграция на отдельный микросервис админки — вкладка «Администрирование» живёт в текущем
  SPA, админ-API уже готов.
- Автоматическое удаление демо-пользователей по расписанию — только ручное админом
  (по требованию Павла).
- Смена схемы ролей (красивый RBAC) — достаточно существующих USER/ADMIN + префикса логина
  демо-пользователя для фильтрации.
