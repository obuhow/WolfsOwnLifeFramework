# 02 — Регистрация по инвайт-коду

**Type:** task
**Status:** resolved
**Blocked by:** 01 — Модель пользователя

**What to build:** Инвайт-коды как сущность + публичный `POST /api/v1/auth/register`, принимающий код, username и пароль, создающий полноценного пользователя со своими Сферами жизни и сразу выдающий JWT. Плюс экран регистрации, доступный с экрана входа.

## Scope

Миграция `V37__invite_code.sql`: `code` (unique), `created_by_user_id`, `max_uses INT NOT NULL DEFAULT 1`, `used_count INT NOT NULL DEFAULT 0`, `expires_at NULL`, `revoked_at NULL`, `note VARCHAR(255) NULL`, `created_at`.

`POST /api/v1/auth/register` (`permitAll`), тело `{ code, username, password }`, в одной транзакции:

1. код существует, `revoked_at IS NULL`, не истёк, `used_count < max_uses` — иначе единое нейтральное сообщение «Код недействителен»
2. username свободен (иначе явное «Имя занято» — это пользователю нужно), длина 3–100, безопасный алфавит
3. пароль ≥ 8 символов
4. создать `User(role=USER, status=ACTIVE, account_type=REGULAR, onboarding_completed_at=NULL)`
5. засеять 9 Сфер жизни через `LifeSphereSeeder`
6. `used_count++` с блокировкой строки (гонка двух регистраций по последнему использованию кода)
7. вернуть JWT — повторный логин не требуется

Фронтенд: маршрут `/register` (`meta.public`), три поля, ссылка «У меня есть код» с `/login` и обратная ссылка. Register-форма в UI-контракте 0.3: нижнее правило у полей, текстовое действие с подчёркиванием, без залитых кнопок.

## Checklist

- [ ] Миграция + сущность + репозиторий `InviteCodeRepository`
- [ ] Эндпоинт регистрации со всеми семью шагами в одной транзакции
- [ ] Генератор кодов: 10 символов, алфавит без `0/O/1/I/l`
- [ ] `RegistrationApiIT`: валидный, истёкший, отозванный, исчерпанный код; занятый username; короткий пароль; успех сеет ровно 9 Сфер
- [ ] Тест на гонку: два параллельных запроса по коду с `max_uses=1` дают ровно одну регистрацию
- [ ] Экран `/register` собран, задеплоен, проверен в браузере: регистрация по реальному коду доходит до `/onboarding` (или `/today`, если 08 ещё не готов)
- [ ] Ошибка API показывается текстом сервера, а не общим «Что-то пошло не так»

## Pitfalls

- Не раскрывать в ошибке, какое из условий кода нарушено — это перебор кодов.
- `used_count++` без `SELECT ... FOR UPDATE` (или атомарного `UPDATE ... WHERE used_count < max_uses`) допускает две регистрации по одноразовому коду.
- Не копировать список 9 Сфер в регистрацию — только `LifeSphereSeeder` из тикета 01.
