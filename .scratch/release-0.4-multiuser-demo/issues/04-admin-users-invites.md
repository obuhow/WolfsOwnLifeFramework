# 04 — Администрирование: пользователи и инвайт-коды

**Type:** task
**Status:** open
**Blocked by:** 01 — Модель пользователя; 02 — Регистрация по инвайт-коду; 03 — Изоляция арендатора

**What to build:** Админский API и экран «Пользователи» под `ROLE_ADMIN`: список пользователей, блокировка, сброс пароля, удаление со всеми данными, выпуск и отзыв инвайт-кодов. Обычный пользователь не видит ни экрана, ни пункта меню и получает 403 на эндпоинтах.

## Scope

**API `/api/v1/admin/**`, все под `hasRole('ADMIN')`:**

- `GET /users` — username, e-mail, роль, статус, тип аккаунта, создан, последний вход, число Проектов/Дел/записей времени. Демо-аккаунты скрыты по умолчанию, параметр `includeDemo=true` их показывает
- `POST /users/{id}/block` / `POST /users/{id}/unblock`
- `POST /users/{id}/reset-password` — генерирует временный пароль, возвращает его **один раз** в ответе (почты нет, передаётся вручную)
- `DELETE /users/{id}` — через `UserPurgeService` (тикет 03), с обязательным подтверждением username в теле запроса
- `GET/POST /invite-codes`, `POST /invite-codes/{id}/revoke`

**Правила защиты от самострела:**

- нельзя заблокировать, удалить или разжаловать самого себя
- нельзя удалить последнего активного `ADMIN`
- обе проверки — на бэкенде, а не только скрытием кнопки

**Фронтенд:** маршрут `/admin/users` + `/admin/invites`, пункт «Пользователи» в Настройках, видимый только при `role === 'ADMIN'` (роль читается из `/api/v1/auth/me`, расширенного полем `role`). Ruled-реестр по контракту 0.3, удаление — через `ConfirmInline`, без модальных окон и без красных заливок.

## Checklist

- [ ] Все админские эндпоинты + `@PreAuthorize`/matcher на `hasRole('ADMIN')`
- [ ] `GET /api/v1/auth/me` отдаёт `role`, `accountType`, `email`
- [ ] Защиты от самострела покрыты тестами
- [ ] `AdminApiIT`: обычный пользователь получает 403 на каждом админском маршруте
- [ ] Удаление пользователя реально стирает его данные (проверка через `UserPurgeServiceIT`-ассерты)
- [ ] Временный пароль работает на логине и показывается ровно один раз
- [ ] Экраны собраны, задеплоены, проверены в браузере под ADMIN и под обычным пользователем
- [ ] Под обычным пользователем пункт меню отсутствует в DOM, а не спрятан стилем

## Pitfalls

- Прятать админку только на фронте — не защита. Гейт на сервере.
- Удаление админом самого себя оставляет систему без администратора при единственном ADMIN.
- Не показывать в списке хэш пароля и токены даже в отладочных полях ответа.
