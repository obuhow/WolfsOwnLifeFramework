**What to build:** Короткий мастер из трёх шагов, каждый из которых создаёт реальную сущность через существующие API. По завершении — редирект на «Сегодня», где уже виден остаток нормы. Мастер одноразовый и пропускаемый.

> **Точка входа переформулирована.** В релизе 0.6 первым, что видит новый пользователь, становится выбор одного из трёх демо-профилей, а затем Знакомство — тур по интерфейсу. Эти три шага получают управление **только по ветке «Очистить профиль»** в финале Знакомства: гость, отказавшийся от предзаполненных данных, не должен оказаться в пустой системе. До выхода 0.6 мастер остаётся единственным первым входом и реализуется как описано. Решение принято при черчении карты `.scratch/wayfinder-releases-05-07/map.md`.

## Scope

**Маршрут `/onboarding`, не модальное окно.** Модалка поверх пустого «Сегодня» оставляет пользователя перед пустым «Сегодня», когда он её закроет.

**Guard в `main.js`:** аутентифицирован + `onboardingCompletedAt == null` + маршрут не `/onboarding` → редирект на `/onboarding`.

**Три шага, по одному вопросу на шаг:**

1. **Проект.** Одно поле «Название проекта» + пример-подсказка. `POST /api/v1/projects`. Проект требует Область жизни — если у пользователя нет ни одной, мастер молча создаёт «Мои дела» и кладёт проект туда.
2. **Цель.** «Что вы хотите продвинуть?» + недельный бюджет часов. Создаёт Цель, связанную с проектом из шага 1.
3. **Норма.** «Сколько часов в неделю у вас реально есть?», предзаполнено 30. Пишет `availableWeeklyHours` через существующий эндпоинт настроек.

**Сохранение пошаговое:** закрытая на втором шаге вкладка не теряет созданный на первом шаге Проект. Возврат в мастер продолжает с первого незавершённого шага.

**Завершение:** `POST /api/v1/onboarding/complete` ставит `onboarding_completed_at = now()` → редирект на `/today`. «Пропустить» на любом шаге делает то же самое, не создавая сущностей.

Созданные Проект и Цель — обычные сущности: переименовываются и удаляются как любые другие, никакого признака «создано мастером».

**Визуально:** контракт 0.3. Один вопрос на экран, поле с нижним правилом, «Далее» и «Пропустить» — текстовые действия с подчёркиванием. Без прогресс-бара шагов, без иллюстраций, без приветственного баннера.

## Pitfalls

- Guard без исключения для самого `/onboarding` даёт бесконечный редирект.
- Guard, срабатывающий до загрузки `/auth/me`, отправит в мастер уже прошедшего его пользователя. Дождаться профиля.
- Создание Проекта без Области жизни упадёт валидацией — обработать первый вход честно, а не показать пользователю ошибку API на первом же шаге.
- Не создавать «демонстрационных» заглушек: пользователь вводит свой реальный проект, иначе первое, что он делает после мастера — удаляет мусор.
