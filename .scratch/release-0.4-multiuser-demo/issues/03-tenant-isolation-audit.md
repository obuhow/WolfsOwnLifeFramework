# 03 — Изоляция арендатора: аудит, закрытие дыр, тест-гейт

**Type:** task
**Status:** open
**Blocked by:** 01 — Модель пользователя

**What to build:** Доказанная изоляция данных между пользователями. Сейчас она предполагается, но не гарантируется и не покрыта тестами. Тикет закрывает известные дыры, приводит все чтения-по-id к владельцу и вводит `TenantIsolationApiIT` как гейт релиза. **Ни 02, ни 06 не выкатываются на публичный адрес до закрытия этого тикета.**

## Scope

**Известные дыры (закрыть):**

- `SecurityConfig`: `/api/v1/delos/import` переводится из `permitAll()` в `authenticated()`. Ручное извлечение JWT из `HttpServletRequest` внутри `DeloImportController` (обходной путь 0.1, когда фильтр не ставил `Authentication` для `permitAll` multipart) удаляется — вместе с методом `currentUser(Authentication, HttpServletRequest)`.
- `AgentJob`: `userRepository.findAll()` → `findByAccountTypeAndStatus(REGULAR, ACTIVE)`.
- `DataSyncManifestController` не принимает `Authentication` — проверить, отдаёт ли он что-либо пользовательское; если да, привязать к владельцу, если нет (статический манифест) — зафиксировать это в `## Answer` явно.

**Аудит всех 36 контроллеров:**

- каждый доменный маршрут резолвит владельца из `Authentication`
- каждое чтение по id идёт через `findByIdAndUser(...)`, а не `findById(...)` с ручной проверкой или без неё
- чужая и несуществующая сущность дают **одинаковый 404**; 403 — только на админских маршрутах
- вложенные ресурсы (Дело внутри Проекта, вложение внутри Заметки, слот внутри повторения) проверяют владельца **корня**, а не только своего родителя

**`UserPurgeService`** — явное каскадное удаление всех данных пользователя в детерминированном порядке, в одной транзакции. Нужен тикетам 04 и 06. Полагаться на `ON DELETE CASCADE` нельзя: `note_attachment`, `delo_recurrence_slot`, `data_sync_preview_*`, `focus_review`, `load_curve`, `goal_metric_target` привязаны к пользователю транзитивно. Сервис завершается проверкой отсутствия осиротевших строк.

- [ ] Ручная проверка: старый скрипт импорта без заголовка получает 401, с заголовком — работает

## Pitfalls

- Соблазн закрыть тикет по «все контроллеры принимают Authentication» — приём параметра не равен фильтрации по нему. Смотреть тело метода.
- Разные коды для «нет» и «чужое» — это оракул существования чужих записей. Только 404.
- Порядок удаления в `UserPurgeService` определяется FK-графом; менять его при добавлении новых таблиц. Тест на осиротевшие строки — единственная защита.
- Закрытие импорта ломает пользовательские скрипты. Предупредить владельца до деплоя.
