# 09 — Сквозная приёмка релиза 0.4

**Type:** task
**Status:** open
**Blocked by:** 04 — Администрирование; 08 — Мастер первого входа; 10 — Фронтенд ввода инвайт-кода; 11 — Фронтенд выпуска инвайт-кодов; 12 — Аккаунт obuhov; 13 — Закрытие доступа к admin

**What to build:** Единственный тикет, который имеет право объявить релиз готовым. Проверяет два полных пути на реально задеплоенной системе, а не по исходникам и не по зелёным тестам.

> Путь «демо» снят вместе с отменой тикета 06: анонимного входа в системе нет, демо-стенд закрыт инвайт-кодами. Проверка заполненности всех экранов переезжает в приёмку релиза 0.6 вместе с демо-профилями.

## Два пути

**Путь A — новый пользователь:**
`obuhov` выпускает инвайт-код через `/admin/invites` → приватное окно → `/register` по коду → мастер: Проект → Цель → Норма → «Сегодня» с непустым остатком нормы → создать одно Дело и записать время → остаток пересчитался.

**Путь B — изоляция и администрирование:**
под пользователем A попытаться открыть сущности B по прямым id → 404 → под `obuhov` открыть «Пользователи»: список, блокировка, сброс пароля → заблокированный не входит → удалить тестового пользователя → его данные исчезли, данные соседа целы → обычный пользователь не видит пункт «Пользователи» в DOM и получает 403 на админских маршрутах → seed-аккаунт `admin` заблокирован (тикет 13) и не пускает по старым учётным данным.

## Pitfalls

- Зелёные тесты и успешная сборка не являются приёмкой. Владелец принимает по браузеру.
- Проверять регистрацию **только** в приватном окне: обычное окно подставит сохранённый токен и покажет чужую сессию.
- Не открывать стенд приглашённым раньше, чем закрыт тикет изоляции и определена лицензия.
