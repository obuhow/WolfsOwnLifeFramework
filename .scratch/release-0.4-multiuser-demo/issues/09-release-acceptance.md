# 09 — Сквозная приёмка релиза 0.4

**Type:** task
**Status:** open
**Blocked by:** 04 — Администрирование; 06 — Demo Sandbox; 08 — Мастер первого входа

**What to build:** Единственный тикет, который имеет право объявить релиз готовым. Проверяет три полных пути на реально задеплоенной системе, а не по исходникам и не по зелёным тестам.

## Три пути

**Путь A — новый пользователь:**
admin выпускает инвайт-код → приватное окно → `/register` по коду → мастер: Проект → Цель → Норма → «Сегодня» с непустым остатком нормы → создать одно Дело и записать время → остаток пересчитался.

**Путь B — демо:**
приватное окно → `/login` → «Попробовать демо» → внутри системы за один клик → плашка демо-режима с обратным отсчётом → пройти по **каждому** пункту меню 0.3 и подтвердить, что ни один экран не пуст → изменить и удалить что-нибудь → второе демо в другом окне не видит правок первого.

**Путь C — изоляция и администрирование:**
под пользователем A попытаться открыть сущности B по прямым id → 404 → под ADMIN открыть «Пользователи»: список, блокировка, сброс пароля → заблокированный не входит → удалить тестового пользователя → его данные исчезли, данные соседа целы → обычный пользователь не видит пункт «Пользователи» в DOM и получает 403 на админских маршрутах.

## Pitfalls

- Зелёные тесты и успешная сборка не являются приёмкой. Владелец принимает по браузеру.
- Демо проверять **только** в приватном окне: обычное окно подставит сохранённый токен и покажет чужую сессию.
- Не включать GC до подтверждённого удаления на реальной БД.
- Не открывать демо публично раньше, чем закрыт тикет изоляции и определена лицензия.
