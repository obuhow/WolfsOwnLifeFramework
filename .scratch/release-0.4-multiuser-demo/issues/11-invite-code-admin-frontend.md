# 11 — Фронтенд: выпуск пригласительных кодов (только админ)

**Type:** task
**Status:** resolved
**Blocked by:** 04 — Администрирование: пользователи и инвайт-коды (бэкенд готов); 12 — Аккаунт администратора obuhov

**What to build:** Экран `/admin/invites`, которого сейчас нет. Бэкенд (`AdminController`: `GET/POST /api/v1/admin/invite-codes`, `POST /api/v1/admin/invite-codes/{id}/revoke`) полностью реализован, но выпустить код можно только curl'ом от лица администратора. Опция должна быть видна и доступна исключительно пользователю с `role === 'ADMIN'`.

## Scope

- Новый компонент `web/src/components/AdminInvitesView.vue`: реестр выпущенных кодов (код, кто выпустил, использовано/лимит, срок действия, отозван ли, примечание, дата создания) + форма выпуска нового кода (лимит использований, необязательный срок действия, примечание) + действие «Отозвать» на активных кодах через `ConfirmInline` (без модальных окон, без красных заливок — контракт 0.3).
- Маршрут `/admin/invites` в `main.js`, `meta: { requiresAuth: true }`.
- Пункт «Пользователи»/«Инвайт-коды» в Настройках (`SettingsView.vue`), видимый **только** при `role === 'ADMIN'` — роль читается из `GET /api/v1/auth/me` (расширенного полем `role`, см. тикет 04). У обычного пользователя пункт должен отсутствовать в DOM, а не быть скрыт стилем.
- Роутер-гард или проверка на уровне компонента: прямой переход по URL `/admin/invites` без роли ADMIN редиректит на `/today` (сервер всё равно вернёт 403 на самих запросах — фронт не единственная защита).
- После выпуска кода — явный текстовый показ значения кода с возможностью скопировать (администратор передаёт код приглашённому вручную, почты нет).

## Checklist

- [ ] `AdminInvitesView.vue` создан, маршрут зарегистрирован
- [ ] Пункт меню виден только под ADMIN и отсутствует в DOM под обычным пользователем (не `display: none`)
- [ ] Выпуск, просмотр списка и отзыв кода работают через реальные API-вызовы
- [ ] Обычный пользователь получает 403 при прямом обращении к `/api/v1/admin/invite-codes` (уже гарантировано бэкендом — только подтвердить в браузере)
- [ ] Сборка, пересоздание `web`, сверка хэшей
- [ ] Браузерная проверка под `obuhov` (см. тикет 12): выпуск кода → скопировать → использовать на `/register` (тикет 10) — полный путь A из тикета 09 пройден вручную

## Pitfalls

- Не показывать пункт «Пользователи»/инвайты в разметке для не-админа даже в `v-if`, который просто скрывает — рендерить условно так, чтобы элемента не было в DOM (см. pitfall тикета 04).
- Поле `createdAt` у только что созданного кода в текущем ответе API приходит `null` (баг бэкенда, не блокирует эту задачу, но не полагаться на него для сортировки — сортировать по возврату списка `findAllByOrderByCreatedAtDesc`, а не по клиентской дате).
