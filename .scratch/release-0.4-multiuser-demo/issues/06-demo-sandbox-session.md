**What to build:** Публичный вход в демо. `POST /api/v1/demo/session` создаёт **нового временного пользователя** с полным набором фикстур и сроком жизни 24 часа и возвращает готовый JWT. Кнопка «Попробовать демо» на экране входа. Часовой GC удаляет истёкшие аккаунты со всеми данными.

Почему эфемерный клон, а не общий `demo@wolf.local`: общий аккаунт требует ночного отката (посетитель видит чужие правки до сброса) либо read-only (нельзя потрогать систему — а именно возможность потрогать и продаёт WOLF).

## Scope

**`POST /api/v1/demo/session`** (`permitAll`):

1. проверить лимиты (см. ниже)
2. создать `User(username='demo-'+random8, password=random, account_type=DEMO, role=USER, status=ACTIVE, expires_at=now+24h, onboarding_completed_at=now)`
3. `DemoFixtureGenerator.populate(user)`
4. вернуть `{ token, expiresAt, username }`

Пароль наружу не отдаётся — войти в демо-аккаунт можно только по выданному токену. `onboarding_completed_at` проставлен: демо-пользователь мастера первого входа не видит, у него уже всё заполнено.

**Лимиты (в `application.yml`, не в коде):**

- `wolf.demo.rate-per-ip-per-hour: 3` — превышение даёт 429 «Демо временно недоступно, попробуйте позже»
- `wolf.demo.max-live-accounts: 200` — превышение даёт 429 с тем же текстом
- `wolf.demo.ttl-hours: 24`
- `wolf.demo.gc.enabled: false` — **по умолчанию выключено**, включается вручную после первого успешного прогона `UserPurgeServiceIT` и `DemoGcIT` на реальной БД

**GC:** `@Scheduled` раз в час удаляет `account_type=DEMO AND expires_at < now()` через `UserPurgeService` из тикета 03. Логирует число удалённых.

**Исключения демо:** `AgentJob` не обрабатывает `account_type=DEMO` (сделано в 03); админский список скрывает демо по умолчанию (сделано в 04).

**Фронтенд:** на `/login` под формой — текстовое действие «Попробовать демо» по контракту 0.3 (подчёркивание, без залитой кнопки). Клик → запрос → запись токена → переход на `/today`. Ошибка 429 показывается текстом сервера. Если токен протух и вернулся 401 — предложить «Открыть новое демо», а не бросать на пустой логин.

**Плашка демо-режима:** тонкая полоса в шапке `Демо-режим · данные удалятся через N ч` + текстовая ссылка «Получить доступ» (на `/register`). Нейтральные чернила и правило, без оранжевого/красного, без иконки предупреждения — тихий контракт распространяется и сюда.

## Pitfalls

- `permitAll`-эндпоинт, который создаёт пользователей и пишет в БД — вектор заполнения диска. Без лимитов не выкатывать.
- Генерация фикстур внутри HTTP-запроса может занять секунды. Если ответ дольше ~3 с — вынести в асинхронную подготовку пула прогретых демо-аккаунтов, но **не** усложнять заранее: сначала измерить.
- GC удаляет данные необратимо и по расписанию. Флаг по умолчанию `false` — не «на всякий случай», а обязательное условие.
- Не отдавать пароль демо-пользователя в ответе: он превращает эфемерный аккаунт в общий.
