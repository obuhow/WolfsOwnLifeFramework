# 10 — Фронтенд: ввод пригласительного кода (экран регистрации)

**Type:** task
**Status:** resolved
**Blocked by:** 02 — Регистрация по инвайт-коду (бэкенд готов)

**What to build:** Экран `/register`, которого сейчас физически нет в SPA. Бэкенд (`POST /api/v1/auth/register`, `InviteController`) полностью реализован и покрыт тестами, но пригласительный код негде ввести — на `/login` нет ни поля, ни ссылки. Путь A из тикета 09 (сквозная приёмка) не может быть пройден в браузере, пока этого экрана нет.

## Scope

- Новый компонент `web/src/components/RegisterView.vue`: три поля — код, `username`, пароль — и кнопка отправки.
- Маршрут `/register` в `web/src/main.js` с `meta: { public: true }`, по образцу `/login`.
- `POST` на `${apiBase()}/auth/register` с телом `{ code, username, password }`. При успехе — `localStorage.setItem('wolf_token', ...)` и редирект на `/onboarding` (или `/today`, если 08 недоступен на момент проверки — см. поведение тикета 02).
- Ошибка показывается текстом сервера (`data.message`), а не общим «Что-то пошло не так» — как уже сделано в `LoginView.vue`.
- Взаимная навигация: на `/login` — текстовая ссылка «У меня есть код» → `/register`; на `/register` — обратная ссылка на `/login`.
- Визуально — контракт 0.3: поле с нижним правилом, текстовое действие с подчёркиванием, без залитых кнопок (см. существующий `LoginView.vue` как образец вёрстки).

## Checklist

- [ ] `RegisterView.vue` создан, маршрут зарегистрирован
- [ ] Успешная регистрация по валидному коду доходит до `/onboarding`/`/today` без повторного логина
- [ ] Ошибки сервера (истёкший/отозванный/исчерпанный код, занятое имя, короткий пароль) показываются текстом ответа API
- [ ] Ссылки «У меня есть код» (login → register) и обратная (register → login) работают
- [ ] Сборка, пересоздание `web`, сверка отданных хэшей с `web/dist/assets`
- [ ] Браузерная проверка: `TC-0.4-02-01`, `TC-0.4-02-02..06`, `TC-0.4-02-09` из `testing/release-0.4/02-invite-registration.md` пройдены вручную, не только curl'ом

## Pitfalls

- Не путать с онбордингом (тикет 08) — это отдельный экран, регистрация должна работать даже если `/onboarding` ещё не задеплоен (тогда редирект идёт на `/today`).
- Не раскрывать в UI, какое из условий кода нарушено (истёк/отозван/исчерпан) — единое нейтральное сообщение уже приходит с бэкенда, фронт не должен его переформулировать.
