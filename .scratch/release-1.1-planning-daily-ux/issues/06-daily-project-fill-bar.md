# Тикет 06 — Полоса заполнения проекта в бэклоге Ежедневника

Status: ready-for-agent
Blocked by:
Type: task

> ⚠️ Требует принятия ADR `docs/adr/0006-daily-project-fill-bar-quiet-register-exception.md`
> (исключение из визуального контракта 0.3). ADR — черновик, ожидает финальной приёмки
> владельца. Реализация цветной полосы без принятого ADR противоречит релизу 0.3.

## Вопрос

Заявка (Ежедневник п.2): справа в бэклоге Ежедневника под каждым Проектом — **полоса
заполнения** недельной загрузки Проекта. Пример: «Курс английского до B2», всего 60 ч,
на этой неделе 8 ч в плане. Пользователь поставил 2 Дела «Урок английского» по 1 ч
(пн и ср); 1 ч в пн уже отзанимался, 1 ч в ср — только планирует. Полоса под Проектом:
**1/8 тёмным акцентом (зелёный) — факт**, **2/8 светло-зелёным — план** (факт+план),
относительно недельного плана (8 ч).

## Доказательство контекста и конфликта

- Данные для полосы уже есть: Бэклог недели группирует по Проектам с `x / y ч`, где
  `x` — факт ISO-недели, `y` — план недели, оба из `GET /api/v1/gantt?from=<monday>&weeks=1`
  (`cells[].factHours/planHours`) — см. `.scratch/release-0.3-ui-design/issues/03`.
- **Конфликт с контрактом 0.3** (двойной):
  - `issues/09` п.1: прогресс-бар с процентами был **удалён** как нарушение запрета;
  - `issues/01`/`05`: зелёный (`--wolf-done-surface`) — **только за выполненным фактом**,
    план должен быть нейтральным.
  Заявка требует и шкалу-полосу, и зелёный для плана → разрешено **только** ADR-0006
  (реш. A владельца): точечное исключение для этого элемента этого экрана.

## Что сделать

Фронт (данные уже приходят — бэкенд не трогаем):

1. Под каждым Проектом в бэклоге Ежедневника (компонент бэклога недельного вида — найти:
   `WeekView.vue`/выделенный aside-бэклог) добавить **полосу заполнения**:
   - ширина полосы = недельный план Проекта (`planHours`, `y`);
   - сегмент **факт** (`factHours`, `x`) — тёмный зелёный акцент;
   - сегмент **план** (запланированные, ещё не выполненные = `planHours − factHours`,
     но не меньше поставленных дел) — светло-зелёный;
   - остаток до полного плана — нейтральный (пустой).
2. **Проценты как текст не показывать** — доля выражается длиной сегментов; текст `x / y ч`
   рядом сохраняется (как сейчас).
3. **Перегруз** (факт+план > недельного плана) — нейтрально (штриховка/подпись), без красного.
4. Данные брать из того же агрегата Гантта, что и текущий `x / y ч` (не считать из
   видимой страницы — правило `issues/03`).
5. Цветовые токены завести/переиспользовать под ADR-0006 (тёмно-зелёный факт,
   светло-зелёный план); ограничить применение этим экраном.

## Testing Decisions

- Пример из заявки: Проект с планом 8 ч, факт 1 ч, план ещё 1 ч → полоса: 1/8 тёмно-зелёным,
  1/8 (до 2/8) светло-зелёным, остальное пусто; подпись `1 / 8 ч`.
- Перегруз: план недели 8 ч, наставлено 10 ч → нейтральный индикатор превышения без красного.
- Grep: нет `%`-текста в полосе; зелёный-план присутствует только на этом экране.
- Браузерная приёмка владельцем (ADR-исключение принимает владелец).
- `npm run build` зелёный.

## Out of Scope

- Распространение цветной полосы на Утренний обход/Гантт/др. реестры — запрет 0.3 там
  остаётся (ADR-0006 ограничен бэклогом Ежедневника).
- Изменение агрегата Гантта/бэкенда.

## Закрывает

Доработка «Ежедневник п.2» (реш. A). Зависит от принятия ADR-0006.
