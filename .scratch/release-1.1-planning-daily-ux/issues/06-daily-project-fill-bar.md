# Тикет 06 — Полоса заполнения проекта в бэклоге Ежедневника

Status: resolved
Blocked by:
Type: task

## Вопрос

Заявка (Ежедневник п.2): справа в бэклоге Ежедневника под каждым Проектом — **полоса
заполнения** недельной загрузки Проекта. Пример: «Курс английского до B2», всего 60 ч,
на этой неделе 8 ч в плане. Пользователь поставил 2 Дела «Урок английского» по 1 ч
(пн и ср); 1 ч в пн уже отзанимался, 1 ч в ср — только планирует. Полоса под Проектом:
**1/8 тёмным акцентом (зелёный) — факт**, **2/8 светло-зелёным — план** (факт+план),
относительно недельного плана (8 ч).

## Доказательство контекста и конфликта

- Данные для полосы уже есть: Бэклог недели группирует по Проектам с `x / y ч`, где
  `x` — факт ISO-недели, `y` — план недели, оба из `GET /api/v1/gantt?from=<monday>&weeks=1`
  (`cells[].factHours/planHours`) — см. `.scratch/release-0.3-ui-design/issues/03`.
- **Конфликт с контрактом 0.3** (двойной):
  - `issues/09` п.1: прогресс-бар с процентами был **удалён** как нарушение запрета;
  - `issues/01`/`05`: зелёный (`--wolf-done-surface`) — **только за выполненным фактом**,
    план должен быть нейтральным.
  Заявка требует и шкалу-полосу, и зелёный для плана → разрешено **только** ADR-0006
  (реш. A владельца): точечное исключение для этого элемента этого экрана.

## Что сделать

Фронт (данные уже приходят — бэкенд не трогаем):

1. Под каждым Проектом в бэклоге Ежедневника (компонент бэклога недельного вида — найти:
   `WeekView.vue`/выделенный aside-бэклог) добавить **полосу заполнения**:
   - ширина полосы = недельный план Проекта (`planHours`, `y`);
   - сегмент **факт** (`factHours`, `x`) — тёмный зелёный акцент;
   - сегмент **план** (запланированные, ещё не выполненные = `planHours − factHours`,
     но не меньше поставленных дел) — светло-зелёный;
   - остаток до полного плана — нейтральный (пустой).
2. **Проценты как текст не показывать** — доля выражается длиной сегментов; текст `x / y ч`
   рядом сохраняется (как сейчас).
3. **Перегруз** (факт+план > недельного плана) — нейтрально (штриховка/подпись), без красного.
4. Данные брать из того же агрегата Гантта, что и текущий `x / y ч` (не считать из
   видимой страницы — правило `issues/03`).
5. Цветовые токены завести/переиспользовать под ADR-0006 (тёмно-зелёный факт,
   светло-зелёный план); ограничить применение этим экраном.

- Grep: нет `%`-текста в полосе; зелёный-план присутствует только на этом экране.

- `npm run build` зелёный.

## Answer

ADR-0006 принят владельцем (2026-08-31) — точечное исключение из визуального контракта
0.3 для полосы заполнения проекта в Ежедневнике.

**Расхождение с формулой п.1, обнаруженное при реализации.** Буквальная формула
светлого сегмента `planHours − factHours` противоречила собственному примеру тикета:
план 8ч, факт 1ч, ещё запланирован 1ч → по формуле светлый = 8−1=7ч (почти вся полоса),
а по примеру ожидалась полоса 1/8 тёмным + 1/8 (до 2/8) светлым. По решению владельца
(batched-clarify в сессии) светлый сегмент считается по сумме часов **запланированных**
(status=PLANNED, не DONE) Записей времени проекта за неделю — не как остаток бюджета.

**Реализация:**
- Backend: `GET /api/v1/gantt` → `CellHours.pendingHours` — новый агрегат, тот же
  primary/ALL_PROJECTS учёт, что и `factHours` (`GanttService.computeHours`, объединяет
  бывший `computeFacts` в один проход по DONE+PLANNED). Юнит-контракт покрыт двумя новыми
  IT-тестами (`planned_entries_not_counted_as_fact_but_counted_as_pending`,
  `pending_primary_only_counts_primary_project`) — `GanttApiIT`: 13/13 зелёных
  (`./gradlew test --tests 'ru.wolf.api.gantt.GanttApiIT'` в докеризованном Gradle,
  `--network host` для Testcontainers на этом хосте).
- Frontend: `backlogGroups.js` → `fillBarSegments(group)` — чистая функция (доли
  факт/план относительно `plan`, клампится до 100%, `overLimit` при факт+план > план);
  покрыта `backlogGroups.test.mjs` (14 ассертов, включая точный пример тикета),
  подключена в `npm test`. Полоса отрисована только в бэклоге недели `WeekView.vue`
  (Ежедневник → Неделя) — НЕ в общем `BacklogGroups.vue` (используется также на
  `/backlog` и в месячном виде Календаря, где ADR-исключение не действует).
- Цветовые токены `--wolf-fill-fact` / `--wolf-fill-plan` / `--wolf-fill-neutral`
  заведены в `style.css`, ограничены классами `.fill-bar*` в `WeekView.vue`.
- Перегруз — нейтральная полупрозрачная штриховка (`.fill-bar-over`), без `role="alert"`
  и без красного/`--wolf-danger`; проценты как текст не выводятся — доля только длиной
  сегментов.
- `npm run build` зелёный (122 модуля, без ошибок); `npm test` зелёный (все существующие
  сьюты + новый).

**Проверка на живом стенде (API, реальные данные, пример тикета буквально).** Стенд
пересобран из этой ветки (worktree `origin/develop` + тикет 06; тот же compose-проект
`wolfsownlifeframework`, БД не тронута — 6 пользователей до/после). Через реальные API
(login → life-areas → projects → delos → grid-click, тот же путь, что фронт) воссоздан
пример из тикета: план недели 8ч, «Урок английского» пн 14:00–15:00 (DONE, факт 1ч),
ср 14:00–15:00 (PLANNED, план ещё 1ч). `GET /api/v1/gantt?from=2026-08-31&weeks=1` для
этого проекта вернул `{"planHours":8.0,"factHours":1.0,"pendingHours":1.0}` — ровно то,
что нужно `fillBarSegments`: factPct=12.5% (1/8), pendingPct=12.5% (до 2/8), overLimit=false —
совпадает с примером тикета «1/8 тёмным, 2/8 светлым». Тестовые записи/дело/проект/область
удалены после проверки. **Не проверено** — рендер DOM в реальном браузере (headless-среда
этой сессии без GUI/Chrome); логика полосы проверена от API-ответа до пиксельных долей
через ту же чистую функцию, что использует компонент.
