# Тикет 04 — Кнопка «Распределить время»: окно с редактируемой кривой загрузки

Status: resolved
Blocked by: 02
Type: task

## Вопрос

Заявка (Дорожная карта п.1): у каждого проекта рядом с плановым числом часов — кнопка
**«Распределить время»**. По клику — окно с кривой загрузки и формой: **дата начала** и
**дата завершения** проекта. После заполнения дат на кривой отображается **прямая** по
числу часов. Пользователь может **разбить кривую на 2 части**, поставив точку на одной из
недель, и двигать отдельные сегменты вверх (↑ плановые часы) / вниз (↓), при этом остальные
сегменты пересчитываются так, что **суммарное число часов на проект остаётся прежним**.

Решение владельца (grill-with-docs реш. D): редактор **ДОПОЛНЯЕТ** существующие стратегии
(Бюджет/Лестница/Очередь), не заменяет их. Инвариант перетаскивания — суммарные плановые
часы проекта неизменны.

## Доказательство контекста

- Существующие стратегии распределения План-на-неделю: `LoadCharts` +
  `BudgetTab.vue`/`LadderTab.vue`/`QueueTab.vue`, расчёты — `loadChartsForecast.js`
  (ровная ставка / лестница / всё-в-один). Новый редактор — четвёртый, **ручной** способ.
- Модель «План на неделю» (`CONTEXT.md`): плановое число часов на Проект в конкретной
  ISO-неделе; задаётся на Гантте. Кривая редактирует именно эти недельные значения.
- Термин закреплён: `CONTEXT.md` → «Распределение времени проекта».

## Что сделать

1. **Форма/окно (фронт).** Кнопка «Распределить время» рядом с плановыми часами проекта
   (на `/load-plan` и/или в строке проекта Гантта — согласовать точку размещения при
   реализации). Модальное окно:
   - поля **дата начала** / **дата завершения** проекта (если у проекта уже есть сроки —
     предзаполнить; поле `endDate` появилось в релизе 1.0, тикет 02);
   - по диапазону недель строится **прямая**: суммарные плановые часы проекта равномерно
     раскладываются по ISO-неделям диапазона (стартовое состояние кривой);
   - **точка-разбивка**: клик на неделе делит кривую на 2 сегмента;
   - **перетаскивание сегмента** вверх/вниз меняет часы его недель; остальные сегменты
     авто-пересчитываются так, что Σ часов проекта = const (инвариант). Правило
     распределения дельты между прочими сегментами — зафиксировать в тикете (пропорционально
     их текущим часам, не уводя ни один сегмент ниже 0).
2. **Сохранение.** Итоговые недельные значения пишутся как «План на неделю» проекта
   (тот же эндпоинт/агрегат, что правит недельные планы на Гантте — найти при реализации;
   переиспользовать, не плодить новый способ хранения). Дебаунс + откат при ошибке PUT —
   как в шаблоне 0.8 (`inject` write-helper из `LoadCharts`, см. skill-заметку).
3. **Визуальный контракт.** Кривая — нейтральная (graphite), без red/`#a33`/`role="alert"`
   и без сигнальных цветов при превышении; перегруз — нейтрально (текст/штриховка).
   ADR-исключение 0006 касается ТОЛЬКО полосы Ежедневника (тикет 06), не этой кривой.

## Testing Decisions

- Юнит на инвариант: старт-прямая по Σ=N ч на K недель даёт N/K на неделю; после разбивки
  и подъёма одного сегмента на +Δ — сумма по всем неделям остаётся N (в пределах округления
  до 0.25 ч); ни одна неделя не уходит в минус.
- Браузер: кнопка «Распределить время» у проекта → окно; ввод дат → прямая; клик по неделе
  → 2 сегмента; тянем сегмент вверх → соседние опускаются, сумма сверху не меняется;
  сохранение отражается в недельных планах Гантта/Плана нагрузки.
- `npm run build` зелёный; при затрагивании бэкенда — соответствующий `*ApiIT`.

## Out of Scope

- Замена стратегий Бюджет/Лестница/Очередь (кривая их дополняет — реш. D).
- Изменение суммарных плановых часов проекта через это окно (только перераспределение).
- Разбивка более чем на 2 сегмента в этом тикете (заявка — «на 2 части»); N-сегментов —
  возможное развитие, не сейчас.

## Answer

Реализовано в ветке `release-1.1/feature/04-distribute-time-curve-editor` (коммит `537ecde`),
смёржено в `develop` (`33db00e`).

**Точка размещения (согласовано при реализации):** кнопка «Распределить время» — в строке
проекта на вкладке «Бюджет» Плана нагрузки (`/load-plan`), рядом с плановыми часами
(ползунком ставки). Детали проекта (`startDate`/`endDate`/`totalPlanHours`) подтягиваются
из `GET /projects/{id}` — в `load-charts` их нет; бэкенд не менялся.

Что сделано:

- `web/src/distributeTime.js` — чистая математика: `buildWeeks` (ISO-недели диапазона
  включительно), `straightLine` (суммарные плановые часы ровной прямой, шаг 0.25 ч,
  остаток первым неделям — Σ = N в пределах 0.25 ч), `splitAt` (разбивка на 2 сегмента
  с выпрямлением до средней высоты, Σ сохраняется; снятие разбивки — та же операция),
  `adjustSegment` (перетаскивание: дельта на остальные сегменты пропорционально их
  текущим суммарным часам, ни один сегмент не ниже 0, ход ограничивается клампом).
- `web/distributeTime.test.mjs` — юнит на инвариант (подключён в `npm test`).
- `web/src/components/DistributeTimeModal.vue` — окно: даты начала/завершения
  (предзаполнение из деталей проекта), прямая по неделям, клик по неделе — точка
  разбивки, перетаскивание сегмента, клавиатура (↑/↓ ±0.25 ч), мобильная текстовая
  форма; запись в **`PUT /gantt/week-plans`** (тот же эндпоинт, что правит недельные
  планы Гантта — новый способ хранения не плодился) через `inject('loadCharts').makeWriter`:
  по одному write-helper на неделю, дебаунс 400 мс, откат недели к серверному значению
  при ошибке PUT, строка ошибки под кривой. Сумма плановых часов проекта (totalPlanHours)
  окном не меняется — только перераспределение.
- `web/src/components/BudgetTab.vue` — кнопка «Распределить время» у плановых часов.

Проверка (все зелёные):

- `npm test`: 60+ ассертов — старт-прямая N/K, после подъёма сегмента на +Δ сумма по
  всем неделям остаётся N (с точностью до 1e-6), кламп при нехватке ёмкости (B не ниже 0),
  снятие разбивки, симметрия (подъём/опускание).
- `npm run build` зелёный (122 модуля).
- Браузерный гейт (CDP, headless Chromium, admin): кнопка у проекта → окно «Найти работу ·
  план 120 ч»; прямая 26 недель (120/26, Σ = 120 ч); клик по неделе → 2 сегмента
  (4.75 → 4.58 ч/нед); ↑↑ на сегменте A → 5.25 → 4.46, **сумма 120.0 == 120.0**;
  запись ушла в БД: 26 строк `week_plan` для проекта (Σ = 119.91 — в пределах округления
  0.25 ч от 120); Esc и «Готово» закрывают окно; проект без плановых часов показывает
  нейтральную подсказку (кривой нет); тихий контракт 0.3: 0 `role="alert"`, 0 сигнальных
  цветов.
