Status: resolved
Blocked by:
Type: task

## Вопрос

В «Утреннем обходе» (`/morning`) сейчас поведение инвертировано относительно заявки:
название проекта — ссылка, уводящая на `/projects/{id}`, а раскрытие/сворачивание — на
кнопке справа. Заявка (Утренний обход п.1): **клик по названию** проекта раскрывает его
подробную информацию на месте; **справа** вместо кнопки «Развернуть» — кнопка
«Редактировать проект».

## Доказательство текущего состояния

`web/src/components/MorningView.vue:88-91`:

```html
<router-link :to="`/projects/${project.id}`" class="morning-project-link">{{ project.title }}</router-link>
<button class="btn btn-ghost" :aria-expanded="expanded.has(project.id)" @click="toggle(project.id)">
  {{ expanded.has(project.id) ? 'Свернуть' : 'Развернуть' }}
</button>
```

Логика раскрытия (`expanded` Set + `toggle(projectId)`) уже есть (строки ~29-31, 89) и
работает — тикет её переиспользует, меняя лишь, что её дёргает.

## Что сделать

Только фронт, `MorningView.vue`:

1. Название проекта из `<router-link>` сделать **кликабельным заголовком раскрытия**:
   `<button>`/кликабельный `<h*>` с `@click="toggle(project.id)"`, `:aria-expanded`,
   `role`/клавиатурная доступность (Enter/Space раскрывают). Сохранить тихий контракт 0.3
   (без цветных маркеров, только правило/отступ; см. тикет 05 релиза 1.0 как образец).
2. Справа вместо кнопки «Развернуть/Свернуть» — кнопка **«Редактировать проект»**,
   ведущая на форму редактирования проекта. Целевой маршрут — тот же, что открывает
   `ProjectsView.vue` в режиме редактирования (`editingId`, см. `ProjectsView.vue:321`
   «Редактировать проект»); уточнить конкретный путь/квери при реализации
   (`/projects/{id}` в режиме edit либо `/projects?edit={id}` — выбрать существующий).
3. Индикатор раскрытия (шеврон/«· подробнее») повесить на заголовок, не на правую кнопку.
4. Учесть вложенность из релиза 1.0 (тикет 05): у узлов-родителей клик по названию
   раскрывает поддерево через существующий `visibleProjects`/`isVisible` — не сломать.
