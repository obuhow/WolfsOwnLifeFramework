## Вопрос

На странице Ежедневник (недельная сетка) добавить кнопку-тумблер **«Карандаш с плюсом»**
(как инструмент в фоторедакторе). При её активации включается режим быстрого добавления
времени: **+15 минут** к слоту и быстрого вычитания **−15 минут** из слота.

В активном режиме положение клика относительно существующей записи определяет край:

- клик **снизу** у записи → добавить (или отнять) 15 минут **снизу** (с конца, `endAt`);
- клик **сверху** у записи → добавить (или отнять) 15 минут **сверху** (с начала, `startAt`).

Отдельно — **исправить баг**: сейчас при клике снизу «отнять 15 минут» время вычитается
**не с конца, а с начала**. Перепроверить и починить в рамках этого тикета.

## Диагностика бага (root cause — фронт, не бэкенд)

Бэкенд `gridClick` укорачивает по краю **корректно** — `api/.../timeentry/TimeEntryService.java:333-345`:

```java
LocalDateTime lastSlot = e.getEndAt().minusMinutes(15);
LocalDateTime firstSlot = e.getStartAt();
if (slot.equals(lastSlot) || slot.equals(firstSlot)) {
    ...
    if (slot.equals(lastSlot)) { e.setEndAt(e.getEndAt().minusMinutes(15)); }   // с конца — верно
    else                       { e.setStartAt(e.getStartAt().plusMinutes(15)); } // с начала — верно
}
```

Баг во **фронте**: запись рендерится **одной кнопкой** на весь диапазон, и эта кнопка несёт
слот **верхней** строки блока. `web/src/components/WeekView.vue`:

```js
// :515-516 — slot блока = slotStart ВЕРХНЕЙ строки
slot: { startAt: slotStart, ... }
```
```html
<!-- :1048-1060 — одна кнопка на span строк; cont-строки своих кнопок не имеют (:1049) -->
<button v-if="blockAt(dayIdx, rowIdx) && blockAt(dayIdx, rowIdx).kind !== 'cont'"
        :style="{ gridRow: ... ' / span ' + blockAt(dayIdx, rowIdx).span }"
        @click="onCellClick(blockAt(dayIdx, rowIdx).slot, blockAt(dayIdx, rowIdx).span)">
```

→ Куда бы внутри записи ни пришёлся клик, на бэкенд уходит `firstSlot` (верх блока) →
всегда срабатывает ветка «с начала» (`:342`). Отсюда «вычитается не с конца».

## Что сделать

Фронт, `web/src/components/WeekView.vue` (бэкенд-контракт `grid-click` менять **не нужно** —
он уже различает верх/низ по переданному слоту; см. также `findByUserIdAndEndAt` /
`findByUserIdAndStartAt` для расширения от соседа, `:376-395`):

1. **Кнопка-тумблер «Карандаш+»** в тулбаре недельного вида (рядом с «Показать ночь» /
   «Подтвердить все», `:995-1013`): `aria-pressed`, включает/выключает `quickEditMode` (ref).
   Иконка — карандаш с плюсом; активное состояние визуально заметно (тихий контракт 0.3:
   без сигнальных цветов, только заметный active-стейт кнопки).

2. **Разрешить клик по любому под-слоту записи.** Сейчас `cont`-строки не кликабельны
   (`:1049`). Нужно, чтобы клик попадал в тот 15-мин слот, над которым он произошёл:
   - вариант A (минимальный): в активном режиме рендерить кликабельные оверлеи по каждой
     строке блока (по `row.index`), передавая в `onCellClick` слот **именно этой строки**,
     а не `blockStart`;
   - вариант B: определять под-слот по позиции курсора внутри спан-кнопки
     (`event.offsetY` / высота строки) и вычислять целевой `startAt` строки.
   Выбрать вариант при реализации; ключ — **на бэкенд должен уходить слот кликнутой строки**,
   тогда существующая логика краёв (`lastSlot`/`firstSlot`) отработает верно и баг уйдёт.

3. **Семантика ±15 в активном режиме:**
   - клик по **пустому** слоту прямо **под** записью (слот `== endAt`) → расширить снизу
     (уже есть: `findByUserIdAndEndAt` → `EXTEND`, `:376-384`);
   - клик по **пустому** слоту прямо **над** записью (слот `== startAt-15`) → расширить сверху
     (уже есть: `findByUserIdAndStartAt` для `slotEnd` → `EXTEND`, `:386-395`);
   - клик по **последнему занятому** слоту записи → отнять 15 мин **с конца** (`SHRINK`, endAt−15);
   - клик по **первому занятому** слоту записи → отнять 15 мин **с начала** (`SHRINK`, startAt+15);
   - направление (+ или −): согласовать при реализации — например, клик по пустому соседнему
     слоту = «+15», клик по крайнему занятому слоту записи = «−15» (естественно ложится на
     текущие ветки EXTEND/SHRINK бэкенда). Зафиксировать финальное правило в `## Answer`.

4. **Вне активного режима** поведение сетки не меняется (обычный клик/picker как сейчас).
   Режим — надстройка, а не замена.

## Testing Decisions

- **Регресс на баг (обязательно):** запись 09:00–10:00 (4 слота). В активном режиме клик по
  нижнему занятому слоту (09:45) «−15» → становится 09:00–**09:45** (укорочено **с конца**).
  Клик по верхнему занятому слоту (09:00) «−15» → становится **09:15**–10:00 (с начала).
  До фикса оба клика укорачивали с начала — тест должен это ловить.
- Расширение: клик по пустому слоту 10:00 (под записью) → 09:00–**10:15**; клик по пустому
  08:45 (над записью) → **08:45**–10:00.
- Тумблер: без активного режима старый клик работает как прежде; активный режим —
  ±15 по краям; `aria-pressed` отражает состояние; доступно с клавиатуры.
- Бэкенд-ветки уже покрыты `TimeEntryApiIT` (SHRINK/EXTEND/SPLIT, `:724-736`) — при
  необходимости добавить IT на «клик по нижнему слоту укорачивает endAt, а не startAt».
- `npm run build` в `web/` зелёный.
