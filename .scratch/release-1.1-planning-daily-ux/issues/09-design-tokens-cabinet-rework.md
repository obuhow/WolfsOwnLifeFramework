# Тикет 09 — Правки вёрстки: направление «Кабинет» (токены + 94 неописанных класса)

Status: resolved
Blocked by:
Type: task

> ⚠️ Требует принятия ADR `docs/adr/0007-cabinet-visual-direction-revision.md`
> (пересмотр визуального контракта 0.3 целиком, не точечное исключение). ADR — черновик,
> ожидает финальной приёмки владельца. Реализация патча без принятого ADR противоречит
> релизу 0.3 (заливка `.btn-primary`, радиус >2px, рамки у полей, danger-красный).

## Вопрос

Павел принёс готовый патч (`wolftokensstep1.patch`, приложен к тикету) на `web/src/style.css`
+ новый `web/src/tokens.css`. Патч решает две задачи одновременно:

1. Выносит токены дизайн-системы в отдельный файл `tokens.css` (единый источник истины
   вместо инлайн `:root` в `style.css`) и вводит направление **«Кабинет»**: заполненная
   `.btn-primary`, скруглённые контролы (`--wolf-radius`), рамки у полей вместо нижней
   линии, тёплый danger-акцент для опасных действий, чуть более крупная типографика и
   более широкая шкала отступов.
2. Добавляет CSS-правила для **94 классов, которые разметка 30 компонентов из 50
   использует, а `style.css` не описывал** (`projects-toolbar`, `form-row`, `sr-only`,
   `btn-sm`/`input-sm`, `aggregate-total`, `link-list`, `page-intro`, `confirm-inline`
   разделитель и др.) — эти классы были в шаблонах без единого правила, часть UI держалась
   на дефолтном браузерном рендере (кнопка вплотную к селекту, `sr-only`-подписи видны
   как обычный текст и т.д.).

Grill-with-docs (batched-clarify при заведении тикета) разобрал каждое расхождение с
контрактом 0.3 отдельно от «просто недостающих классов» — см. ниже.

## Доказательство конфликта с контрактом 0.3 и решения владельца

`.scratch/release-0.3-ui-design/spec.md` §«Design tokens» и §«Typography, rhythm, and
surfaces» фиксирует: текст-действия с подчёркиванием (не заливка), радиус ≤2px без pill,
поля с одной нижней линией, «no saturated or semantic red... not a red button» для
destructive-действий, шкала отступов `4,8,12,16,24,28,40px`, `13px / 1.45`.

Патч расходится с этим системно (не на одном экране, как ADR-0006 для полосы заполнения
проекта в Ежедневнике) — полный разбор и решения владельца в
**`docs/adr/0007-cabinet-visual-direction-revision.md`**:

- **Реш. 1 (владелец, batched-clarify):** заливка `.btn-primary`, радиус `4px`/`6px`,
  рамки у `.input`/`.filter-select`/`.weeks-select select`, danger-акцент
  `--wolf-danger-ink`/`--wolf-danger-surface` — принимаются **как есть**, системно, не
  точечным исключением. Контракт 0.3 в этих пунктах считается устаревшим (см. ADR §
  «Последствия»).
- **Реш. 2 (владелец, batched-clarify):** новые значения шкалы отступов
  (`--wolf-space-6` 28→32px, `--wolf-space-7` 40→48px) и типографики (13→13.5px,
  line-height 1.45→1.5) — принимаются **как есть**, под тем же ADR-0007.
- Остальное из контракта 0.3 (белая поверхность, без теней, без синего, зелёный только
  за фактом кроме ADR-0006, без прогресс-баров/процентов) патчем не затрагивается и
  остаётся в силе — ADR-0007 не отменяет их.

## Что сделать

Фронт (`web/src`), патч уже готов (файл `wolftokensstep1.patch` в приложении к тикету,
скопирован в `.scratch/release-1.1-planning-daily-ux/assets/wolftokensstep1.patch`):

1. Создать `web/src/tokens.css` содержимым из патча (копирайт-шапка WOLF/AGPL уже внутри).
2. Применить правки `web/src/style.css`: `@import './tokens.css';` первой строкой,
   удаление старого инлайн-`:root` токен-блока, обновление `.btn`/`.btn-primary`/
   `.btn-ghost`/`.icon-btn`/`.input`/`.filter-select`/`.weeks-select select` под новые
   токены (заливка, радиус, рамки — см. «Решение владельца» выше).
3. Добавить блок «СЛОЙ 2» из патча — правила для 94 недостающих классов
   (`.projects-toolbar`, `.projects-toolbar-actions`, `.project-form`/`.life-area-form`,
   `.form-row`, разделитель `.confirm-inline` перед destructive-действием, `.btn-sm`/
   `.input-sm`, `.btn-danger-text` hover/`.is-armed`, `.sr-only`, `.preserve-lines`,
   `.link-list`, `.aggregate-mode`/`.aggregate-total`/`.aggregate-total-value`, общий
   вертикальный ритм `*-page` классов, `.page-intro`, финальное правило
   `.projects-toolbar-actions .input/.filter-select` — селект в тулбаре не растягивается
   на всю строку).
4. Применить `git apply` патча дословно (он уже прошёл ручную вычитку); при конфликте с
   текущим `style.css` (мог измениться после тикетов 01–08) — перенести правки вручную,
   сохранив итоговый результат идентичным патчу по содержанию правил.
5. `--wolf-tap` поднимается до `44px` на `max-width: 768px` — зона клика на телефоне;
   `--wolf-text-h1` на мобильном — `24px` (было `28px` на десктопе). Патч уже содержит
   `@media (max-width: 768px)` блок — переносится как есть.
6. `@media (prefers-reduced-motion: reduce)` — `--wolf-transition: 0s` — переносится как
   есть.

## Testing Decisions

- `npm run build` — зелёный, без новых предупреждений о неизвестных CSS-переменных.
- Grep по бандлу: `--wolf-radius`, `--wolf-danger-ink`, `--wolf-tap` присутствуют.
- Визуальная приёмка владельцем (ADR-0007 принимает владелец) на нескольких экранах:
  Проекты (`.projects-toolbar`), Дела (форма `.form-row`), удаление Области жизни
  (`.confirm-inline` разделитель + danger-hover), Настройки (`.form-row`).
- Проверить, что зелёный `--wolf-done-surface`/полоса заполнения проекта (ADR-0006,
  тикет 06) не задета этим патчем — токен не переопределён.
- Мобильная проверка `--wolf-tap: 44px` на экране `<768px` (реальная зона клика кнопок).

## Out of Scope

- Полоса заполнения проекта (ADR-0006, тикет 06) — отдельный тикет, эта правка её не
  затрагивает.
- Любые изменения бэкенда — правка чисто CSS-слоя.
- Классы, встречающиеся только в одном компоненте (не входят в «СЛОЙ 2» из патча) —
  переезжают в scoped-стили своих компонентов отдельно, вне этого тикета.
