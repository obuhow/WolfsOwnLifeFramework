# Баг Б-1 — на странице Документация две шапки; у пункта «Документация» нет всплывающего подменю

Type: bug
Status: open
Найдено при: релиз 1.1 (живой сайт, `/docs` под залогиненным пользователем)
Регрессия в: `release-0.5-navigation-docs`, тикет 02 (раздел `/docs` + `DocsShell`), Status: resolved

## Доказательство расхождения

### Проблема 1 — две шапки

Глобальная навигационная оболочка рендерится для **любого** маршрута под токеном, кроме
онбординга. `web/src/App.vue`:

```js
// :37
const isOnboarding = computed(() => route.path.startsWith('/onboarding'))
```
```html
<!-- :275-276 -->
<div v-if="token && !isOnboarding" class="app-shell">
  <header class="app-header"> ... </header>
```

`/docs` в исключение НЕ входит (исключён только `/onboarding`). При этом сам раздел
документации рисует **свою** шапку — `web/src/components/docs/DocsShell.vue:40-51`:

```html
<header class="docs-topbar">
  <router-link to="/docs" class="docs-brand">WOLF</router-link>
  <nav class="docs-tabs" aria-label="Разделы документации"> ... </nav>
</header>
```

Итог: залогиненный пользователь на `/docs` (и `/docs/manifesto`, `/docs/scenarios`,
`/docs/self-hosting`) видит **две шапки** — глобальную `app-header` и `docs-topbar`.
`DocsShell` проектировался как автономная оболочка для **неаутентифицированного** гостя
(`main.js:120` «Документация — доступна без аутентификации»; `DocsShell.vue:24` «Available
to unauthenticated visitors»), но под токеном поверх неё встаёт ещё и глобальная шапка.
Вторая шапка (`docs-topbar`) — лишняя, когда уже есть глобальная.

### Проблема 2 — «Документация» без всплывающего подменю

Пункт меню «Документация» объявлен как простая ссылка, без flyout, в отличие от групп
(`Управление делами`, `Настройки`), у которых при наведении раскрываются дети.
`web/src/App.vue:84`:

```js
{ kind: 'link', label: 'Документация', to: '/docs', tour: 'docs' },
```

Подпункты раздела уже существуют (`DocsShell.vue:32-34`, `DocsIndexView.vue:26-28`):
**Манифест WOLF**, **Сценарии использования**, **Технические инструкции** — но из верхнего
меню при наведении они не всплывают (нужно зайти на `/docs` и искать вкладки).

## Почему это важно

- Две шапки — визуальный дефект и потеря вертикального пространства на всех 4 страницах
  `/docs`; сбивает навигацию (два «WOLF»-бренда, две строки ссылок).
- Отсутствие flyout у «Документация» делает подразделы недоступными в один наведённый
  жест, в отличие от остальных пунктов меню — несогласованность IA релиза 0.5.

## Что сделать

1. Убрать **вторую** шапку на `/docs`: под залогиненным пользователем не рисовать
   `DocsShell.docs-topbar` (оставить только глобальную `app-header`), либо на маршрутах
   `/docs*` скрывать глобальную и оставлять `docs-topbar`. Выбрать один источник шапки;
   для гостя (без токена) `docs-topbar` должна остаться (иначе гость теряет навигацию по
   разделу). Простейший критерий: `docs-topbar` рендерить только когда `!token`.
2. Сделать «Документация» в NAV **группой** (`kind: 'group'`) с всплывающими детьми
   **Манифест WOLF** (`/docs/manifesto`), **Сценарии использования** (`/docs/scenarios`),
   **Технические инструкции** (`/docs/self-hosting`) — по образцу групп `Управление делами`
   / `Настройки` (`App.vue:46-83`), сохранив `tour: 'docs'` и активное состояние.
3. Мобильный drawer и `data-tour-target` не сломать.
4. Решить, оставлять ли `resolved` у 0.5-02 — шапка/меню раздела доделываются здесь;
   статус исходного тикета меняет владелец.

## Testing Decisions

- Браузер (залогинен): на `/docs`, `/docs/manifesto`, `/docs/scenarios`, `/docs/self-hosting`
  ровно **одна** шапка.
- Браузер (гость, без токена): раздел `/docs` навигируется как прежде (шапка раздела на месте).
- Наведение на «Документация» в верхнем меню раскрывает 3 подпункта; клик по каждому ведёт
  на нужный маршрут; активное состояние подсвечивается.
- `npm run build` зелёный.
