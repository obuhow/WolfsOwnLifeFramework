## 2. Противоречия и решения владельца

### A. Полоса заполнения проекта в Ежедневнике vs визуальный контракт 0.3 🔴→ РЕШЕНО
Заявка (Ежедневник п.2): под проектом полоса; 1/8 тёмно-зелёным (факт), 2/8 светло-зелёным (план).
Доказательства запрета из `.scratch/release-0.3-ui-design/`:
- `issues/09-flow-management-screens.md` п.1: в Утреннем обходе **был прогресс-бар с процентами** —
  «*прямое нарушение запрета на прогресс-бары и проценты*», удалён, заменён на `x / y ч`.
- `issues/03-today-register-project-backlog.md`: Бэклог недели **«не показывает шкалу
  прогресса/оценку»**.
- `issues/01-global-design-system.md` + `issues/05-planning-gantt.md`: **бледно-зелёный
  зарезервирован ТОЛЬКО за выполненным фактом** (`--wolf-done-surface`, класс `has-fact`);
  план — нейтральный graphite.

**Решение владельца:** пересмотреть контракт 0.3 **для этого экрана** — зелёный факт +
светло-зелёный план допускаются. Оформить как **осознанное решение владельца → ADR**
(«исключение из quiet-register для полосы заполнения проекта в Ежедневнике»), НЕ молчаливо.
→ Новый термин «Полоса заполнения проекта» в глоссарии; ADR-набросок в тикете релиза.

### B. «План нагрузки на отдельной странице» vs глоссарий/релиз 0.8 🔴→ РЕШЕНО
Глоссарий «План нагрузки (секция)»: *«Не отдельный маршрут — якорь на той же странице»*,
`_Avoid_` отдельного маршрута. В 0.8 секция вынесена в `LoadCharts.vue` внутри `/roadmap`
(`PlanningView.vue:21`, `LoadCharts.vue:160` `id="load-plan"`).

**Решение владельца:** вынести в **отдельную страницу** (новый маршрут, напр. `/load-plan`).
→ Обновить глоссарий «План нагрузки»: секция → страница; старый якорь `/roadmap#load-plan`
даёт **302** на новый маршрут (как ранее `/gantt`,`/planning`→`/roadmap`).

### C. «Порядок вкладок: Бюджет, План нагрузки» → УТОЧНЕНО
Сейчас на `/roadmap`: Гантт + секция «План нагрузки» с внутренними вкладками
`Кривые / Бюджет / Лестница / Очередь` (`LoadCharts.vue:40-41`). «Бюджет» перегружен —
это ещё и недельный бюджет **Цели** (`GoalsView.vue`).

**Решение владельца:** на новой странице **План нагрузки** вкладки в порядке:
**Бюджет, Кривые, Лестница, Очередь**. («План нагрузки» — имя страницы, а не вкладки;
исходная формулировка «Бюджет, План нагрузки» имела в виду именно это.)

### D. Ручной редактор кривой («Распределить время») vs стратегии Бюджет/Лестница/Очередь → РЕШЕНО
`LoadCharts` уже содержит `BudgetTab`/`LadderTab`/`QueueTab` — альтернативные **стратегии**
распределения План-на-неделю (ровная ставка / лестница / всё в один; см.
`loadChartsForecast.js`).

**Решение владельца:** новый ручной редактор **ДОПОЛНЯЕТ** стратегии, не заменяет.
Инвариант при перетаскивании сегментов: **суммарные плановые часы проекта неизменны** —
подъём одного сегмента компенсируется опусканием прочих. Вызов — кнопка «Распределить
время» рядом с плановыми часами каждого проекта; всплывает окно с кривой загрузки и формой
(дата начала / дата завершения → прямая по часам; точка-разбивка → перетаскиваемые сегменты).
→ Новый термин «Распределение времени проекта» + кнопка «Распределить время».

### E. Запись «со скольки до скольки» (дефолт 15 мин) → ПЕРЕСМОТРЕНО 2026-08-31
Глоссарий «Запись времени» = один 15-мин слот; в ячейке не более одной Записи.

**Первоначальное решение владельца:** диапазон создаёт N последовательных 15-мин Записей
(кратно 15 мин), модель не меняется; авто-простановку по клику временно отключить.

**Изменено владельцем (2026-08-31):** вместо формы-диапазона — режим-тумблер **«Карандаш+»**
для быстрого добавления/вычитания **±15 мин** к слоту. В активном режиме положение клика
относительно записи задаёт край: клик снизу → правит `endAt`, клик сверху → правит `startAt`.
Модель по-прежнему **не меняется**. Дополнительно — **фикс бага**: сейчас вычитание снизу
идёт «с начала», т.к. на фронте запись рендерится одной кнопкой и слот всегда берётся с
верха блока (`WeekView.vue:515-516,1048-1060`); бэкенд краевую логику (`TimeEntryService.java:333-345`)
считает верно. Полная постановка и диагностика — в тикете
`issues/07-daily-quick-time-pencil-mode.md`.

### G. h1 «Календарь» → «Ежедневник» 🟡→ РЕШЕНО (тривиально)
`CalendarView.vue:143` = `<h1>Календарь</h1>`, а NAV уже «Ежедневник» (`App.vue:45`).
Правка h1 (+ подзаголовок). В глоссарии «Календарь (страница)» остаётся как **внутренняя
вкладка/сетка «Неделя»**, но как **видимый заголовок страницы** имя уходит в пользу
«Ежедневник» — уточняем `_Avoid_` в статье «Календарь».

## 3. Подтверждено кодом (обосновано, без противоречий)

### F. Утренний обход п.1 — инверсия клик/кнопка
Сейчас: название проекта = `router-link` на `/projects/{id}` (уводит со страницы), кнопка =
«Развернуть/Свернуть» (`MorningView.vue:88-91`). Заявка: клик по **названию** раскрывает
подробности на месте; справа вместо «Развернуть» — кнопка **«Редактировать проект»**.
Чисто фронт, модель не трогаем.

### H. Баг «2 шапки» на Документации + hover-подменю
Подтверждён: `DocsShell.vue:40` рисует собственную `docs-topbar` (бренд WOLF + вкладки)
**поверх** глобальной шапки `App.vue`. Плюс пункт «Документация» в NAV — `kind:'link'`
(`App.vue:84`) **без** flyout, в отличие от группы «Управление делами» (`kind:'group'`).
Починка: (1) убрать лишнюю (вторую) шапку на `/docs`; (2) сделать «Документация» группой
с всплывающими детьми **Манифест WOLF / Сценарии использования / Технические инструкции**
(ярлыки уже есть в `DocsShell.vue:32-34` и `DocsIndexView.vue:26-28`). Навигация, не домен.
