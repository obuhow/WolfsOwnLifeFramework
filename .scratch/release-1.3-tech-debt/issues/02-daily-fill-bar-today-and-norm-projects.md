# Тикет 02 — Полоса заполнения проекта на дневной странице Ежедневника + список от проектов с недельной нормой

Status: resolved
Blocked by:
Type: task

## Вопрос

Заявка владельца (Ежедневник): на странице Ежедневника видеть **список Проектов, у которых на этой неделе запланирована норма часов**, и под каждым — **полосу заполнения**, которую наполняют привязанные Дела: тёмно-зелёный = выполненные Дела (факт), светло-зелёный = запланированные. Закрывает баг `bugs/02-daily-project-fill-bar-not-on-today-and-no-norm-only-projects.md`.

## Контекст (данные уже есть, бэкенд не трогаем)

- Полоса закреплена ADR-0006 (тёмно-зелёный факт / светло-зелёный план / нейтральный остаток; проценты текстом не показываем; перегруз нейтрально, без красного).
- `GET /api/v1/gantt?from=<monday>&weeks=1` уже отдаёт по каждому проекту `cells[0].{planHours, factHours, pendingHours}` и возвращает **все** проекты пользователя (`GanttService:87`, `findByUserOrderByTitleAsc`) — проект с нормой без записей тоже присутствует.
- Готовые к переиспользованию: `backlogGroups.js` → `fillBarSegments()` (`:100`), `fetchProjectWeekHours()` (`:115`); рендер-образец полосы — `WeekView.vue:1192-1199`.

## Что сделать (фронт)

1. **Перенос полосы на `TodayView.vue`.** Добавить `pending` в группы бэклога (сейчас `TodayView.vue:314-321` строит группу без `pending`), импортировать `fillBarSegments`, отрисовать сегменты `.fill-bar` / `.fill-bar-fact` / `.fill-bar-pending` / `.fill-bar-over` — тем же контрактом, что `WeekView.vue`.
2. **Токены.** Перенести `--wolf-fill-fact` / `--wolf-fill-plan` / `--wolf-fill-neutral` из `<style>` `WeekView.vue` в место, доступное обеим страницам Ежедневника, сохранив ограничение классами `.fill-bar*` (не утекают в Утренний обход/Гантт/`/backlog`/месячный Календарь — граница ADR-0006).
3. **Источник списка — проекты с нормой.** Строить группы от `projectWeekHours` (все проекты с `plan > 0`), а не только от Дел бэклога. Дела наполняют полосу и раскрываются под своей группой; проект с нормой без Дел показывается с пустой полосой и подписью `0 / y ч`. Группа «Без проекта» — как сейчас (только при наличии несвязанных Дел). Применить то же и к `WeekView.vue`, чтобы обе страницы Ежедневника вели себя одинаково.
4. **Порядок.** Сортировка групп — по названию проекта (как сейчас), «Без проекта» в конце.

## Testing Decisions

- Пример владельца: проект «Курс английского», план недели 8 ч; пн 14:00–15:00 DONE (факт 1 ч), ср 14:00–15:00 PLANNED (план 1 ч) → полоса 1/8 тёмным + 1/8 (до 2/8) светлым, подпись `1 / 8 ч`. Тот же результат на **обеих** страницах Ежедневника.
- Новый кейс: проект с нормой 5 ч и **нулём** привязанных Дел → появляется в списке, полоса пустая, подпись `0 / 5 ч`. Покрыть в `backlogGroups.test.mjs` на уровне построения групп от `projectWeekHours`.
- Перегруз: план 8 ч, факт+план 10 ч → нейтральная штриховка `.fill-bar-over`, без красного/`role=alert`; процент текстом не выводится.
- Grep: нет `%`-текста в полосе; зелёный-план присутствует только в пределах Ежедневника (Today + Неделя), не в других реестрах.
- Браузерная приёмка владельцем DOM-рендера на дневной странице (ADR-исключение принимает владелец).
- `npm run build` и `npm test` зелёные.

## Out of Scope

- Изменение агрегата Гантта/бэкенда (`planHours`/`factHours`/`pendingHours` — как есть).
- Полоса вне Ежедневника (Утренний обход, Гантт, `/backlog`, месячный Календарь) — запрет 0.3 там сохраняется.
- Новая логика вычисления нормы: «норма недели» = существующий `planHours` из плана Гантта, не вводим новых источников.

## Answer

Реализовано на ветке `release/1.3-tech-debt-docs` (только фронт, бэкенд не тронут).

**Общая чистая функция.** `web/src/backlogGroups.js` → `groupBacklogWithNorm(projects, delos, hoursByProject)`: строит группы от проектов с недельной нормой (все `plan > 0` из Gantt-агрегата, даже без Дел → пустая полоса `0 / y ч`), Дела наполняют полосу и раскрываются под своей группой; проект без нормы, но с привязанным Делом, не теряется; «Без проекта» — только при наличии несвязанных Дел; `plan = 0`/NaN нормой не считаются. Числа берутся из агрегата, не из видимой страницы.

**Оба компонента переведены на неё:**
- `TodayView.vue` — добавлен импорт `groupBacklogWithNorm`/`fillBarSegments`, `backlogGroups` теперь зовёт общую функцию; добавлен `groupFillBar`; `loadProjectWeekHours` начал читать `pendingHours`; в шаблон добавлена разметка полосы (`.fill-bar` + `fact`/`pending`/`over`), в `<style scoped>` — те же правила `.fill-bar*`, что в `WeekView` (токены `--wolf-fill-*` уже глобальны в `tokens.css`; применение ограничено классами `.fill-bar*` в пределах Ежедневника — граница ADR-0006).
- `WeekView.vue` — `backlogGroups` переведён на ту же общую функцию (единое поведение обеих страниц Ежедневника); полоса и загрузка `pending` там уже были.

**Тесты.** `web/backlogGroups.test.mjs` дополнен 18 ассертами на `groupBacklogWithNorm` (пример владельца, проект-с-нормой-без-Дел `0 / y ч`, микс с сортировкой, linked-no-norm, «Без проекта», `plan=0` не норма). `npm test` — все сьюты зелёные; `npm run build` — 124 модуля без ошибок. Доп. проверка edge-кейсов (дедуп `projectIds [1,1]`, Дело в двух проектах) — ручным прогоном чистой функции.

**Независимое ревью** (свежий контекст, только диф) — passed, логических/секьюрити-замечаний нет.

**Не проверено:** DOM-рендер в реальном браузере (headless-среда без GUI) — остаётся на браузерную приёмку владельцем (ADR-исключение принимает владелец). Логика полосы проверена от агрегата до пиксельных долей через ту же чистую функцию, что использует компонент.
