# Б-2 — Полоса заполнения проекта: нет на дневной странице Ежедневника + проекты с недельной нормой без Дел не показываются

Type: bug
Status: open
Найдено при: release-1.3-tech-debt (сбор объёма, заявка владельца: «на Ежедневнике видеть список проектов с недельной нормой часов и полосу наполнения — зелёный факт, светло-зелёный план»)
Регрессия в: release-1.1-planning-daily-ux, тикет `issues/06-daily-project-fill-bar.md` (Status: **resolved**). Вертикальный срез поставлен наполовину: полоса реализована только в бэклоге вкладки «Неделя» (`WeekView.vue`), на дневной странице Ежедневника (`TodayView.vue`) её нет; и оба списка строятся от Дел, а не от проектов с нормой.

## Симптом

Заявка владельца (Ежедневник): видеть **список Проектов, у которых на этой неделе запланирована норма часов**, и под каждым — **полосу**, которую наполняют привязанные Дела: тёмно-зелёный сегмент = выполненные Дела (факт), светло-зелёный = запланированные.

Фактически:
1. На **дневной** странице Ежедневника (`TodayView.vue`) полосы **нет вообще** — только текст `x / y ч`.
2. Полоса есть **только** на вкладке «Неделя» (`WeekView.vue`).
3. На **обеих** вкладках список проектов строится перебором Дел недельного бэклога, поэтому **Проект с недельной нормой, но без привязанных Дел, в списке не появляется** — то есть «список проектов с нормой» неполный.

## Как устроено (контекст)

- Полоса заполнения проекта закреплена ADR-0006 (`docs/adr/0006-daily-project-fill-bar-quiet-register-exception.md`): тёмно-зелёный = факт (status=DONE), светло-зелёный = запланированное (status=PLANNED), относительно недельного плана Проекта; проценты как текст не показываем; перегруз — нейтрально, без красного.
- Данные для полосы приходят из реального агрегата Гантта, **бэкенд трогать не нужно**:
  `GET /api/v1/gantt?from=<monday>&weeks=1` → на каждый проект `cells[0].{planHours, factHours, pendingHours}`.
- Чистая функция полосы уже есть и покрыта тестами:
  `web/src/backlogGroups.js` → `fillBarSegments({fact, plan, pending})` (`:100`) и `fetchProjectWeekHours(...)` (`:115`).

## Доказательство расхождения (по коду)

### Дефект A — полосы нет на дневной странице Ежедневника (`TodayView.vue`)

`TodayView.vue` не импортирует и не вызывает `fillBarSegments`, в шаблоне нет разметки полосы, а группы бэклога не несут поля `pending` (в отличие от `WeekView`):

```
# grep -nE 'fill-bar|fillBarSegments|groupFillBar|fill-fact|fill-plan' web/src/components/TodayView.vue
(нет ни одного совпадения по разметке/логике полосы)

# backlogGroups в TodayView.vue строит группу без pending:
314:  groups.set(key, {
315:    key,
316:    projectId: pid,
317:    label: pid == null ? 'Без проекта' : projectTitle(pid),
318:    fact: pid == null ? null : (hours ? hours.fact : 0),
319:    plan: pid == null ? null : (hours ? hours.plan : null),
320:    items: []
321:  })   // ← нет `pending`, полосу строить нечем
```

Для сравнения — в `WeekView.vue` полоса реально в DOM:

```

```

Таким образом тикет 06 закрыл только половину вертикального среза: логика (`backlogGroups.js`) и рендер на «Неделе» — есть, дневная страница — нет.

### Дефект B — проекты с недельной нормой без Дел не попадают в список

И в `TodayView.vue`, и в `WeekView.vue` группы проектов формируются перебором **Дел** недельного бэклога (`filteredWeekBacklog`), а не перебором проектов с нормой:

```
# TodayView.vue:308  for (const delo of filteredWeekBacklog.value) { ... groups.set(key, ...) }
# WeekView.vue:363   for (const delo of filteredWeekBacklog.value) { ... groups.set(key, ...) }
```

Проект без единого Дела в бэклоге не создаёт группу → не отрисовывается. При этом данные о его норме уже есть: `GET /api/v1/gantt` возвращает **все** проекты пользователя с недельным `planHours` (не только те, где есть записи) —

```
# api/src/main/java/ru/wolf/api/gantt/GanttService.java
87:  List<Project> allProjects = projectRepository.findByUserOrderByTitleAsc(user);
88:  List<Project> filtered = allProjects.stream()
89:      .filter(p -> areaFilter.isEmpty() || areaFilter.contains(p.getLifeArea().getId()))
90:      .filter(p -> !onlyWithDates || p.getStartDate() != null || p.getEndDate() != null)
91:      .toList();
```

Без фильтров area/dates (случай Ежедневника) вернутся все проекты; `planHours` берётся из плана недели независимо от наличия записей. Значит требование «показать все проекты с `planHours>0`» **выполнимо целиком на фронте**, без изменения бэкенда — нужно строить список от `projectWeekHours` (проекты с `plan>0`), а Дела лишь наполняют полосу и раскрываются под группой.

### Что работает (не трогаем)

- Агрегат `pendingHours` в `GET /api/v1/gantt` и его атрибуция (тикет 06) — корректны, покрыты `GanttApiIT`.
- Чистая функция `fillBarSegments` и её тесты (`backlogGroups.test.mjs`) — корректны; переиспользуются как есть.
- Полоса на вкладке «Неделя» — остаётся, меняется только источник списка (см. Дефект B).

## Почему это важно

- Владелец явно просит видеть загрузку недели по Проектам **на Ежедневнике** — главном ежедневном экране; сейчас там этого сигнала нет вообще.
- «Список проектов с нормой» неполный: проект, на который поставлена недельная норма, но ещё не разложены Дела, невидим — а это ровно тот случай, ради которого нужен визуальный сигнал «надо наполнить».
- Полу-выполненный resolved-тикет 06 вводит следующего агента в заблуждение: по Answer «полоса сделана», по факту — только на одной из двух поверхностей Ежедневника.

## Границы / ADR

- ADR-0006 разрешает полосу как **точечное исключение** «на этом экране (бэклог Ежедневника)». Дневная страница Ежедневника — та же поверхность семейства Ежедневника, что и вкладка «Неделя», где полоса уже принята → перенос в пределах Ежедневника исключение **не расширяет**. Распространение на Утренний обход / Гантт / общий `/backlog` / месячный Календарь остаётся **запрещённым** (Out of Scope).
- Уточнить у владельца при триаже: строку списка для проекта **с нормой, но без Дел** показывать (пустая полоса + `0 / y ч`, раскрывать нечего) — да/нет. Заявка владельца (batched-clarify): **показывать все проекты с `planHours>0`, даже без привязанных Дел**.
