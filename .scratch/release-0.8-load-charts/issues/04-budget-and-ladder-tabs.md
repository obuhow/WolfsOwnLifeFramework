# Вкладки «Бюджет» и «Лестница»: ставка часов и цена решения в датах (варианты 2a + 2b)

Status: ready-for-agent
Blocked by: 01, 02

## Question

Реализовать две вкладки, работающие с одной величиной — ставкой «часов в неделю» на проект и недельной нормой пользователя. «Бюджет» даёт эту ставку менять и показывает прогноз финиша; «Лестница» показывает, какой финиш дали бы четыре соседние ставки. Объединены в один тикет: общая модель, общий обработчик записи, расхождение между вкладками недопустимо.

Референс: `ref/WOLF - планирование (варианты).dc.html`, варианты `2a` и `2b`. Переносить логику и геометрию, не цвета.

## Что сделать — вкладка «Бюджет» (2a)

1. **Строка на проект:** название и подпись «Область · N Дел»; ползунок «часов в неделю»; объём работ; полоса окна работ; дата финиша. Колонки — одна CSS Grid система для заголовка и всех строк.
2. **Ползунок** — нативный `<input type="range">`, `min=0`, `max=20`, `step=1`, `aria-label` вида «Часов в неделю: Разработка WOLF». Подпись под ним: «8 ч» либо «заморожен» при нуле.
3. **Объём работ** — `effortHours`; при `effortSource: ESTIMATED` — тонкая пометка «оценка», чтобы вычисленное не выдавалось за заданное.
4. **Полоса окна работ** — от старта до прогнозного финиша, ширина пропорциональна максимальному прогнозу среди проектов. Заливка `--wolf-subrule`, левая граница 2px `--wolf-ink`; при нулевой ставке границы нет.
5. **Финиш** — `forecastByRate`; при ставке 0 — «—» цветом `--wolf-faint`. Под плановым прогнозом — **тонкая подпись с фактическим прогнозом** из существующего `GET /api/v1/gantt/forecast` («по факту: 14 мар 27»), чтобы расхождение плана и реальности было видно, а не спрятано. Оба прогноза сосуществуют, плановый фактический не заменяет.
6. **Строка бюджета в шапке вкладки:** «распределено 27 ч · свободно 3 ч» либо «распределено 34 ч — перебор на 4 ч». Перебор — **текстом, без сигнального цвета и без блокировки**; ползунки продолжают работать.
7. **Запись:** отпускание ползунка → `PUT /api/v1/gantt/week-plans` с `{ projectId, isoYear, isoWeek, planHours }` на **текущую ISO-неделю**, через общий хелпер тикета 02 (дебаунс 400 мс, откат при ошибке). Исторические недели не переписываются.

## Что сделать — вкладка «Лестница» (2b)

8. **Стопка распределения** сверху: горизонтальная полоса, сегмент на проект шириной от его доли недельной нормы, подпись с часами внутри сегмента; свободный остаток — заштрихованная зона (`repeating-linear-gradient` на нейтральных токенах). Рамка 1px `--wolf-ink`.
9. **Подзаголовок:** «Свободный резерв недели: 3 ч» либо «Сумма превышает норму. Уберите часы у одного проекта, чтобы освободить другой.» — констатация, не предупреждение.
10. **Лестница сроков:** строка на проект, четыре колонки — «Меньше / Сейчас / Больше / Максимум», рассчитанные от текущей ставки как `[max(1, h−3), h, h+3, h+6]` с отбрасыванием дублей и нулей. В каждой ячейке: ставка («5 ч/нед»), дата финиша, число недель. Колонка текущей ставки выделяется **весом шрифта и цветом чернил** (`--wolf-ink`, `font-weight: 600`, левое правило `--wolf-ink`), остальные — `--wolf-muted` с правилом `--wolf-rule`. Никакого цветового акцента.
11. **Прогнозы лестницы считаются той же формулой, что `forecastByRate` на бэкенде** (`weeks = remainingHours / ставка`, финиш = ближайший понедельник + `ceil(weeks)`). Формула не переписывается второй раз — выносится в общий модуль или приходит с бэкенда; расхождение «Бюджета» и «Лестницы» на одинаковой ставке — баг.
12. **Связь вкладок:** подпись под лестницей — «Тёмная колонка — текущая ставка часов из вкладки Бюджет». Изменение ставки на «Бюджете» отражается на «Лестнице» без перезагрузки (общий стейт секции из тикета 02).
13. **Мобильный вид (≤700px):** обе вкладки перестраиваются в одноколоночные карточки строк — как уже сделано для `.curve-row` в текущем `PlanningView.vue`. Четыре колонки лестницы становятся четырьмя строками внутри карточки проекта.

## Testing Decisions

- Ручная приёмка записи: подвинуть ползунок → открыть Гантт → плановые часы текущей недели изменились там же.
- Ручная приёмка дебаунса: протаскивание ползунка через весь диапазон порождает один `PUT`.
- Ручная приёмка отката: offline в devtools → ползунок возвращается к серверному значению, показана строка ошибки.
- Согласованность: ставка 5 ч/нед на «Бюджете» и колонка «5 ч/нед» на «Лестнице» дают одну и ту же дату финиша.
- Перебор нормы: сумма ползунков выше `availableWeeklyHours` → текст «перебор на N ч», ползунки не заблокированы, `PUT` проходит.
- Проект с `effortSource: ESTIMATED` показывает пометку «оценка»; проект без Дел и плановых часов — финиш «—».
- Тихий контракт 0.3: инспекция DOM при переборе — нет `red`/`#a33`, нет `role="alert"`, нет заблокированных полей.
- Клавиатура: ползунок доступен `Tab`-ом, стрелки меняют значение, изменение уходит на сервер.
- Геометрия: сверка `getBoundingClientRect()` колонок заголовка с ячейками первой строки на обеих вкладках; расхождения `left`/`width` ≤ 1px.
- Мобильная проверка на 390px: обе вкладки в одну колонку, ползунок доступен.
- Гейт визуального тикета: сборка → пересоздание контейнера → сверка хэшей ассетов → аутентификация → инспекция DOM.

## Out of Scope

Изменение `GET /api/v1/gantt/forecast` — фактический прогноз используется как есть, только показывается рядом. Запись ставки в будущие недели пачкой («с этой недели и до конца проекта») — это поведение кривой, вкладка «Кривые» (тикет 03).
