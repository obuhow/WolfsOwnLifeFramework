# Вкладка «Очередь»: последовательный сценарий и цена приоритета (вариант 2c)

Status: ready-for-agent
Blocked by: 01, 02

## Question

Реализовать вкладку «Очередь» — крайний полюс относительно «Бюджета»: вся недельная норма уходит на один проект за раз, ноль переключений, но последний в очереди ждёт годы. Инструмент сравнения сценария, а не второй план.

Референс: `ref/WOLF - планирование (варианты).dc.html`, вариант `2c`.

## Что сделать

1. **Строка на проект:** порядковый номер; название и подпись «N Дел · M ч»; полоса окна работ; «старт → финиш» и число недель; действие «выше».
2. **Расчёт:** курсор идёт по очереди, длительность проекта `dur = remainingHours / weeklyLimit` недель, старт следующего = финиш предыдущего. Полоса позиционируется от общей длительности прохода всей очереди (`left` и `width` в процентах). Проекты с нулевым остатком занимают минимальную ширину, из очереди не выпадают.
3. **Подзаголовок:** «Все 30 ч в неделю уходят на один проект за раз. Полный проход: N недель до <дата>.»
4. **Действие «выше»** — текстовое, `--wolf-muted`, при наведении `--wolf-ink`; у первой строки отсутствует. Перестановка пересчитывает сроки всех проектов ниже без перезагрузки данных.
5. **Порядок очереди — представление, не хранимое поле.** Действие «выше» **не пишет в БД**: базовый порядок — `ProjectRepository.findByUserOrderByTitleAsc` (порядок массива `projects[]` из ответа API), пользовательская перестановка живёт в `localStorage` (`wolf.loadCharts.queueOrder`) как список id. Проекты, появившиеся после сохранения порядка, встают в конец; исчезнувшие id игнорируются.
6. **Никаких `PUT` с этой вкладки.** Это единственная вкладка релиза, которая ничего не записывает на сервер — она отвечает на вопрос «а что, если по одному», а не задаёт план. Подпись внизу проговаривает это явно: «Крайний вариант последовательности: ноль переключений, но последний проект в очереди ждёт годы. Сравните с вкладкой Бюджет, где всё идёт разом.»
7. **Заливка полос** — градация нейтральными токенами по позиции: первая `--wolf-ink`, вторая-третья `--wolf-muted`, дальше `--wolf-faint`. Без цветовых акцентов.
8. **Геометрия** — одна CSS Grid координатная система для заголовка и всех строк.
9. **Мобильный вид (≤700px)** — одноколоночные карточки строк; действие «выше» остаётся доступной текстовой кнопкой.
10. **Клавиатура:** «выше» — настоящая `<button>`, доступная `Tab`-ом, с `aria-label` вида «Поднять выше: Разработка WOLF».

## Testing Decisions

- Ручная приёмка: поднятие проекта на позицию выше сдвигает старт/финиш всех, кто оказался ниже; сумма недель полного прохода не меняется.
- Порядок сохраняется между перезагрузками страницы; вкладка Network при действии «выше» не показывает запросов на сервер.
- Новый проект, созданный после сохранённого порядка, появляется в конце очереди; удалённый — исчезает без ошибки.
- Проект с нулевым остатком (факт перекрыл объём) отображается с минимальной полосой и не ломает раскладку.
- Первая строка не имеет действия «выше».
- Геометрия: сверка `getBoundingClientRect()` колонок заголовка с ячейками первой строки; расхождения `left`/`width` ≤ 1px.
- Тихий контракт 0.3: инспекция DOM — нейтральные токены, нет сигнальных цветов, нет `role="alert"`.
- Мобильная проверка на 390px: одна колонка, «выше» доступно.
- Клавиатура: `Tab` доходит до «выше», `Enter`/`Space` срабатывают.
- Гейт визуального тикета: сборка → пересоздание контейнера → сверка хэшей ассетов → аутентификация → инспекция DOM.

## Out of Scope

**Сохранение порядка очереди в БД и приоритет проекта как хранимое поле** — сознательно отложено: это продуктовое решение о модели данных, а не часть визуализации нагрузки. Автоматический перевод очереди в план (проставить `WeekPlan` по расписанию очереди) — вне объёма, вкладка ничего не записывает.
