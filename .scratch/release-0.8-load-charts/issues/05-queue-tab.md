# Вкладка «Очередь»: последовательный сценарий и цена приоритета (вариант 2c)

Status: resolved
Blocked by: 01, 02

## Question

Реализовать вкладку «Очередь» — крайний полюс относительно «Бюджета»: вся недельная норма уходит на один проект за раз, ноль переключений, но последний в очереди ждёт годы. Инструмент сравнения сценария, а не второй план.

Референс: `ref/WOLF - планирование (варианты).dc.html`, вариант `2c`.

## Что сделать

1. **Строка на проект:** порядковый номер; название и подпись «N Дел · M ч»; полоса окна работ; «старт → финиш» и число недель; действие «выше».
2. **Расчёт:** курсор идёт по очереди, длительность проекта `dur = remainingHours / weeklyLimit` недель, старт следующего = финиш предыдущего. Полоса позиционируется от общей длительности прохода всей очереди (`left` и `width` в процентах). Проекты с нулевым остатком занимают минимальную ширину, из очереди не выпадают.
3. **Подзаголовок:** «Все 30 ч в неделю уходят на один проект за раз. Полный проход: N недель до <дата>.»
4. **Действие «выше»** — текстовое, `--wolf-muted`, при наведении `--wolf-ink`; у первой строки отсутствует. Перестановка пересчитывает сроки всех проектов ниже без перезагрузки данных.
5. **Порядок очереди — представление, не хранимое поле.** Действие «выше» **не пишет в БД**: базовый порядок — `ProjectRepository.findByUserOrderByTitleAsc` (порядок массива `projects[]` из ответа API), пользовательская перестановка живёт в `localStorage` (`wolf.loadCharts.queueOrder`) как список id. Проекты, появившиеся после сохранения порядка, встают в конец; исчезнувшие id игнорируются.
6. **Никаких `PUT` с этой вкладки.** Это единственная вкладка релиза, которая ничего не записывает на сервер — она отвечает на вопрос «а что, если по одному», а не задаёт план. Подпись внизу проговаривает это явно: «Крайний вариант последовательности: ноль переключений, но последний проект в очереди ждёт годы. Сравните с вкладкой Бюджет, где всё идёт разом.»
7. **Заливка полос** — градация нейтральными токенами по позиции: первая `--wolf-ink`, вторая-третья `--wolf-muted`, дальше `--wolf-faint`. Без цветовых акцентов.
8. **Геометрия** — одна CSS Grid координатная система для заголовка и всех строк.
9. **Мобильный вид (≤700px)** — одноколоночные карточки строк; действие «выше» остаётся доступной текстовой кнопкой.
10. **Клавиатура:** «выше» — настоящая `<button>`, доступная `Tab`-ом, с `aria-label` вида «Поднять выше: Разработка WOLF».

## Testing Decisions

- Ручная приёмка: поднятие проекта на позицию выше сдвигает старт/финиш всех, кто оказался ниже; сумма недель полного прохода не меняется.
- Порядок сохраняется между перезагрузками страницы; вкладка Network при действии «выше» не показывает запросов на сервер.
- Новый проект, созданный после сохранённого порядка, появляется в конце очереди; удалённый — исчезает без ошибки.
- Проект с нулевым остатком (факт перекрыл объём) отображается с минимальной полосой и не ломает раскладку.
- Первая строка не имеет действия «выше».
- Геометрия: сверка `getBoundingClientRect()` колонок заголовка с ячейками первой строки; расхождения `left`/`width` ≤ 1px.
- Тихий контракт 0.3: инспекция DOM — нейтральные токены, нет сигнальных цветов, нет `role="alert"`.
- Мобильная проверка на 390px: одна колонка, «выше» доступно.
- Клавиатура: `Tab` доходит до «выше», `Enter`/`Space` срабатывают.
- Гейт визуального тикета: сборка → пересоздание контейнера → сверка хэшей ассетов → аутентификация → инспекция DOM.

## Out of Scope

**Сохранение порядка очереди в БД и приоритет проекта как хранимое поле** — сознательно отложено: это продуктовое решение о модели данных, а не часть визуализации нагрузки. Автоматический перевод очереди в план (проставить `WeekPlan` по расписанию очереди) — вне объёма, вкладка ничего не записывает.

## Answer

Блокирующие тикеты 01 (`GET /planning/load-charts`, `hoursPerDelo`) и 02 (каркас
`LoadCharts.vue`, `provide('loadCharts')`) уже слиты — их `Status: ready-for-agent`
устаревший дрейф (см. замечание в тикете 02). Реализация опирается на реальный
контракт эндпоинта и общий provide из каркаса. База ветки —
`release-0.8/feature/04-budget-and-ladder-tabs` (содержит каркас и вкладки 03/04).

**Сделано в этом тикете:**

1. Новый компонент `web/src/components/QueueTab.vue` — вкладка «Очередь» (2c),
   подключён в `LoadCharts.vue` вместо заглушки «подключается в тикете 05».
2. Порядок очереди — представление, не хранимое поле (п.5). Базовый порядок =
   `projects[]` из ответа API (уже `orderByTitleAsc` на бэкенде); пользовательская
   перестановка живёт в `localStorage` (`wolf.loadCharts.queueOrder`) как список id.
   Новые проекты встают в конец, исчезнувшие id игнорируются, база перезаписывается
   в LS при построении очереди.
3. Расчёт (п.2): курсор идёт по очереди, `dur = remainingHours / weeklyLimit` недель,
   старт следующего = финиш предыдущего. Прогноз каждого проекта — та же формула
   `forecastByRate` из `loadChartsForecast.js`, что на «Бюджете»/«Лестнице», но
   ставкой выступает вся недельная норма (`weeklyLimit`), а не ставка проекта.
   Полоса позиционируется от общей длительности прохода (`left`/`width` в % от
   `totalWeeks`); проекты с нулевым остатком занимают минимальную ширину
   (через `min-width: 2px`) и не выпадают из очереди.
4. Подзаголовок (п.3): «Все N ч в неделю уходят на один проект за раз. Полный проход:
   M недель до <дата>.» — считается от реального `weeklyLimit` и финиша очереди.
5. Действие «выше» (п.4, п.10): настоящая `<button>` с `aria-label` вида
   «Поднять выше: <название>», `--wolf-muted`, при наведении `--wolf-ink`; у первой
   строки отсутствует. Перестановка пересчитывает сроки всех ниже без перезагрузки
   данных и **не пишет в БД** (п.5) — `moveUp` только правит локальный порядок
   и `localStorage`.
6. Никаких `PUT` с вкладки (п.6): подпись внизу проговаривает это явно
   («Крайний вариант последовательности… Сравните с вкладкой Бюджет…»).
7. Заливка полос — градация нейтральными токенами (п.7): первая `--wolf-ink`,
   вторая-третья `--wolf-muted`, дальше `--wolf-faint`. Без цветовых акцентов.
8. Геометрия (п.8) — одна CSS Grid координатная система (`.queue-grid`) для
   заголовка и всех строк (`grid-template-columns: subgrid` на строках).
9. Мобильный вид (≤700px, п.9): одноколоночные карточки строк; «выше» остаётся
   доступной текстовой кнопкой.
10. Тихий контракт 0.3: нейтральные токены, нет `red`/`#a33`/`--wolf-danger`,
    нет `role="alert"`, без прогресс-баров и сигнальных цветов; все часы и даты —
    `font-variant-numeric: tabular-nums`.

**Проверка:**

- `npm run build` (web) — зелёный: `✓ 110 modules transformed`, без ошибок.
- Логика расчёта проверена отдельным node-скриптом (импорт реального
  `loadChartsForecast.js` + воспроизведение `schedule` из `QueueTab.vue`):
  цепочка дат (старт следующего = финиш предыдущего), недели
  `[ceil(132.5/30)=5, ceil(60/30)=2, 0, ceil(15/30)=1]`, сумма недель = 8,
  геометрия полос (сумма `width` ≈ 100%, последний `left+width` ≈ 100%),
  перестановка «выше» НЕ меняет сумму недель и финиш полного прохода,
  нулевой остаток не ломает раскладку.
- Гейт визуального тикета (сборка → пересоздание контейнера → сверка хэша
  ассетов → аутентификация → инспекция DOM) **не прогнан**: нет поднятого стека
  (docker-демон недоступен стабильно на слабом хосте). Статического нарушения
  тихого контракта 0.3 в коде нет — используются только токены `--wolf-*`,
  `role="alert"` и сигнальные цвета отсутствуют. Ручную приёмку из Testing
  Decisions (поднятие проекта сдвигает сроки ниже; `?chart=queue` открывает
  «Очередь»; порядок сохраняется между перезагрузками; вкладка Network не
  показывает запросов на сервер при «выше»; мобильная проверка на 390px;
  клавиатура Tab→Enter/Space) нужно прогнать в браузере отдельно — предлагаю
  после поднятия стека.
