# Общая диаграмма нагрузки: мультифильтр проектов и рутин

Status: resolved
Blocked by: 01, 02

## Question

На общей диаграмме нагрузки (вкладка «Кривые» и суммарная строка `monthlyLoad`) добавить
панель фильтров — мультивыбор проектов и рутин чекбоксами. Снятые с выбора проекты/рутины
**выпадают из общей суммарной нагрузки** (capacity пересчитывается), как в Яндекс.Директе,
где выбираешь статистику по отдельным кампаниям и по всем вместе. Бэкенд уже отдаёт все
проекты (`projects[]` с `curve`) и рутины (`routines[]` с `weeklyHours`) в одном ответе
`GET /planning/load-charts` — значит пересчёт делается на клиенте без перезапроса к
серверу, мгновенно.

## Что сделать

1. **Панель фильтров** в `LoadCharts.vue` над вкладками (или над содержимым): два блока —
   «Проекты» и «Рутины» — со списком чекбоксов (по `data.projects` и `data.routines`).
   Состояние выбора — `reactive` множество id проектов и рутин.
2. **Видимость дорожек** на вкладке «Кривые»: показываются только выбранные проекты
   (снятый чекбокс скрывает дорожку). Суммарная строка (`monthlyLoad`) пересчитывается
   только по выбранным.
3. **Пересчёт capacity на клиенте** — точная копия бэкенд-формулы
   `LoadChartsService.accumulateProjectMonthly` + вклад рутин:
   - для проекта без кривой: `weeklyPlanHours × 4.33` в каждый месяц горизонта
     (`weeklyPlanHours` берётся из `project.weeklyPlanHours` ответа);
   - для проекта с кривой: `hoursAt(month) × 4.33` по ступенчатым сегментам;
   - рутины: `weeklyHours × 4.33` в каждый месяц (общая константа на все выбранные рутины);
   - итог месяца = сумма проектов + сумма рутин; флаг `overLimit` = итог > `weeklyLimit`.
   Реализовать в `loadChartsForecast.js` (рядом с `forecastByRate`) как
   `computeMonthlyLoad(projects, routines, weeklyLimit, startMonday, horizonMonths,
   selectedProjectIds, selectedRoutineIds)` — чтобы формула жила в одном месте и не
   расходилась с бэкендом.
4. **«Все / Сброс»** — кнопка, выбирающая все проекты и рутины (состояние по умолчанию:
   выбрано всё, совпадает с текущим поведением бэкенда).
5. **Тихий контракт 0.3:** чекбоксы — нативные, без сигнальных цветов; перебор в суммарной
   строке — штриховкой, как сейчас.

## Testing Decisions

- Снять чекбокс проекта → его дорожка скрывается, суммарная строка уменьшается на его
  вклад (проверка: сумма часов выбранных проектов + рутин ≤ прежней).
- Снять все проекты, оставить одну рутину → суммарная строка равна `weeklyHours рутины
  × 4.33` каждый месяц.
- Пересчёт на клиенте даёт те же числа, что `monthlyLoad` из бэкенда при выборе всех
  (проверка совпадения с серверным `monthlyLoad` для полного набора).
- «Сброс» возвращает выбор всех проектов/рутин; суммарная строка совпадает с серверной.
- Клавиатура: `Tab` проходит по чекбоксам, `Space` переключает.
- Тихий контракт 0.3: нет `red`/`#a33`/`--wolf-danger`, нет `role="alert"`.

## Out of Scope

- Сохранение выбора фильтров в БД/URL — состояние сессионное (как у вкладки в localStorage).
- Серверный перезапрос по выбранным id — не нужен, все данные уже в ответе
  `load-charts`; пересчёт клиентский, мгновенный.
- Фильтр по области жизни (`lifeAreaIds`) остаётся как есть на бэкенде; мультифильтр
  проектов/рутин — дополнительный, клиентский слой поверх него.

## Answer

Реализовано в ветке `release-0.8/feature/06-project-curve-editor` (общая с тикетом 06).

- `LoadCharts.vue`: сверху вкладок — панель фильтра `<details>` с двумя столбцами
  чекбоксов (Проекты / Рутины) из `data.projects` и `data.routines`, счётчик выбранных
  (`проектов: X/N · рутин: Y/M`) и кнопка «Выбрать все». Состояние — `reactive` множества
  id (по умолчанию выбрано всё, как сейчас на бэкенде).
- Видимость дорожек на вкладке «Кривые» управляется выбором: `CurvesTab` получает пропс
  `selectedProjectIds` и рендерит только выбранные (`visibleProjects`).
- Суммарная строка (`monthlyLoad`) пересчитывается на клиенте функцией
  `computeMonthlyLoad` из `web/src/loadChartsForecast.js` — **дословная копия бэкенд-формулы**
  `LoadChartsService.accumulateProjectMonthly` + вклад рутин. Снятый проект/рутина выпадает
  из capacity мгновенно, без перезапроса к серверу (все данные уже в ответе load-charts).
- Написан скрипт проверки (`/tmp/verify_filters.mjs`): 10 метрик — полный выбор совпадает с
  серверной формулой, снятие проекта вычитает его вклад, только одна рутина = `weeklyHours
  × 4.33` каждый месяц, пустой выбор = нули, флаг `overLimit` корректен. Все проверки
  пройдены; тест поймал расхождение с бэкендом (первый месяц не клэмпился к startMonday) —
  исправлено до точного совпадения.
- Тихий контракт 0.3: нативные чекбоксы без сигнальных цветов; перебор в суммарной строке —
  штриховкой, как и было.

Проверка: `npm run build` зелёный; логика `computeMonthlyLoad` верифицирована скриптом.
Визуальный гейт (браузерная инспекция фильтра/суммарной строки) — ручная приёмка.
