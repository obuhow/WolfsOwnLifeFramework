# Release-документы WOLF

Все документы релизов находятся в каталогах `.scratch/release-<номер>-<название>/`.
Название каталога — часть идентификатора: если каталог переименован, все ссылки на него
обновляются в том же изменении.

## Шаблон

```text
.scratch/
└── release-<номер>-<название>/
    ├── spec.md       # единственная спецификация релиза
    ├── issues/       # планируемые тикеты, NN начинается с 01
    ├── bugs/         # обнаруженные дефекты, независимая нумерация
    └── spike/        # необязательные исследования и артефакты
```

`issues/` обязателен даже для ещё не разбитой спецификации; пустой каталог можно
создать заранее. `bugs/` и `spike/` появляются только когда нужны.

В `spec.md` хранятся цель, границы, решения прожарки, граф тикетов, критерии приёмки
и out of scope. Отдельный `grill.md` в корне релиза не используется: прожарка лежит
в `spec.md` или в `spike/`, если это отдельный исследовательский материал.

В `spike/` допускаются `RESULT.md`, скрипты, образцы, визуальные патчи и старые
варианты спецификации. Это не рабочие тикеты и не источник требований без ссылки из
`spec.md`.

## Не релизы

Каталоги `wayfinder-*` и другие effort-каталоги не переименовываются по этому правилу:
у них собственный формат с `map.md`. Архив отменённого объёма также получил номер и
название исходного релиза: `release-0.4-cancelled-demo-sandbox`.

## Правила ссылок

- в ссылках используется полный путь `.scratch/release-.../`;
- ссылки на исследование указывают на `.scratch/<release>/spike/...`;
- баг выбирается по релизу, где он обнаружен, и живёт в его `bugs/`;
- статус и комментарии тикета ведутся внутри соответствующего файла.
