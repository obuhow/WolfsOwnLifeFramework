# Релиз 1.6 — Архетипы демо-профилей

Status: `needs-triage`
Release: `1.6`
Feature slug: `release-1.6-demo-archetypes`
Depends on: `release-1.5-agent-chat-planner` (карточки агента могут быть заранее заполнены)
Tracker: local markdown

## Цель

Дать демо-гостю три содержательных профиля с готовой историей, чтобы систему можно
было показать не на пустом аккаунте. Переключение архетипа не маскируется под
синхронизацию контекста: это явная операция «начать заново как другой архетип» с
предупреждением о потере текущих данных.

## Зафиксированные решения

- Используется существующая модель демо-профилей и `reloadProfile` с очисткой данных;
  сквозное сосуществование нескольких профилей в одном аккаунте в релиз не входит.
- Внутренний slug `worker-class` сохраняется для совместимости. Отображаемое имя и
  история профиля меняются на «Инженер на разгоне»; миграция ссылок и slug не нужна.
- Готовая история включает проекты, Дела, Записи времени, цели, заметки и данные,
  достаточные для демонстрации последующих релизов.
- 90-секундный демонстрационный сценарий запускается на загруженном профиле, а не на
  пустом аккаунте. Существующий 15-шаговый приветственный тур не заменяется.
- В интерфейсе остаётся только разрешённое визуальным контрактом обозначение WOLF;
  новые эмодзи, красные алерты, проценты и декоративные прогресс-бары не вводятся.

## Acceptance criteria

- Гость видит три профиля с понятным отображаемым именем и краткой историей.
- Выбор другого профиля показывает предупреждение и требует явного подтверждения.
- После подтверждения старые пользовательские данные очищаются существующим
  механизмом, новый профиль загружается целиком, а при отмене ничего не меняется.
- Повторная загрузка одного профиля идемпотентна с точки зрения итогового набора данных.
- 90-секундный сценарий на каждом профиле имеет данные для всех демонстрируемых
  экранов; приветственный тур 1.2 продолжает работать отдельно.

## Out of scope

- Несколько активных архетипов в одном аккаунте.
- Перенос пользовательских данных между архетипами.
- Новый механизм авторизации или отдельные демо-аккаунты.
- Изменение `worker-class` в URL/API slug.
