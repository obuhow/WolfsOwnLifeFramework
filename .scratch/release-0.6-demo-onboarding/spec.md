## Problem Statement

Гость, получивший приглашение в WOLF, сегодня видит после регистрации пустую систему — ни одного Проекта, ни одной Записи времени, ни одной Цели. Пустой интерфейс не объясняет, зачем нужен каждый из шести разделов меню, и не даёт повода задержаться дольше первого клика. Мастер первого входа (0.4-08) частично закрывает эту проблему — три коротких шага (Проект → Цель → Норма) — но это ввод *своих* данных вслепую, без единого взгляда на то, как выглядит уже живущая в WOLF система.

Одновременно WOLF — не про демонстрационную песочницу без последствий (это явно отменено в релизе 0.4, тикет 06 → `wontfix`): гость входит в свой постоянный аккаунт, а не в изолированную демо-сессию с автоочисткой. Задача 0.6 — дать этому постоянному аккаунту предзаполненное содержимое по выбору гостя, а не пустоту, и провести короткий тур по интерфейсу, чтобы структура меню из релиза 0.5 не осталась абстрактным списком названий.

## Solution

Три элемента одного потока первого входа, включаемые вместо трёх шагов мастера 0.4-08 (которые остаются, но переезжают на ветку «Очистить профиль» — см. `## Соотношение с мастером 0.4-08`):

**1. Загрузка профиля.** Сразу после регистрации по инвайту — экран «Загрузка профиля» с тремя вариантами: Рабочий класс, Мудрый фрилансер, Свободный художник. Выбор загружает декларативный JSON-профиль в постоянный аккаунт гостя через расширенный `DemoFixtureGenerator`, даты пересчитываются относительно текущего дня загрузки.

**2. Знакомство.** Ведущий тур из 6–7 шагов — по одному на каждый пункт верхнего уровня утверждённого в 0.5 меню, с блокировкой интерфейса и подсветкой-вырезом вокруг активного элемента. Прерывается в любой момент.

**3. Финальный выбор.** «Оставить предзаполненный профиль» или «Очистить профиль» — без второго подтверждения. Очистка удаляет всё, что создал профиль (кроме справочника Областей жизни и 9 Сфер), сбрасывает норму на дефолт и передаёт управление трём шагам существующего мастера (0.4-08).

Технически: расширение уже существующего `DemoFixtureGenerator` (сейчас генерирует один жёстко закодированный набор) на приём декларативного профиля вместо встроенных данных; повторное использование `UserPurgeService` для очистки; новый Vue-компонент тура, работающий поверх утверждённой в 0.5 структуры `App.vue`.

## User Stories

1. Как гость, зарегистрировавшийся по инвайт-коду, я хочу увидеть экран выбора демо-профиля сразу после регистрации, чтобы посмотреть на живую систему, а не на пустой интерфейс.
2. Как гость, я хочу выбрать один из трёх профилей — Рабочий класс, Мудрый фрилансер, Свободный художник — по короткому описанию каждого, чтобы найти близкий своему образу жизни пример.
3. Как гость с загруженным профилем, я хочу видеть данные, датированные «на сегодня» (месяц истории времени, актуальные сроки Проектов), а не с фиксированными датами прошлого года, чтобы демонстрация выглядела живой в любой день после релиза.
4. Как гость, я хочу пройти ведущий тур по шести разделам меню — по одному клику на раздел за раз — чтобы понять, что находится за каждым названием без самостоятельного тыканья.
5. Как гость посреди тура, я хочу выйти в любой момент без потери прогресса объяснения, чтобы не чувствовать себя запертым в обязательном сценарии.
6. Как гость, завершивший или прервавший тур, я хочу увидеть явный выбор «Оставить» или «Очистить» и получить именно то, что выбрал — без скрытых полумер, чтобы не обнаружить чужие данные в своём личном пространстве позже.
7. Как гость, выбравший «Очистить профиль», я хочу сразу перейти к трём коротким шагам ввода своего реального Проекта, Цели и нормы (существующий мастер 0.4-08), чтобы не остаться перед пустым «Сегодня» без объяснения, что делать дальше.
8. Как пользователь, уже прошедший Знакомство, я хочу иметь возможность заново загрузить другой профиль через Настройки, чтобы передумать без обращения к владельцу системы.
9. Как читатель Сценариев использования в `/docs` (релиз 0.5), я хочу узнавать в текстовых историях трёх персонажей ту же личность, что вижу в загруженных данных, чтобы текст и демонстрация не противоречили друг другу.

## Implementation Decisions

### Порядок первого входа (заменяет часть 0.4-08)

```
Инвайт-код → Регистрация → «Загрузка профиля» (новый экран) → загрузка данных
    → Знакомство (тур, 6–7 шагов) → Финальный выбор
        ├── «Оставить предзаполненный профиль» → редирект на /calendar (Ежедневник)
        └── «Очистить профиль» → UserPurgeService (частичный, см. ниже)
            → Мастер 0.4-08 (Проект → Цель → Норма) → редирект на /today
```

### Расширение `DemoFixtureGenerator`

Текущая реализация (`api/src/main/java/ru/wolf/api/demo/DemoFixtureGenerator.java`) генерирует один жёстко закодированный набор данных методом `populate(User user)`. Расширяется до `populate(User user, DemoProfile profile)`, где `DemoProfile` — модель, десериализованная из декларативного JSON-файла (`assets/profiles/<slug>.json`, три файла: `worker-class.json`, `wise-freelancer.json`, `free-artist.json`, структура — по эталону тикета «Содержание трёх демо-профилей» карты 05-07). Существующая проверка идемпотентности («отказ, если у пользователя уже есть данные») сохраняется без изменений — важна и для первой загрузки, и для проверки перед повторной (см. ниже).

Дата-сдвиг: все даты профиля заданы смещением от `LocalDate.now(zone)` (`startOffsetDays`, `dueOffsetDays`, `timeEntriesHistoryDays` = 30) — не абсолютными датами. Существующий детерминированный `Random(user.getId() ^ 0x5A5A5A5AL)` используется там, где профиль не специфицирует точное значение (например, порядок Дел внутри дня).

Обязательный охват профиля — по каждому пункту утверждённого в 0.5 меню экран должен быть непустым: Проекты, Дела, Записи времени (30 дней истории), Цели, Идеи (для «Свободного художника» особенно плотно — Банк идей), Синергия/Диаграмма компетенций, Рутины (правила повторения через `RecurrenceService`), Заметки (минимум одна с автором «Агент»).

### Экран «Загрузка профиля»

Новый компонент, маршрут `/onboarding/profile` (первый шаг после регистрации, перед `/onboarding` мастера 0.4-08, который теперь условно пропускается). Заголовок «Загрузка профиля», подзаголовок «Посмотри, как можно использовать WOLF. Выбери пункт, чтобы загрузить демо-конфигурацию». Три карточки — по одной на профиль, короткое описание (2-3 предложения, тон профиля — с характером, см. тикет «Содержание трёх демо-профилей»). Клик по карточке вызывает `POST /api/v1/onboarding/load-profile` с `slug` профиля → бэкенд десериализует JSON, вызывает `DemoFixtureGenerator.populate(user, profile)` → редирект на `/onboarding/tour`.

### Тур Знакомства

Новый Vue-компонент `OnboardingTour.vue`, монтируется поверх `App.vue` после утверждённой в 0.5 структуры меню — **зависимость от релиза 0.5 обязательна**, тур ссылается на конкретные DOM-элементы шести пунктов верхнего уровня.

Механика: модальное затемнение с вырезом-подсветкой под активный пункт меню, блокирующее клики вне цели шага; текстовая подсказка рядом с вырезом; без прогресс-бара (тихий контракт 0.3). 6–7 шагов — по одному на каждый пункт NAV (Утренний обход · Ежедневник · Управление делами · Управление потоком · Настройки · Документация). На мобильном — та же ведущая механика через drawer-меню: подсказка инструктирует открыть меню, тур ждёт открытия, затем клика по нужному пункту внутри drawer.

Выход возможен в любой момент (кнопка «Пропустить» / клик вне модалки не засчитывается как навигация, но кнопка явно доступна) → сразу переход к Финальному выбору. Состояние тура не сохраняется в БД — начинается заново при следующем запуске (если пользователь вручную инициирует повторный тур; автоматически при обычном входе тур не повторяется, см. ниже).

Флаг видимости: переиспользуется `onboarding_completed_at` из тикета 0.4-01 — отдельного признака для тура не создаётся. Тур показывается ровно один раз в общем потоке первого входа; `admin` и личный аккаунт владельца, уже прошедшие/не проходящие онбординг, тур не видят.

### Финальный выбор и очистка

Компонент `OnboardingFinalChoice.vue`. Две текстовые кнопки-действия (тихий контракт: без цвета, без иконок предупреждения) — «Оставить предзаполненный профиль» и «Очистить профиль». Клик по «Очистить» — само по себе подтверждение, второго модального окна нет.

Очистка удаляет: Проекты, Дела, Записи времени, Цели, Идеи, Заметки — всё, что создал загруженный профиль. Не удаляет: Области жизни и 9 Сфер (справочник). Недельная норма часов сбрасывается на системный дефолт.

Реализация: расширение `UserPurgeService` (сейчас — заглушка, полагающаяся на `ON DELETE CASCADE` при удалении пользователя целиком) новым методом `purgeProfileData(User user)`, который удаляет перечисленные сущности точечно, не трогая самого пользователя, справочник Сфер и Области жизни. Покрывается тестом на осиротевшие строки (никаких Записей времени без пользователя, никаких Синергий, ссылающихся на удалённый Проект).

После очистки — редирект на `/onboarding` (существующий мастер 0.4-08, без изменений его собственной логики), затем на `/today`.

### Повторная загрузка в Настройках

Новый блок в `SettingsView.vue` — «Демо-профиль»: кнопка «Загрузить другой профиль», открывающая тот же выбор из трёх карточек. Выбор нового профиля (в т.ч. повторный выбор текущего) сначала вызывает `purgeProfileData`, затем `populate` с новым профилем — та же последовательность, что при «Очистить профиль», без промежуточного экрана мастера (пользователь уже прошёл его или явно отказался ранее).

### Соотношение с мастером 0.4-08

Мастер 0.4-08 (маршрут `/onboarding`, три шага Проект → Цель → Норма) **не переписывается** — код и API-контракт остаются как есть. Меняется только точка входа: раньше guard в `main.js` вёл туда сразу после регистрации; теперь guard ведёт на `/onboarding/profile` (выбор профиля) первым, а на `/onboarding` (три шага) — только после явного выбора «Очистить профиль» в Финальном выборе Знакомства, минуя автоматический показ.

## Testing Decisions

- `DemoProfileLoadIT`: загрузка каждого из трёх профилей на чистом пользователе — каждый пункт утверждённого меню 0.5 непустой (Проекты, Дела, Записи времени за последние 30 дней, Цели, Идеи, Синергия/Диаграмма компетенций, Рутины, Заметки).
- Дата-сдвиг: тест, запущенный в разные календарные дни (или с мокнутым `Clock`), даёт одинаково «свежий» результат — сегодняшний день истории заполнен частично, не пуст и не полон целиком.
- `ProfilePurgeIT`: после `purgeProfileData` — ноль Проектов/Дел/Записей времени/Целей/Идей/Заметок этого пользователя; Области жизни и 9 Сфер остались; норма сброшена на дефолт; ни одной осиротевшей строки в дочерних таблицах.
- Ручная приёмка полного пути в браузере: инвайт → регистрация → выбор профиля → данные видны на всех пунктах меню → тур (6–7 шагов, блокировка интерфейса подтверждена) → «Оставить» — данные на месте.
- Отдельный прогон: тот же путь → тур → «Очистить» → три шага мастера 0.4-08 → «Сегодня» показывает остаток нормы по только что введённым пользователем данным, не по профилю.
- Мобильная проверка тура: drawer открывается по подсказке, клик по пункту внутри засчитывается как шаг тура.
- Повторная загрузка в Настройках: выбор нового профиля поверх старого — точная очистка перед наполнением, без остатков.
- Тихий контракт 0.3: инспекция DOM тура и финального выбора — без цвета, без прогресс-бара, без иконок предупреждения.
- Гейт визуальных тикетов неизменен: сборка → пересоздание контейнеров → сверка хэшей с `web/dist` → аутентификация в браузере → инспекция DOM.

## Out of Scope

- **Содержание Дел/Заметок для «Мудрого фрилансера» и «Свободного художника» вплоть до последней строки** — эталон задан для «Рабочего класса» (тикет «Содержание трёх демо-профилей» карты 05-07), два оставшихся профиля дописываются по тому же образцу как часть реализации этого релиза, не архитектурная задача карты.
- **Отмена последнего действия внутри тура** (undo) — не предусмотрена; тур — только вперёд/выход, без отката отдельных шагов.
- **AI-анализ содержимого профиля** — вне объёма; профили статичны и декларативны.
- **Английская локализация профилей** — только русский, как и весь релиз 0.5.
- **Изменение самого мастера 0.4-08** — код не трогается, меняется только момент его вызова.
- **Автоматическое периодическое обновление дат профиля без действия пользователя** — пересчёт дат происходит только в момент загрузки/повторной загрузки, не фоновой задачей.

## Further Notes

**Зависимость от 0.5 не декоративная.** Тур ссылается на конкретные DOM-элементы (`data-tour-target` атрибуты на шести пунктах NAV) — если структура меню 0.5 меняется после реализации тура, тур ломается тихо (элемент не найден → шаг не подсвечивается). Тикет реализации обязан добавить `data-tour-target` атрибуты в `App.vue` релиза 0.5 или явным патчем поверх него.

**`DemoFixtureGenerator` — общий код с отменённым 0.4-06.** Сервис уже существует и сохранён по решению тикета 0.4-05 (`resolved`, переопределён под многопрофильную модель). Эта спецификация не создаёт сервис заново — расширяет параметризацию существующего.

**Профиль как обычные данные.** Ничего из загруженного профилем не помечено служебным флагом «создано системой» — Дела/Проекты/Заметки переименовываются и удаляются как любые другие сущности пользователя. Это сознательное решение: гость должен свободно редактировать демо-данные, не боясь «сломать демо».
