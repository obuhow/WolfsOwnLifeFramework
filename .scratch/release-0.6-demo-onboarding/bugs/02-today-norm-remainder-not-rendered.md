# Остаток дневной нормы 0.4-07: API считает, «Сегодня» не показывает

Type: bug
Status: open
Blocked by:
Найдено при: релиз 0.6, тикет 04 (Финальный выбор и очистка профиля)
Регрессия в: `release-0.4-multiuser-demo`, тикет 07 (`Status: resolved`)

## Что не так

Тикет `.scratch/release-0.4-multiuser-demo/issues/07-today-norm.md` помечен
`resolved`, но поставлена только серверная половина — тот же разрыв, что в баге 09.

Коммит `622ecf7` («feat(release-0.4): ticket 07 today daily norm remainder») изменил
**один файл** — `api/.../timeentry/TimeEntryController.java`, добавив в
`TodayResponse` три поля: `dayNormMinutes`, `dayFactMinutes`, `remainingMinutes`.
Расчёт корректный: логический день по `dayEnd`, «Сон» исключён из факта,
`PRIMARY_ONLY` схлопывает параллельные интервалы.

Фронтенд эти поля не читает вообще:

```
grep -rn "remainingMinutes\|dayNormMinutes\|dayFactMinutes" web/src/   → пусто
```

Проверка на живом стенде (гость `purger`, норма 12 ч/нед):

```
GET /api/v1/time-entries/today
{'dayNormMinutes': 90, 'dayFactMinutes': 0, 'remainingMinutes': 90}
```

90 минут = 12 ч ÷ 7, округлено вниз по 15-минутной сетке — API прав. На экране
«Сегодня» этих чисел нет ни в каком виде; в DOM нет ни строки со словом «норма»,
«остаток» или «осталось».

Формулировка тикета 0.4-07 при этом прямо про экран: «Экран „Сегодня“ показывает
остаток дневной нормы часов — **то, ради чего новый пользователь и приходит**.
Нейтральный факт в информационной шапке дня, без цвета, процентов и прогресс-бара».
Чек-лист требует `TodayNormIT` — такого теста в `api/src/test` нет.

## Почему это важно

1. Это заявленная ценность продукта, а не второстепенная деталь: 0.4-07 поставлен
   **до** мастера 0.4-08 именно потому, что мастер приводит пользователя на этот
   экран ради остатка.
2. Тестовое решение тикета 0.6-04 требует: «после завершения мастера „Сегодня“
   показывает остаток нормы по только что введённым пользователем данным». Проверить
   это в браузере невозможно — показывать нечего. В тикете 0.6-04 пункт подтверждён
   косвенно (норма 12 ч сохранена и видна в Настройках) с явной пометкой.
3. Вся серверная работа уже сделана и покрыта — остался только рендер.

## Что сделать

- [ ] Вывести остаток в информационной шапке дня на `/today`: нейтральный факт,
      без цвета, процентов и прогресс-бара (визуальный контракт 0.3).
- [ ] Превышение нормы формулировать как «сверх», а не как отрицательный остаток
      («осталось −1 ч 30 мин» — оценочная формулировка, см. Pitfalls 0.4-07).
- [ ] `TodayNormIT` по чек-листу 0.4-07: логический день с `dayEnd=02:00`; «Сон»
      вне факта; превышение даёт положительное «сверх»; `PRIMARY_ONLY` не удваивает
      параллельные слоты.
- [ ] Гейт: сборка → пересоздание контейнера → сверка хэшей с `web/dist` →
      аутентификация в браузере → инспекция DOM на пользователе с непустым днём
      (остаток ненулевой и осмысленный).
- [ ] Решить, оставлять ли `Status: resolved` у 0.4-07 со ссылкой на этот баг.
