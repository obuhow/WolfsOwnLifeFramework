# Остаток дневной нормы 0.4-07: API считает, «Сегодня» не показывает

Type: bug
Status: resolved
Blocked by:
Найдено при: релиз 0.6, тикет 04 (Финальный выбор и очистка профиля)
Регрессия в: `release-0.4-multiuser-demo`, тикет 07 (`Status: resolved`)

## Что не так

Тикет `.scratch/release-0.4-multiuser-demo/issues/07-today-norm.md` помечен
`resolved`, но поставлена только серверная половина — тот же разрыв, что в баге 09.

Коммит `622ecf7` («feat(release-0.4): ticket 07 today daily norm remainder») изменил
**один файл** — `api/.../timeentry/TimeEntryController.java`, добавив в
`TodayResponse` три поля: `dayNormMinutes`, `dayFactMinutes`, `remainingMinutes`.
Расчёт корректный: логический день по `dayEnd`, «Сон» исключён из факта,
`PRIMARY_ONLY` схлопывает параллельные интервалы.

Фронтенд эти поля не читает вообще:

```
grep -rn "remainingMinutes\|dayNormMinutes\|dayFactMinutes" web/src/   → пусто
```

Проверка на живом стенде (гость `purger`, норма 12 ч/нед):

```
GET /api/v1/time-entries/today
{'dayNormMinutes': 90, 'dayFactMinutes': 0, 'remainingMinutes': 90}
```

90 минут = 12 ч ÷ 7, округлено вниз по 15-минутной сетке — API прав. На экране
«Сегодня» этих чисел нет ни в каком виде; в DOM нет ни строки со словом «норма»,
«остаток» или «осталось».

Формулировка тикета 0.4-07 при этом прямо про экран: «Экран „Сегодня“ показывает
остаток дневной нормы часов — **то, ради чего новый пользователь и приходит**.
Нейтральный факт в информационной шапке дня, без цвета, процентов и прогресс-бара».
Чек-лист требует `TodayNormIT` — такого теста в `api/src/test` нет.

## Почему это важно

1. Это заявленная ценность продукта, а не второстепенная деталь: 0.4-07 поставлен
   **до** мастера 0.4-08 именно потому, что мастер приводит пользователя на этот
   экран ради остатка.
2. Тестовое решение тикета 0.6-04 требует: «после завершения мастера „Сегодня“
   показывает остаток нормы по только что введённым пользователем данным». Проверить
   это в браузере невозможно — показывать нечего. В тикете 0.6-04 пункт подтверждён
   косвенно (норма 12 ч сохранена и видна в Настройках) с явной пометкой.
3. Вся серверная работа уже сделана и покрыта — остался только рендер.

## Answer

Реализовано в ветке `fix/02-today-norm-remainder-not-rendered`.

### Что сделано

- `TodayView.vue`: добавлен `dayNormLabel` (computed) и строка в информационной
  шапке дня рядом с `.eyebrow` датой/таймзоной/ночью. Формулировки строго по
  тикету 0.4-07: `осталось {ост} из {норма}` при недоборе; `норма выбрана` при
  точном совпадении; `норма выбрана · +{излишек} сверх` при превышении —
  положительный «сверх», никогда отрицательный остаток. Строка отсутствует
  полностью, если `dayNormMinutes <= 0` (норма не задана/равна нулю), не
  показывается как «0 ч».
- `formatMinutesLabel()`: `90` → `1 ч 30 мин`, `240` → `4 ч`, `15` → `15 мин`
  (без «0 ч» перед короткими интервалами).
- Стиль — переиспользует `.eyebrow` (нейтральные чернила, тот же `rgb(115,115,115)`),
  без цвета/процентов/прогресс-бара/иконок — тихий контракт 0.3 соблюдён.
- `TodayNormIT` (7 тестов) — весь чек-лист 0.4-07: логический день `dayEnd=02:00`
  (послеполуночная работа считается во вчерашнем логическом дне), «Сон»
  исключён из факта, `PRIMARY_ONLY` не удваивает пересекающиеся интервалы,
  недобор даёт положительный остаток, превышение даёт отрицательный
  `remainingMinutes` (фронт переворачивает его в «сверх»), округление нормы
  вниз до 15-минутной сетки (30 ч/нед → 4 ч 15 мин, не 4 ч 30 мин), норма
  отсутствует при `availableWeeklyHours=0`.

### Найденный попутно бэкенд-баг: `sumMergedMinutes` падал на `PRIMARY_ONLY`

`calculateDailyNormAndFact` строит список `doneEntries.stream()...toList()` —
`Stream#toList()` возвращает **неизменяемый** список. `sumMergedMinutes()`
вызывал на нём `.sort(...)`, что бросает `UnsupportedOperationException` при
любом непустом списке DONE-записей для пользователя с `hourAccountingMode=
PRIMARY_ONLY` (дефолт для всех новых аккаунтов). Экран «Сегодня» отдавал 500
на `GET /today` для любого пользователя, у которого есть хотя бы одна
завершённая запись — то есть бы не заработал вообще ни у одного реального
пользователя после рендера строки остатка. Исправлено копированием в
`ArrayList` перед сортировкой (`TimeEntryController.java`, `sumMergedMinutes`).
Это не переписывание расчёта (границы тикета соблюдены) — тот же алгоритм,
без мутации входного неизменяемого списка.

### Проверено

`TodayNormIT` 7/7 зелёных, `TimeEntryApiIT` 21/21 зелёных (регрессии нет).
Гейт пройден: `bootJar` → `npm run build` → `docker compose build api web` →
пересоздание изолированного стека воркtree (`wolf02todaynorm`: web :8095,
api :8096, db :5440) → сверка хэшей (`index-DQdsVs-u.js` + `index-BV5zf67h.css`
совпадают с `web/dist`) → аутентификация в браузере (гость `normtest`,
`availableWeeklyHours=12` → норма 90 мин) → инспекция DOM через
`scripts/cdp_driver.py` (headless Chrome, CDP).

Три состояния подтверждены живыми числами из API и текстом в DOM:

| Состояние | API (`dayNorm`/`dayFact`/`remaining`) | Текст в DOM |
|---|---|---|
| Недобор | 90 / 30 / 60 | `осталось 1 ч из 1 ч 30 мин` |
| Норма ровно | 90 / 90 / 0 | `норма выбрана` |
| Превышение | 90 / 105 / −15 | `норма выбрана · +15 мин сверх` |
| Норма не задана | `availableWeeklyHours=0` | строка отсутствует в DOM (0 `.day-norm-label`) |

Цвет строки `rgb(115, 115, 115)` — тот же нейтральный `.eyebrow`, что и
остальная информационная шапка; ни в одном состоянии не менялся (проверено
компьютерным стилем `getComputedStyle`).

### Решение по 0.4-07

багом.
