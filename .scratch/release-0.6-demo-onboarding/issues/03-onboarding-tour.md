# Тур Знакомства: ведущие подсказки по шести пунктам меню

Status: resolved
Blocked by: 02
Depends on: release-0.5-navigation-docs (утверждённая структура меню и DOM-цели тура)

## Question

Реализовать ведущий тур с подсветкой-вырезом по решениям тикета «Механика Знакомства: тур, финальный выбор, повторная загрузка» карты `.scratch/wayfinder-releases-05-07/map.md`.

## Что сделать

1. Новый компонент `OnboardingTour.vue`, монтируется поверх `App.vue` после релиза 0.5. Добавить `data-tour-target` атрибуты на шесть пунктов верхнего уровня NAV (Утренний обход · Ежедневник · Управление делами · Управление потоком · Настройки · Документация) в `App.vue`, если их там ещё нет.
2. Механика: модальное затемнение с вырезом под активный элемент + текстовая подсказка рядом. Блокирует клики вне цели текущего шага. 6–7 шагов, один клик = один пункт верхнего уровня. Без прогресс-бара («шаг 3 из 7»).
3. Выход в любой момент — явная кнопка «Пропустить»/«Завершить». Прерывание не требует специального состояния — сразу переход к Финальному выбору (тикет 04).
4. Состояние тура не сохраняется в БД — при следующем ручном запуске (см. Настройки, тикет 05) начинается заново.
5. Мобильное поведение: та же ведущая механика через drawer — подсказка инструктирует открыть меню, тур ждёт открытия drawer, затем клика по нужному пункту внутри него.
6. Показ тура управляется `onboarding_completed_at` (существующее поле из 0.4-01) — не создавать отдельный признак.

## Testing Decisions

- Ручной обход всех 6–7 шагов на десктопе — подсветка следует за кликами, интерфейс вне цели заблокирован.
- Мобильный обход — тур открывает drawer по подсказке, засчитывает клик внутри него.
- Прерывание на любом шаге (2, 4, 6) — сразу попадает на Финальный выбор.
- Инспекция DOM: нет прогресс-бара, нет цветных индикаторов (тихий контракт 0.3).
- Гейт: сборка → пересоздание контейнера → сверка хэшей с `web/dist` → аутентификация в браузере → инспекция DOM.

## Out of Scope

Финальный выбор и очистка (тикет 04). Изменения самой структуры меню — тур только читает `data-tour-target`, не меняет NAV.

## Answer

Реализовано в ветке `feature/03-onboarding-tour`.

### Что сделано

- `web/src/components/OnboardingTour.vue` — оверлей тура: затемнение четырьмя
  полосами вокруг выреза, графитовая рамка выреза, подсказка рядом. Клик
  слушается в фазе перехвата, потому что триггеры групп в `App.vue` гасят
  всплытие (`@click.stop`).
- `web/src/onboardingTour.js` — состояние тура в памяти вкладки; в БД ничего не
  сохраняется, при следующем ручном запуске тур начинается заново.
- `web/src/components/OnboardingTourEntry.vue` + маршрут `/onboarding/tour` —
  точка входа: включает режим тура и уводит на `/morning`. Своего интерфейса нет,
  потому что тур идёт по настоящему меню поверх обычной оболочки.
- `App.vue` — добавлены `data-tour-target` на шесть пунктов верхнего уровня (и в
  десктопной шапке, и в drawer) + `data-tour-target="menu"` на кнопку меню.
  Структура NAV не менялась — только атрибуты-якоря.
- `main.js` — гейт онбординга молчит, пока тур активен: иначе первый же шаг
  вернул бы гостя на экран выбора профиля.
- `OnboardingFinalChoiceStub.vue` + маршрут `/onboarding/final` — честная
  заглушка, тикет 04 заменит её на настоящий Финальный выбор.

### Проверено в браузере (headless Chrome через CDP, контейнер :5176)

Гейт пройден полностью: сборка → пересоздание контейнера → сверка хэшей
(`index--9euSH8W.js` совпадает с `web/dist`) → аутентификация → инспекция DOM.

- **Десктоп 1440×900:** все 6 шагов, вырез обнимает цель на каждом шаге
  (`обнимает=True` ×6), последняя кнопка — «Завершить», финиш на
  `#/onboarding/final`.
- **Блокировка интерфейса:** клик в затемнение не меняет маршрут
  (`elementFromPoint='tour-shade'`); клик по чужому пункту меню шаг не
  засчитывает.
- **Вырез вокруг группы:** при раскрытом подменю вырез охватывает и сам список
  (16 ссылок), `covers=true`.
- **Мобильный 390×780:** `nav-desktop` скрыт, тур подсвечивает кнопку меню с
  подсказкой «Меню», ждёт открытия drawer, засчитывает клик по пункту внутри.
  Полный обход — 6 шагов, финиш на `#/onboarding/final`.
- **Прерывание на шагах 2, 4, 6:** «Пропустить» → сразу `#/onboarding/final`.
- **Тихий контракт 0.3:** `progressBars=0`, счётчика «шаг N из M» нет,
  `svgIcons=0`, эмодзи нет, `boxShadow: none`, `borderRadius: 0`, только
  графит `rgb(26,26,26)` и затемнение `rgba(26,26,26,.42)`.

### Найденные и исправленные дефекты

1. **Раскрытая группа в drawer уводила следующую цель за нижний край экрана**
   (`outline top: 869` при высоте 780) — тур подсвечивал невидимый пункт и
   вставал. Добавлен `ensureVisible()`: цель подкручивается в кадр.
2. **`scrollIntoView({behavior:'smooth'})` из rAF-цикла — livelock:** каждый
   следующий кадр перезапускал анимацию до её завершения, прокрутка не
   доезжала. Заменено на мгновенную прокрутку с защитой от повторов.
3. **Раскрытое десктопное подменю перекрывало цель следующего шага** — после
   шага-группы подменю закрывается штатным Escape оболочки.
