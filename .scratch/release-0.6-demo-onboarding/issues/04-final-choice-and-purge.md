# Финальный выбор и очистка профиля

Status: resolved
Blocked by: 03

## Question

Реализовать выбор «Оставить / Очистить» и точечную очистку данных профиля по решениям тикета «Механика Знакомства» карты `.scratch/wayfinder-releases-05-07/map.md`.

## Что сделать

1. Новый компонент `OnboardingFinalChoice.vue`. Две текстовые кнопки-действия без подтверждающего второго диалога: «Оставить предзаполненный профиль» и «Очистить профиль».
2. «Оставить» → `POST /api/v1/onboarding/complete` (существующий эндпоинт 0.4-08, `onboarding_completed_at = now()`) → редирект на `/calendar`.
3. «Очистить» → расширить `UserPurgeService` новым методом `purgeProfileData(User user)`: точечное удаление Проектов, Дел, Записей времени, Целей, Идей, Заметок текущего пользователя (не сам аккаунт, не через `ON DELETE CASCADE` пользователя). Не удалять: Области жизни, 9 Сфер (справочник). Сбросить `availableWeeklyHours` на системный дефолт.
4. После `purgeProfileData` → редирект на `/onboarding` (существующий мастер 0.4-08 — Проект → Цель → Норма, без изменений его кода) → по завершении мастера `onboarding_completed_at` проставляется как обычно → `/today`.

## Testing Decisions

- `ProfilePurgeIT`: после `purgeProfileData` — ноль Проектов/Дел/Записей времени/Целей/Идей/Заметок этого пользователя; Области жизни и 9 Сфер целы; норма — дефолт; ноль осиротевших строк в дочерних таблицах (Синергия, зависимости Проектов, недельные планы).
- Браузерная проверка ветки «Оставить»: данные профиля видны после редиректа на `/calendar`.
- Браузерная проверка ветки «Очистить»: экраны Проектов/Дел/Целей пусты, мастер 0.4-08 запускается, после его завершения «Сегодня» показывает остаток нормы по только что введённым пользователем данным.
- Гейт: сборка → пересоздание контейнера → сверка хэшей с `web/dist` → аутентификация в браузере → инспекция DOM.

## Out of Scope

Сам мастер 0.4-08 — не переписывается. Повторная загрузка из Настроек (тикет 05, использует тот же `purgeProfileData`, но другой вызывающий поток).

## Answer

Реализовано в ветке `feature/04-final-choice-and-purge`.

### Что сделано

- `web/src/components/OnboardingFinalChoice.vue` — две текстовые кнопки-действия
  без подтверждающего второго диалога. Заменил заглушку `OnboardingFinalChoiceStub.vue`
  (удалена), маршрут `/onboarding/final` из тикета 03 не тронут — выход из тура
  работает как раньше.
- `POST /api/v1/onboarding/purge-profile` — ветка «Очистить». `onboardingCompletedAt`
  здесь намеренно **не** ставится: флаг проставит сам мастер по завершении, иначе
  прерванный мастер оставил бы гостя в пустой системе без возможности вернуться.
- `UserPurgeService.purgeProfileData` расширен до полного порядка удаления
  (было — 14 таблиц, стало 22) и снабжён константой `DEFAULT_WEEKLY_HOURS = 30`,
  совпадающей с `V21__add_available_weekly_hours.sql`.
- Восемь репозиториев получили недостающие пакетные удаления
  (`FocusSession`, `FocusDistraction`, `DailyChecklistItem`, `LoadCurveEntry`,
  `WeekPlan`, `DeloProject`, `RoutineGoal`, `ActivityMapping`, `SyncExternalId`).
- `web/src/components/OnboardingWizardView.vue` + маршрут `/onboarding` —
  см. «Найденный пробел» ниже.

### Найденный пробел: у мастера 0.4-08 не было экрана

Тикет 0.4-08 помечен `resolved`, но по факту в коммите `da5da47` появился только
API (`/step1..step3`, `/complete`, `/skip`) — Vue-экрана и маршрута `/onboarding`
не существовало. Ветка «Очистить» по пункту 4 обязана приводить именно туда, то
есть увела бы гостя на несуществующий маршрут сразу после удаления его данных.

Написал недостающий экран по описанию 0.4-08 (один вопрос на шаг, пошаговое
сохранение, поле с нижним правилом, текстовые действия, без прогресс-бара).
Логику API мастера не менял — Out of Scope соблюдён.

### Порядок удаления — не косметика

`focus_session.delo_id` объявлен `ON DELETE RESTRICT` (V25): пока живы сессии
фокуса, удаление Дел падает на внешнем ключе. Связки без своего `user_id`
(`delo_project`, `routine_goal`, `load_curve_entry`) чистятся через владельца
до его удаления.

### Проверено

`ProfilePurgeIT` — 5/5 зелёных, профиль наполняется настоящей демо-фикстурой
«Мудрый фрилансер», а не пустой базой:

- ноль Проектов/Дел/Записей времени/Целей/Идей/Заметок; Области жизни и 9 Сфер целы; норма — дефолт;
- ноль осиротевших строк в 14 дочерних таблицах (Синергия, зависимости Проектов, недельные планы + остальные);
- изоляция арендаторов: соседний профиль не затронут;
- эндпоинт оставляет `onboardingCompleted=false`;
- очищенный профиль можно загрузить заново (основа тикета 05).

Гейт пройден: `bootJar` → `compose build` → пересоздание контейнеров → сверка
хэшей (`index-D41X78I-.js` + `index-CMpJhdex.css` совпадают с `web/dist`) →
аутентификация в браузере → инспекция DOM. Изолированный стек воркtree:
web :5177, api :8086, db :5438.

**Ветка «Оставить»** (гость `keeper`): клик → `#/calendar?view=week`, диалогов
подтверждения 0, 6 Проектов на месте, `onboardingCompleted=true`, демо-данные
видны на экране.

**Ветка «Очистить»** (гость `purger`): было 6 Проектов / 13 Дел / 3 Цели → стало
0 / 0 / 0, Области жизни 4 и Сферы 9 целы, `#/onboarding`. Экраны Проектов, Дел и
Целей пусты (0 строк). Мастер прошёл все три шага; после завершения
`onboardingCompleted=true`, норма **12 ч** (введена пользователем, не 30 из демо),
Проект «Свой первый проект» и Цель «Продвинуть свой проект» — свои, не демонстрационные.

Сверка напрямую в БД после очистки:

| пользователь | норма | проектов | дел | записей | целей | областей | сфер |
|---|---|---|---|---|---|---|---|
| keeper (оставил) | 30.00 | 6 | 13 | 136 | 3 | 4 | 9 |
| purger (очистил) | 12.00 | 1 | 1 | 1 | 1 | 4 | 9 |

У `purger` единица — это его собственный Проект/Цель из мастера и авто-«Сон»
текущего дня, а не остаток демо-данных.

**Тихий контракт 0.3:** `progressBars=0`, `svgIcons=0`, счётчика «шаг N из M» нет,
эмодзи нет, `boxShadow: none`, `borderRadius: 0`. Мобильный 390×780: обе кнопки в
вьюпорте, горизонтального скролла нет (0 px), обе достижимы кликом.

### Смежные наблюдения (не чинил — чужой объём)

Оба расхождения заведены как баги по правилу `docs/agents/issue-tracker.md`
(«Баги в resolved-тикетах»):

1. **Баг `bugs/01-first-run-wizard-missing-ui.md`** — у мастера 0.4-08 был только API, экрана не существовало.

2. **Баг `bugs/02-today-norm-remainder-not-rendered.md`** — остаток дневной нормы (0.4-07): API считает
   (`remainingMinutes: 90` при норме 12 ч), «Сегодня» не рисует. Поэтому проверка
   «Сегодня показывает остаток нормы» подтверждена косвенно: норма 12 ч сохранена
   и видна в Настройках. Не чинил — чисто фронтендовая работа вне объёма 04.

Не баги, а особенности прогона тестов:

3. **`DemoProfileLoadIT.timeEntriesAreRelativeToToday` падает по времени суток.**

4. **Прогон нескольких IT-классов сразу даёт ложные падения.** `GoalApiIT` +
   `DeloApiIT` вместе — 3 падения `CannotCreateTransactionException` (общий
