# Экран «Загрузка профиля»

Status: open
Blocked by: 01

## Question

Реализовать первый экран после регистрации по инвайту — выбор одного из трёх демо-профилей.

## Что сделать

1. Новый компонент `ProfileLoadView.vue`, маршрут `/onboarding/profile`.
2. Заголовок «Загрузка профиля», подзаголовок «Посмотри, как можно использовать WOLF. Выбери пункт, чтобы загрузить демо-конфигурацию».
3. Три карточки-варианта — Рабочий класс, Мудрый фрилансер, Свободный художник — каждая с коротким описанием (2–3 предложения, тон «с характером», см. `## Тон содержания` тикета «Содержание трёх демо-профилей» карты 05-07). Визуальный контракт тихого регистра 0.3 — без ярких карточек с тенями.
4. Клик по карточке → `POST /api/v1/onboarding/load-profile` (тикет 01) → редирект на `/onboarding/tour` (тикет 03).
5. Guard в `main.js`: аутентифицирован + `onboardingCompletedAt == null` + маршрут не начинается с `/onboarding` → редирект на `/onboarding/profile` (было — на `/onboarding` мастера 0.4-08 напрямую; теперь мастер вызывается только с ветки «Очистить», см. тикет 04).

## Testing Decisions

- Регистрация по инвайту → редирект строго на `/onboarding/profile`, не на старый `/onboarding`.
- Клик по каждой из трёх карточек → соответствующий профиль загружен (проверка через API `GET /api/v1/projects` после загрузки — непустой список с ожидаемыми именами проекта).
- Гейт: сборка → пересоздание контейнера → сверка хэшей с `web/dist` → аутентификация в браузере → инспекция DOM.

## Out of Scope

Сама генерация данных (тикет 01). Тур (тикет 03).
