# 02: Во времени уделённому проекту — сумма времён его подпроектов (roll-up)

**What to build:** В агрегации Гантта для родительского проекта плановые/фактические/ожидаемые
часы (`plan`/`fact`/`pending` по неделям) и `totalPlanHours` показываются как **собственные
проекта плюс сумма всех его подпроектов** (рекурсивно). То есть часы времени «спускаются вверх»
по дереву проектов при отображении, без изменения того, как Дела приписываются проектам.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**Где сейчас (факты):**
- `api/src/main/java/ru/wolf/api/gantt/GanttService.java`: `computeHours` строит
  `fact`/`pending` map по `project×ISO-week` из Записей времени через `DeloProject`
  (уважает `user.getHourAccountingMode()` — primary / все прикреплённые). `buildProjectRows` →
  `walkTree` строит `ProjectRow` с `cells[]` (`planHours`/`factHours`/`pendingHours`).
- `ProjectRow` уже несёт `totalPlanHours` (собственное поле) и `depth`/`parentId`, но
  **не содержит** roll-up: ячейки считаются только для самого проекта.
- Режим учёта часов (`CONTEXT.md`): «считать часы Записи времени только в Основной проект Дела
  (default) либо полностью в каждый прикреплённый Проект».

**Решение (зафиксировано):** Roll-up **суммирует уже посчитанные** Ганттом часы узлов
поддерева. Атрибуцию Дел не меняем — двойного счёта сверх семантики режима учёта нет (каждое Дело
уже учтено в тех проектах, к которым привязано). Для узла-родителя:
`rollup.cell = собственное cell + Σ cell детей` (по каждой неделе), и
`rollup.totalPlanHours = собственное + Σ totalPlanHours детей`. Это честно для обоих режимов.

**Что сделать:**
- [ ] В `GanttService` после построения `rows` (в `buildProjectRows`/`walkTree`) вычислить
      roll-up: пройти дерево снизу вверх, для каждого родителя прибавить к его `cells[]` и
      `totalPlanHours` значения прямых детей. Реализовать отдельным методом, чтобы не смешивать
      с базовой агрегацией.
- [ ] Убедиться, что roll-up не дублирует часы внутри одного узла: суммируем итоги **детей**, а
      не пересчитываем Дела родителя (собственные часы родителя остаются как есть, добавляется
      только спуск от потомков).
- [ ] Проверить взаимодействие с фильтрами Гантта (`onlyWithDates`, `lifeAreaIds`):
      `expandWithAncestors` сохраняет предков — roll-up должен считаться по **видимому**
      поддереву (по уже отобранным `rows`), иначе сумма «уедет» от того, что показано.
- [ ] Покрыть юнит- или IT-тестом (`GanttApiIT` или `GanttServiceTest`): дерево
      Корень(собств. 2ч) → Потомок(3ч) → Лист(5ч); ожидать у Корня plan/fact =
      собственные + 3 + 5 (с учётом режима учёта по умолчанию primary).
- [ ] `npm run build` + сборка API зелёные; существующий Гантт не сломан (визуальная приёмка:
      у родителя часы больше, чем у любого ребёнка по отдельности).

**Проверочный факт (приёмка):** в Гантте у родительского проекта в каждой неделе
`plan`/`fact`/`pending` равны сумме по всему поддереву; `totalPlanHours` = сумма
`totalPlanHours` поддерева. Листовые проекты без детей не меняются.
