Glossary: `CONTEXT.md`
Относится к релизу: 1.4 (выделено из «импорта Расписания» по решению владельца — отдельная

## Problem Statement

Владелец просит четыре доработки по иерархии проектов и дорожным картам:

1. Иерархия проектов должна быть видна в **Бэклоге** и **Утреннем обходе**.
2. Во времени уделённому проекту учитывается **сумма времён его подпроектов** (roll-up).
3. У каждого **родительского проекта** — своя **дорожная карта**.
4. Во всех дорожных картах — **строка внизу** с суммой всех трудочасов.

## Current state (проверено в коде, не на веру)

- **Домен уже поддерживает вложенность.** `Project.parent` (JPA `@ManyToOne`, колонка
  `parent_id`); `CONTEXT.md`: «Проект … может содержать вложенные проекты (подпроекты — тот же
  тип). Проект верхнего уровня (без родителя) — корневой проект». `Трудоёмкость` =
  `totalPlanHours` (плановые часы на весь срок).
- **Утренний обход уже рендерит иерархию.** `MorningDigestService.buildProjectTree` отдаёт
  плоский pre-order список `ProjectDigest` с `parentId`/`depth`; `MorningView.vue` рисует
  отступы (`marginLeft: depth*20`) и сворачивание (`expanded`/`toggle`/`isVisible`). То есть
  пункт 1 для Утреннего обхода **уже выполнен** — тикет 01 его закрепляет и добавляет приёмку.
- **Гантт строит дерево.** `GanttService.buildProjectRows` → `walkTree` (recursive, `depth`),
  `expandWithAncestors` сохраняет предков при фильтрах; `ProjectRow` несёт `parentId`,
  `depth`, `totalPlanHours` и `cells[]` (`planHours`/`factHours`/`pendingHours` по неделям).
  `GanttView.vue` рендерит `depth` + маркер `└`.
- **Бэклог — плоский.** `WeekView.vue` → `groupBacklogWithNorm` и `BacklogView.vue` →
  `groupByProject` (`web/src/backlogGroups.js`) возвращают список групп **без** `parentId`/
  `depth`; иерархия проектов в Бэклоге не отображается. Это основной объём пункта 1.
- **Roll-up времён подпроектов отсутствует.** `GanttService.computeHours` считает `fact`/
  `pending` по Делам **самого** проекта (через `DeloProject`), не по поддереву; `totalPlanHours`
  — собственное поле проекта, не сумма потомков.
- **«Своей дорожной карты» у проекта нет.** `ProjectDetailView.vue` показывает `children`
  (фильтр по `parentId`), но отдельной карты поддерева не существует; «Дорожная карта» = общий
  Гантт всех проектов (`/gantt` → `GanttView`).
- **Итоговой строки в Гантте нет** — ни суммы `totalPlanHours`, ни суммы по неделям.

## Решения владельца (wow-пункты)

| # | Пункт | Куда ложится |
|---|-------|--------------|
| 1 | Иерархия видна в Бэклоге и Утреннем обходе | тикет 01 |
| 2 | Уделённому проекту — сумма времён подпроектов | тикет 02 |
| 3 | У родительского проекта — своя дорожная карта | тикет 03 |
| 4 | Во всех дорожных картах — строка суммы трудочасов внизу | тикет 04 |

## Решения по реализации (зафиксированы, чтобы не додумывать)

- **Roll-up (тикет 02) не меняет атрибуцию Дел и уважает «Режим учёта часов».** Часы Дела
  приписываются проектам ровно по текущей логике Гантта (primary / все прикреплённые). Roll-up
  лишь **суммирует уже посчитанные** `plan`/`fact`/`pending` узлов поддерева. Двойного счёта
  сверх семантики режима учёта нет: каждое Дело уже учтено в тех проектах, к которым привязано.
- **Дорожная карта проекта (тикет 03)** — переиспользование Гантта с фильтром по корню
  поддерева (`GET /gantt?rootId={id}` → сам проект + все потомки), без дублирования логики
  построения дерева. Не новая сущность, а вид существующего Гантта.
- **Итоговая строка (тикет 04)** считается на стороне фронта из уже полученных `rows`
  (сумма `totalPlanHours` + по каждой неделе сумма `plan`/`fact`/`pending`), чтобы не плодить
  отдельный эндпоинт.

## Ticket graph

```
01 Иерархия в Бэклоге (плоский → дерево) + закрепить в Утреннем обходе        [независим]
02 Roll-up времён подпроектов в агрегации Гантта                             [независим]
03 Своя дорожная карта у родительского проекта                       [нужны 01, 02]
04 Строка-итог (сумма трудочасов) во всех дорожных картах            [нужны 02, 03]
```

Порядок: **01 и 02** независимы и могут идти параллельно; **03** опирается на дерево (01) и на
roll-up (02), чтобы в карте проекта тоже показывать суммарные часы; **04** — финальный слой
поверх Гантта (02) и карты проекта (03).

## Out of Scope

- Переход на рекурсивную 「трудоёмкость = сумма потомков」 в самом поле `totalPlanHours`
  (БД). Тикет 02 суммирует только для отображения; собственное поле проекта не трогаем.
- Изменение «Режима учёта часов» (primary/all) — не входит; roll-up его уважает.
- Множественные корни в одной карте проекта — карта строится от одного родителя.
