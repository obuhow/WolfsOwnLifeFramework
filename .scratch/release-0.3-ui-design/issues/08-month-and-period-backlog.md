## Answer

Оба маршрута перестали быть каркасами и работают на **существующих API** (`GET /calendar/month`, `GET /backlog?scope=&period=`, `POST /backlog/{id}/move-to-week`, `GET /gantt`), поэтому блокировка «ждём функциональные тикеты 0.2» снята — новая бэкенд-логика не понадобилась.

**Общий слой.** Логика группировки, вынесенная ранее в три экрана, выделена в `backlogGroups.js` (`groupByProject`, `groupHoursLabel`, `fetchProjectWeekHours`, `mondayOf`, `isoWeekId`) и презентационный компонент `BacklogGroups.vue`. Правило отсутствующего плана — `—`, никогда `0` — теперь живёт в одном месте.

**Календарь → Месяц** (`CalendarView.vue` переписан): сетка 7 колонок × 5–6 недель на реальной агрегации, дни вне месяца приглушены, текущий день помечен graphite-подчёркиванием, в ячейке — до трёх компактных подписей `время + Дело` и «ещё N». Месяц — **обзор, а не редактор слотов**: клик по дню уводит в недельный реестр, никаких мутаций. Справа две панели — «Бэклог недели» и «Бэклог месяца», обе через общий групповой реестр с `x / y ч` из Gantt-агрегата. Сетка в подписанном горизонтальном scroll-регионе; на ≤900px панели уходят под сетку.

**Планирование → Бэклог** (`BacklogView.vue`): реальный переключатель охвата «Неделя»/«Месяц» (с `aria-pressed`, запоминается в localStorage), навигация по периодам ←/Текущий/→, подпись периода (ISO-неделя с датами или месяц), группировка по Проектам и **явное действие «Перенести в неделю»** — только для месячного охвата и только по клику пользователя; автоматического раскладывания по слотам нет. Перенесённые элементы помечаются «перенесено в …».

Маршрут `/calendar/month` теперь редиректит в `/calendar?view=month` (единый компонент вместо дубля), `/planning/backlog` подключён к `BacklogView`.

Проверка: `npm run build` OK; `docker compose build web` + пересоздание контейнера; served-хэши совпадают с `web/dist` (`index-DsU76Eqz.js` / `index-DzanJUdt.css`); маркеры `Перенести в неделю`, `Бэклог месяца`, `move-to-week`, `Обзор месяца`, `Охват бэклога` подтверждены в бандле. Функциональный API-smoke под логином admin — см. отметку выше; ключевой инвариант «просмотр не создаёт TimeEntry» проверен фактически, а не декларативно.
