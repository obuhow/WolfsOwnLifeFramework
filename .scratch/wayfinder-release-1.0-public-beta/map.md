# WOLF 1.0 — Закрытая бета на публичном домене — Wayfinder Map

## Destination

**5 сентября 2026** на публичном домене владельца работает WOLF 1.0, куда **5–10 лично приглашённых** предпринимателей и фрилансеров заходят по инвайт-кодам и ведут свои Дела, Проекты и время, не видя данных друг друга. Корень домена — **лендинг**, объясняющий, что это; приложение живёт по отдельному адресу. Каждый приглашённый получил **сценарий первой недели** и попал в общий Telegram-канал обратной связи. Готовы два дека: **онбординг для пользователей** и **WOLF как кейс агентной разработки**.

Карта пройдена, когда: (а) публичный контур безопасен для чужих данных (HTTPS, нет наружу торчащей БД, нет дефолтных секретов, есть бэкап); (б) регистрация по инвайту и изоляция арендатора проверены в бою на реальном втором аккаунте; (в) корень домена отдаёт лендинг, приложение доступно и не сломано; (г) сценарий первой недели и оба дека существуют как файлы в репозитории; (д) пройдена приёмка go/no-go.

Это override правила «планируй, не делай» (как в карте 0.9): тикеты этой карты **выполняют работу** — правят конфиги, пишут страницы и деки, — а не только описывают решение.

## Notes

- **Домен**: персональная Life OS, RU-интерфейс. Стек: Java 21 + Spring Boot 3.4, Vue 3, Postgres, JWT, Docker Compose. Слоган: «Уютно. Тихо. Под вашим контролем».
- **Навыки каждой сессии**: `wolf-life-os`; для лендинга и деков — `claude-design` / `sketch`; при спорных терминах — `domain-modeling`. Тексты на русском, термины — строго по `CONTEXT.md`.
- **Трекер**: локальный markdown (`docs/agents/issue-tracker.md`).
- **Предшествующие карты**: `.scratch/wayfinder-release-0.9-layered-arch/map.md` (слоистая архитектура), `.scratch/wayfinder-releases-05-07/map.md` (0.5–0.7), `.scratch/wayfinder-wolf/wolf-life-os-map.md` (0.1–0.2).

### Жёсткий срок и что из него следует

Чертёж составлен **27 августа 2026**, старт — **5 сентября 2026**. Окно — **9 дней**, и оно делится с картой 0.9. Это не карта «сделать хорошо», это карта «дойти до старта». Практические следствия:

- Всё, что не блокирует вход первого чужого человека, уходит в **Out of scope**, а не «сделаем если успеем».
- Тикеты 01, 02, 07, 09 не блокируются ничем и берутся параллельно **прямо сейчас**.
- Если 3 сентября что-то не готово — режется скоуп, а не сдвигается дата: решение принимается на тикете 11 (приёмка go/no-go).

### Внешняя зависимость: карта 0.9

Владелец решил, что **0.9 (слоистая архитектура) должна быть добита до старта**. Открыты тикеты 03–11, в работе 03 (ветка `release-0.9/feature/03-planning-priorities`, есть незакоммиченные правки). Темп 26 августа — два кластера за день, так что 03–11 реалистичны за 3–5 дней агентными сессиями, но это **половина окна**.

0.9 не является тикетом этой карты и не блокирует её тикеты формально: лендинг, деки и инструкция пишутся параллельно рефакторингу и не касаются кода API. Единственная точка встречи — тикет 11 (приёмка), где 0.9 обязана быть закрыта. **Риск номер один этой карты**: если 0.9 поедет, режется она, а не старт — HTTP-контракт от рефакторинга не меняется, значит для пользователя разницы нет.

### Отправная точка (замер на момент чертежа)

- **Мультиаккаунтность уже есть** с релиза 0.4 и её не надо строить заново: `User` с ролью (`USER`/`ADMIN`) и статусом (`ACTIVE`/`BLOCKED`), аудит tenant-изоляции, first-run мастер (Проект → Цель → недельная норма). Demo Sandbox был отменён — гость получает настоящий постоянный аккаунт.
- **Инвайты полны по модели**: `InviteCode` с `maxUses`, `expiresAt`, `revokedAt`, `note`; `InviteService.createInvite/registerWithInvite`, админский экран выпуска кодов, `V37__invite_code.sql`. Владелец подтвердил: доработок не нужно, нужна **боевая проверка**.
- **Релиз 0.6** дал демо-профили, тур онбординга, AGPL-3.0, версию в шапке.
- **Лендинга нет.** В `docs-site/` только документация (`index.html`) и `roadmap.html`, отдаются отдельным контейнером `wolf-docs` через `/docs/`. README заявляет `v0.5 / alpha`.
- **Корень занят приложением**: `web/nginx.conf` — `location / { try_files $uri $uri/ /index.html; }`. Лендинг на корне требует переадресации SPA, а не просто нового файла.
- **Публичный контур не подготовлен к чужим данным**: `docker-compose.yml` пробрасывает Postgres наружу (`5434:5432`) с паролем `wolf/wolf/wolf`, HTTPS в compose отсутствует, JWT-секрет и пароли БД — в открытом виде.
- **SMTP нет и не будет в 1.0**: забытый пароль сбрасывает владелец вручную через админку (решено при чертеже, см. Out of scope).

### Решения, принятые при чертеже (не тикеты)

- **Модель размещения**: один публичный инстанс на VPS владельца, закрытая бета по инвайтам. Self-hosted-раздача образов — не в этом релизе.
- **Первая волна**: 5–10 знакомых предпринимателей/фрилансеров, приглашение личное, обратная связь личная.
- **Работа лендинга**: рассказать о продукте и увести на вход. Ни формы заявки, ни ввода инвайт-кода на лендинге — коды владелец раздаёт лично.
- **Обратная связь**: общий чат в Telegram + личные созвоны. Кнопку «Обратная связь» внутри WOLF не строим.
- **Инструкция тестерам** — это **сценарий первой недели** (день 1, день 2, дни 3–7), доводящий человека до ценности, а не QA-чеклист. Тестеры — не QA-инженеры, ловля багов — побочный продукт нормальной работы.
- **Артефакты живут в репозитории**: лендинг — HTML, деки — HTML/Markdown. Ни PPTX, ни внешних конструкторов.
- **Восстановление пароля** — ручное, силами владельца через админку.

## Not yet specified

- **Что делать с версией и README**: сейчас заявлено `v0.5 / alpha`, а стартуем как 1.0 при незакрытой 0.9. Нужно ли отдельное решение о версионировании и тексте README, или это механическая правка внутри тикета приёмки — прояснится к 11-му тикету.
- **Судьба демо-профилей из 0.6 в боевой бете**: приглашённый заводит настоящий аккаунт — предлагать ли ему при первом входе загрузить демо-профиль «посмотреть, как выглядит заполненная система», или это мешает завести своё. Решится внутри сценария первой недели (тикет 07).
- **Нагрузка и предел инстанса**: 5–10 человек на одном VPS — вопрос почти наверняка праздный, но замер после 3–4 живых аккаунтов может изменить требования к машине. Смотрим по факту, до старта не чертим.
- **Что показывать в шапке про стадию беты** (баннер «закрытая бета», версия, ссылка на канал) — мелочь, но всплывёт при вёрстке лендинга и первого входа.

## Out of scope

- **SMTP, письма, восстановление пароля по e-mail** — решено при чертеже: сброс вручную через админку. Возвращается, когда пользователей станет больше десятка.
- **Открытая регистрация, форма «запросить доступ», waitlist** — вход только по инвайту, розданному лично.
- **Раздача self-hosted-образов, публикация в реестрах, инструкция по установке себе** — модель размещения на 1.0 одна: инстанс владельца.
- **Кнопка «Обратная связь» / баг-трекер внутри продукта** — обратная связь идёт в Telegram.
- **Биллинг, тарифы, платные планы** — закрытая бета бесплатна, денежный вопрос не поднимается.
- **Мобильное приложение и адаптив сверх минимума** — лендинг обязан читаться с телефона, само приложение остаётся десктопным.
- **Доработка инвайтов** (персональные коды, ссылка-инвайт вместо кода, e-mail-рассылка кодов) — владелец подтвердил, что текущей модели достаточно.
- **Аналитика, метрики продукта, трекеры посещений** — противоречит слогану «Под вашим контролем» и не нужно на десяти знакомых.
- **Остаток карты 0.9 сверх тикетов 03–11** и любые новые архитектурные улучшения — 1.0 не расширяет 0.9.
