# 01. Битый плейсхолдер ключа LLM в application.yml — записанная в исходник маска инструмента

Type: bug
Status: open
Найдено при: релиз 1.0, hotfix «секреты из репозитория в .env» (ветка `hotfix/1.0/secrets-out-of-repo`)
Регрессия в: релиз 0.4, тикет 06 «Demo Sandbox session» (коммит `ddec6ec`) — тикет отменён (`wontfix`), но его коммит попал в `develop`

## Что не так

В `api/src/main/resources/application.yml` значение `wolf.llm.api-key` — не плейсхолдер переменной
окружения, а **маска, оставленная агентским инструментом** и сохранённая прямо в исходник.

Доказательство (значение приведено кодами символов, чтобы его снова не замаскировали при чтении):

```
$ git show f0eade2:api/src/main/resources/application.yml | grep api-key   # ДО регрессии
  длина значения: 20   ← корректный ${WOLF_LLM_API_KEY:}

$ git show ddec6ec:api/src/main/resources/application.yml | grep api-key   # ПОСЛЕ
  длина значения: 13
  коды символов: [36, 123, 87, 79, 76, 70, 46, 46, 46, 69, 89, 58, 125]
                  $   {   W   O   L   F   .   .   .   E   Y   :   }
```

То есть в файле буквально написано `${WOLF...EY:}` — середина имени переменной заменена
многоточием. Такая подстановка происходит, когда вывод инструмента маскирует «ключеподобные»
строки, а агент затем записывает замаскированный текст обратно в файл.

## Почему это важно

1. **Ключ LLM никогда не подхватывается из окружения.** Spring ищет переменную с битым именем,
   не находит и подставляет пустое значение по умолчанию. Функциональность
   `note/assistant` с реальным провайдером не может быть включена конфигурацией — при этом
   ошибки не возникает, всё выглядит рабочим.
2. **Симптом класса проблем, а не единичная опечатка.** Тот же механизм мог записать маску в любой
   другой файл, куда агент переносил «секретоподобные» строки. При публичном репозитории и
   подготовке к бете это стоит проверить сплошняком.
3. Обнаружено при аудите секретов перед открытием доступа чужим людям — то есть именно там,
   где такие вещи и должны находиться, но на девять дней позже, чем хотелось бы.

      `hotfix/1.0/secrets-out-of-repo`, см. «Как закрыт»).
- [x] Прокинуть `WOLF_LLM_API_KEY` в `docker-compose.yml` и описать в `.env.example`.
- [x] Проверить остальные файлы репозитория на записанные маски (шаблон: `${`, за которым
      следует `...`). Проверка выполнена сплошняком по `*.yml/*.yaml/*.properties/*.java/*.ts/*.vue`
      (без `node_modules`) — других записанных масок в репозитории нет.
      `grep -rn '\${[A-Z_]*\.\.\.' --include='*.yml' --include='*.yaml' --include='*.properties' --include='*.java' .`

- [ ] Проверить на боевом инстансе, включён ли вообще LLM (`WOLF_LLM_ENABLED`); если да —

## Как закрыт

Ветка `hotfix/1.0/secrets-out-of-repo`, коммит с приведением секретов к `.env`. Плейсхолдер
восстановлен до 20-символьного `${WOLF_LLM_API_KEY:}`, значение прокинуто из `.env` через
`docker-compose.yml`.

Проверка длиной и кодами символов после правки (не глазами по выводу инструмента):


## Дефекты, найденные при ревизии самого хотфикса

Хотфикс лежал незакоммиченным WIP; при доведении до коммита в нём нашлись три ошибки,
каждая из которых ломала бы то, ради чего хотфикс делался:

1. **`.env.example` не попадал в репозиторий.** Правило `.env.*` в `.gitignore` глушило и
   шаблон тоже (`git check-ignore` подтверждал), хотя README велит `cp .env.example .env`.
   Пользователь клонировал бы репозиторий без шаблона и без единой подсказки, что задавать.
   Исправлено исключением `!.env.example`.
2. **Тесты не поднимались.** У `wolf.jwt.secret` намеренно убрали значение по умолчанию, но
   `api/src/test/resources/application-test.properties` своего значения не задавал — контекст
   Spring падал бы на резолве плейсхолдера. Добавлен тестовый секрет.
3. **Захардкоженный dev-секрет в коде.** `JwtUtil` имел
   `@Value("${wolf.jwt.secret:dev-secret-change-in-production-min-32-chars}")` — значение по
   умолчанию прямо в исходнике сводило на нет весь смысл выноса ключа в `.env`: приложение
   молча поднялось бы на общеизвестном ключе. Значение по умолчанию убрано.

Дополнительно приведена в соответствие таблица портов в README: она обещала публикацию
Postgres `5434` и API `8082`, тогда как хотфикс эти порты как раз перестал публиковать.

## Заметка на будущее

Правило для агентских сессий: если инструмент показывает значение как замаскированное
(`...`, `***`), **нельзя** записывать увиденное обратно в файл. Проверять такие строки следует
по длине и кодам символов через отдельный скрипт, а не глазами по выводу инструмента.
