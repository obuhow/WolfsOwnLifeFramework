## Problem Statement

Пользователь живёт многоветочной жизнью (музыка, QA Java, спорт, фриланс, здоровье) с историей депрессии и волнообразной продуктивностью. Классические таск-трекеры и Pomodoro **вызывают вину и торможение**, а не помогают. Реальные паттерны входа в работу — **дрейф и возврат**, **воронка разогрева** (YouTube → лёгкий контакт → LLM-подсказки → основная работа), **смена контекста** (дом → Школа 21 → библиотека), **поток важнее расписания**.

Release 0.1 дал календарную сетку и Гантт, но не отвечает на вопросы: **"что мне сейчас делать, если не идёт?"**, **"как этот новый проект повлияет на остальную жизнь?"**, **"когда реально закончу QA при текущем темпе?"**, **"на чём я вчера остановился в Spring Security?"**. Нет слоя **смыслов**: целей, синергии, банка идей, LLM Wiki, честного прогноза по Gantt.

Отдельная проблема — **сама механика ввода факта**. Раскладка по 15-мин ячейкам хороша, когда день заранее нарезан, но в режиме потока (вошёл в работу — работаю, пока идёт) она превращается в ретроспективное заполнение таблицы. Нужен второй способ фиксации: **одно Главное дело + чек-лист переключений**, где переключение на другое Дело отмечается галочкой в момент, а не правкой сетки. Плюс не хватает **горизонта месяца** (недельная сетка не отвечает на "как выглядит август целиком"), **дневного чек-листа первоочередного** и **суммарной плановой нагрузки** на Гантте: сейчас видно часы по одному проекту, но не видно, что сумма планов всех проектов вдвое превышает реальные 30 ч/нед.

## Solution

Собрать **WOLF 0.2 — Methodology Layer**: смысловой слой поверх календаря, который:

- Хранит **Цели** с недельными бюджетами часов и метриками (вес, доход, проекты, готовность трека)
- Связывает **Проекты и Идеи** со **Сферами жизни** через **Синергию** (позитивное/негативное влияние)
- Даёт **Банк Идей** — инкубатор для "ещё не проектов" с категориями (бизнес / музыкальные / личные / криповые)
- Хранит **Заметки** к Проектам и Делам (голос/текст) как основу **LLM Wiki**
- Поддерживает **Утренний обход** — экран всех проектов с последними заметками и подложками от **фонового агента** (без пушей, без напоминаний)
- Считает **честный прогноз** на Гантте: план/факт, зависимости между проектами, месячная корректировка, каскад ресурсов (сдвиг одной цели → пересчёт остальных)
- Импортирует **xlsx-таблицы** текущего учёта времени (апрель 2026 → сейчас) с распознаванием активностей и статусом "Неизвестно" для пустых ячеек
- Даёт два **Режима фиксации времени**: «Фокус» (Главное дело + чек-лист переключений) и «Параллельные слоты» (управление 15-мин ячейками, поведение 0.1)
- Разворачивает календарь до **месячного вида** (Outlook-раскладка) с боковой панелью **Бэклога недели и месяца**
- Добавляет на **Сегодня** блок Бэклога недели с часами **x/y** (уделено / планируется) и **Чек-лист дня** первоочередного, плюс **Отчёт «Чек-лист»**
- Превращает Гантт в страницу **Планирование**: плановые часы у каждого Проекта, равномерное распределение по дням/будням, **суммарная плановая нагрузка** (капасити) под диаграммой

**Ключевой принцип UX:** система **не принуждает, не напоминает, не оценивает**. Она фиксирует факт, показывает честный прогноз, подкладывает материал на страницы проектов — и молчит. Никаких красных бейджей, никаких "вы пропустили", никаких стриков.

## User Stories

### Цели и бюджеты

1. As a Пользователь, I want to define Цели с метриками (вес, доход, количество проектов, готовность трека), so that прогресс измерим, а не абстрактен.
2. As a Пользователь, I want to set недельный бюджет часов на каждую Цель, so that неделя — единица учёта, а не день.
3. As a Пользователь, I want to see фактические часы за неделю по каждой Цели, агрегированные из Записей времени, so that я вижу реальность без ручного подсчёта.
4. As a Пользователь, I want to adjust недельный бюджет под реальность без штрафов и предупреждений, so that план корректируется под меня, а не наоборот.
5. As a Пользователь, I want to prioritize Цели (доход > вес > ISTQB/Java > трек), so that при конфликте слотов видно, что важнее.

### Сферы жизни и Синергия

6. As a Пользователь, I want a справочник Сфер жизни (Здоровье, Навык QA Java, Навык музыканта, Общение на расстоянии, Мотивация к делам, Ресурсы/деньги, Ресурсы/время, Открытие новых ходов, Независимость), so that все аспекты жизни учтены.
7. As a Пользователь, I want to link Проект к Сферам жизни с оценкой влияния (+/−), so that видно, что он усиливает и что ослабляет.
8. As a Пользователь, I want to link Идею к Сферам жизни, so that решение "брать/не брать" видно до старта.
9. As a Пользователь, I want to see Синергию проекта при его создании/редактировании, so that новые инициативы не рушат баланс незаметно.

### Банк Идей

10. As a Пользователь, I want to save Идею в Банк Идей с категорией (бизнес / музыкальная / личная / криповая), so that "ещё не проекты" не теряются.
11. As a Пользователь, I want to describe Идею текстом и синергией, so that через полгода вспомню, зачем она.
12. As a Пользователь, I want to promote Идею в Проект одним действием, so that переход "раздумываю → делаю" мгновенный.
13. As a Пользователь, I want Банк Идей to surface периодически на Утреннем обходе, so that старые идеи не пылятся.

### Заметки и LLM Wiki

14. As a Пользователь, I want to attach Заметку к Проекту текстом или голосом (аудио → транскрипт), so that мысль фиксируется в моменте.
15. As a Пользователь, I want to attach Заметку к Делу, so that "что делал на тренировке" сохраняется.
16. As a Пользователь, I want to ask "на чём я остановился в проекте X?", so that LLM собирает последние заметки в сводку.
17. As a Пользователь, I want to search Заметки по теме ("все решения по Spring Security"), so that дневник решений находим.
18. As a Пользователь, I want Заметки to group по темам автоматически (Spring, танцы, ISTQB), so that личная wiki растёт без ручной сортировки. _(пост-MVP, см. Out of Scope)_

### Фоновый агент (без пушей)

19. As a Пользователь, I want фоновый агент to scan мои проекты и молча класть на страницу проекта находки (ролики, статьи с Хабра, факты), so that утром я нахожу их сам при обходе.
20. As a Пользователь, I want никаких уведомлений от агента, so that система не давит.
21. As a Пользователь, I want to see записи агента отдельным стилем от моих заметок, so that понятно, кто автор.

### Утренний обход

22. As a Пользователь, I want an экран Утренний обход: список всех активных Проектов с последними заметками и подложками агента, so that один взгляд = полная картина.
23. As a Пользователь, I want to see очередь Дел в каждом Проекте при обходе, so that "что дальше" видно сразу.

### Gantt: зависимости и честный прогноз

24. As a Пользователь, I want to set зависимости между Проектами (A блокирует B), so that сдвиг одного виден на других.
25. As a Пользователь, I want to see честный прогноз окончания Проекта на основе текущего темпа (факт часов за N недель), so that Gantt отвечает "когда реально", а не "когда обещал".
26. As a Пользователь, I want to корректировать план раз в месяц, so that не пересчитывать каждый день от тревоги.
27. As a Пользователь, I want каскадный пересчёт ресурсов: сдвиг одной Цели → предложение пересмотреть остальные, so that план остаётся сбалансированным.

### Импорт xlsx

28. As a Пользователь, I want to upload xlsx-файл (лист = неделя, ячейка = 15 мин активности), so that история с апреля 2026 входит в систему.
29. As a Пользователь, I want активности to map на Проекты/Дела по словарю, so that "Работа над WOLF" → проект WOLF автоматически.
30. As a Пользователь, I want to be спрошен при неизвестной активности, so that словарь пополняется в процессе.
31. As a Пользователь, I want пустые ячейки → статус "Неизвестно", so that пропуски честны, а не выдуманы.

### Режимы фиксации времени

35. As a Пользователь, I want to выбрать Режим фиксации времени (Фокус / Параллельные слоты), so that способ ввода факта соответствует тому, как я работаю сегодня, а не наоборот.
36. As a Пользователь, I want в режиме Фокус назначить одно Главное дело на интервал, so that не нужно раскладывать поток по ячейкам заранее.
37. As a Пользователь, I want отмечать переключение на другое Дело одним тапом в чек-листе сессии, so that контроль/ревью соседних проектов фиксируется в момент и без чувства нарушения.
38. As a Пользователь, I want чтобы отметка переключения не ломала сетку и не переписывала часы автоматически, so that факт остаётся честным, а разбор — за мной.
38a. As a Пользователь, I want позже (по желанию) разобрать переключения в часы по Делам, so that часы по каждому Проекту честные, но ввод минут не требуется в момент работы.

### Календарь: неделя и месяц

39. As a Пользователь, I want страницу «Календарь» вместо «Недели», so that название соответствует тому, что там теперь два горизонта.
40. As a Пользователь, I want месячный вид (дни недели по горизонтали, недели по вертикали, дела в ячейке дня), so that видно форму месяца целиком.
41. As a Пользователь, I want боковую панель с Бэклогом недели, а в месячном виде — ещё и с Бэклогом месяца, so that намерение периода лежит рядом с сеткой.

### Сегодня: бэклог и чек-лист

42. As a Пользователь, I want на «Сегодня» видеть Бэклог недели с часами x/y, so that за один взгляд понятно, сколько уделено против запланированного.
43. As a Пользователь, I want вести Чек-лист дня из первоочередных дел и ставить галочки, so that есть лёгкий список намерения, не требующий планирования слотов.
44. As a Пользователь, I want Отчёт «Чек-лист» за период, so that видно фактическую картину дней и переключений без оценок и стриков.

### Планирование

45. As a Пользователь, I want страницу «Планирование» вместо «Диаграммы Ганта» с плановыми часами рядом с названием Проекта, so that объём работы виден сразу в списке.
46. As a Пользователь, I want при заведении Проекта равномерно распределить его часы по дням или по будням, so that план появляется одним действием, а не ручной раскладкой по неделям.
47. As a Пользователь, I want видеть суммарную плановую нагрузку по неделям против доступных часов, so that перегрузка видна до старта, а не по факту провала.

### Общие принципы UX

32. As a Пользователь, I want систему без напоминаний, будильников, pomodoro-таймеров, красных бейджей, so that нет чувства вины.
33. As a Пользователь, I want to видеть "волну продуктивности" (медленный старт → разгон → пауза) как норму в статистике, so that не сравниваю себя с линейным идеалом.
34. As a Пользователь, I want honest fact-tracking: система фиксирует то, что было, без попыток "подтолкнуть", so that я доверяю данным.

## Implementation Decisions

### Architecture & stack

- Наследует Release 0.1: Spring Boot 3 API + Vue 3 SPA + PostgreSQL + JWT + Docker Compose.
- Новые модули добавляются к существующему монолиту, микросервисов нет.
- LLM — **внутренний порт** `NotesAssistant` (interface), реализация: HTTP-клиент к внешнему LLM API (xAI Grok / fallback). В тестах — fake-реализация с заготовленными ответами. **Никакой очереди событий в 0.2.**

### Primary modules (новые к 0.1)

- **Goals** — Цели, метрики, недельные бюджеты, приоритеты, фактические часы (агрегация из Записей времени).
- **Life Areas** — расширение: Справочник Сфер жизни (отдельная сущность от Области жизни в 0.1 — это разные вещи: Область жизни — для Проектов, Сфера жизни — для Синергии).
- **Synergy** — связь (Проект | Идея) × Сфера жизни × влияние (+1 / −1 / 0).
- **Ideas Bank** — Идеи: категория, описание, синергия, статус (в банке / в работе / архив), промоушн в Проект.
- **Notes** — Заметки: текст / аудио-ссылка / транскрипт, привязка к (Проект | Дело), автор (user | agent), теги-темы.
- **Agent** — фоновая задача (`@Scheduled`): сканирует Проекты, генерирует подложки через `NotesAssistant`, пишет как Заметки с `author=agent`. Никаких уведомлений.
- **Morning Digest** — query: все активные Проекты + последние N Заметок каждого + очередь Дел.
- **Gantt Forecast** — зависимости между Проектами, честный прогноз (скользящее среднее фактических часов), месячная корректировка, каскад ресурсов.
- **XLSX Import** — парсер недельной сетки 15-мин ячеек, словарь маппинга активностей → Дела/Проекты, интерактивный режим (вопрос при неизвестной активности), статус "Неизвестно" для пустых ячеек.
- **Time Capture** — Режим фиксации времени (`parallel_slots` | `primary_focus`), Фокус-сессии, Отметки переключений, материализация сессии в Записи времени, добровольный Разбор переключений в часы по Делам.
- **Calendar Views** — переименование «Неделя» → «Календарь», месячная агрегация (Outlook-раскладка), боковая панель бэклогов.
- **Backlog (period)** — обобщение Бэклога недели до Бэклога периода (`week` | `month`) с плановыми часами элемента.
- **Today Board** — блок Бэклога недели с x/y и Чек-лист дня; **Checklist Report** — история чек-листов и переключений за период.
- **Planning** — переименование Гантта в «Планирование», плановые часы в левой колонке, равномерное распределение по дням/будням, суммарная плановая нагрузка (капасити).

### Domain rules to encode

- **Цель** ≠ Проект: Цель — верхнеуровневый вектор (6 мес), Проект — конкретная инициатива внутри. Проект может служить нескольким Целям (редко), Цель имеет несколько Проектов.
- **Сфера жизни** ≠ Область жизни: Область жизни (0.1) — дом для Проектов, Сфера жизни (0.2) — ось Синергии. Связь: у Проекта есть Область жизни (0.1) и Синергия со Сферами (0.2) — независимые измерения.
- **Идея** — не Проект: статус "в банке", нет Дел, нет Записей времени. Промоушн в Проект = создание Проекта + перенос описания/синергии + статус Идеи "в работе".
- **Заметка** принадлежит ровно одному (Проект | Дело). Автор: user или agent. Аудио хранится как файл (S3-compatible или локальный volume), транскрипт — текст.
- **Честный прогноз** = скользящее среднее фактических часов за последние 4 недели × оставшиеся часы по плану. Не корректируется вручную, только пересчётом.
- **Месячная корректировка**: Gantt показывает "план" (заморожен на месяц) и "прогноз" (пересчитывается еженедельно от факта). Разница видна, но не сигнализирует.
- **Каскад ресурсов**: при ручной корректировке срока Проекта система показывает, какие Цели/Проекты пострадают (недельные бюджеты суммарно > доступных часов). Пользователь сам решает, что резать.
- **Статус "Неизвестно"** для пустых ячеек xlsx-импорта — отдельный статус Записи времени, не путается с "неопределено" (пустая ячейка UI).
- **Словарь маппинга активностей** — per-user таблица: текст из xlsx → (Дело | Проект). Пополняется интерактивно при импорте и вручную через настройки.
- **Режим фиксации времени ≠ Режим учёта часов.** Первый (0.2) — *как пользователь вводит факт*: `parallel_slots` (15-мин ячейки, 0.1) или `primary_focus` (Главное дело + чек-лист переключений). Второй (0.1) — *как часы Записи разносятся по Проектам*: `primary_only` / `all_projects`. Настройки независимы и действуют одновременно.
- **Фокус-сессия** — интервал с одним Главным делом. На пользователя не более одной открытой сессии. При закрытии материализуется в Записи времени статуса «выполнена».
- **Алгоритм материализации (обязателен к точному соблюдению — модель 0.1 хранит непрерывные интервалы и склеивает соседние одинаковые):** нормализовать границы сессии до 15 мин → найти занятые слоты диапазона → вычесть их → получить максимальные непрерывные свободные отрезки → создать по одной Записи на отрезок. **Отрезки, разделённые занятым слотом, не склеиваются**, даже если Дело и статус совпадают; склейка допустима только с непосредственно примыкающей Записью того же Дела и статуса. Пересечение — не ошибка (200, чужие Записи не трогаются), пропущенные ячейки возвращаются в `skippedCells`.
- **Отметка переключения** — событие внутри Фокус-сессии (Дело либо свободный текст, время, опционально минуты). Сама по себе **не создаёт Запись времени и не занимает ячейку**; инвариант 0.1 «не более одной Записи в ячейке» сохраняется.
- **Разбор переключений** — отдельный **добровольный** шаг (после сессии или в конце дня), в котором отметки превращаются в часы на соответствующие Дела по тому же алгоритму материализации. Разделение на «фиксацию в один тап» и «разбор потом» — сознательное: пользователю нужны часы по Проектам, но требовать ввода минут в момент переключения значит убить сам режим Фокуса. Отсутствие разбора ничего не ломает и нигде не подсвечивается.
- **Бэклог периода** — обобщение Бэклога недели: `scope` (`week` | `month`) + `period_id`. Бэклог месяца — намерение на месяц, не разложенное по неделям; переход в неделю — явное действие пользователя, автоматической раскладки нет.
- **Бэклог — миграция, а не параллельная таблица.** У старой недельной структуры есть писатель помимо экрана недели: импорт (CSV в текущей ветке, XLSX в тикете 11) с опцией «добавить в бэклог». Переезд считается выполненным только когда переведены **все** писатели и читатели, а старые таблицы удалены в том же PR. Два источника правды запрещены — иначе импорт отчитается «добавлено», а экран покажет пусто.
- **Пункт Чек-листа дня ≠ Дело и ≠ Запись времени** — лёгкий список первоочередного на дату, без часов и без разноса по Проектам. Невыполненные пункты не переносятся автоматически.
- **x/y в Бэклоге недели**: `x` — сумма Записей времени «выполнена» по Делу за ISO-неделю, `y` — плановые часы элемента бэклога. Если `y` не задан — показывается «—», а не «0» (отсутствие плана ≠ нулевой план).
- **Равномерное распределение** (`even_all_days` | `even_weekdays`) — генератор строк «План на неделю» (0.1) из плановых часов и дат Проекта, с округлением дневной доли до 15 мин и остатком в последний день. **Записи времени генератор не создаёт** — план не выдаёт себя за факт.
- **Суммарная плановая нагрузка (капасити)** — сумма плановых часов всех активных Проектов по ISO-неделям против `available_weekly_hours` пользователя. Отображение, не блокировка: превышение показывается нейтральной дельтой.

### API shape (дополнения к 0.1)

- `POST/GET /api/v1/goals` — CRUD Целей, недельные бюджеты, метрики.
- `GET /api/v1/goals/{id}/fact?week=2026-W30` — фактические часы за неделю.
- `POST/GET /api/v1/life-spheres` — справочник Сфер жизни.
- `POST/GET /api/v1/synergies` — связи (projectId | ideaId) × sphereId × impact.
- `POST/GET /api/v1/ideas` — Банк Идей. `POST /api/v1/ideas/{id}/promote` — перевод в Проект.
- `POST/GET /api/v1/notes` — Заметки. `GET /api/v1/projects/{id}/notes?author=agent` — подложки агента.
- `GET /api/v1/morning-digest` — Утренний обход (проекты + последние заметки + очередь Дел).
- `POST /api/v1/projects/{id}/dependencies` — зависимости. `GET /api/v1/gantt/forecast` — честный прогноз.
- `POST /api/v1/import/xlsx` — импорт xlsx (multipart). `POST /api/v1/import/xlsx/{id}/resolve` — ответы на вопросы о неизвестных активностях.
- `POST /api/v1/admin/agent/run` — ручной триггер фонового агента (для тестов и отладки).
- `GET/PUT /api/v1/settings/time-capture-mode` — Режим фиксации времени.
- `POST /api/v1/focus/start`, `POST /api/v1/focus/{id}/stop`, `GET /api/v1/focus/current`, `POST/DELETE /api/v1/focus/{id}/distractions` — Фокус-сессии и отметки переключений.
- `GET /api/v1/focus/{id}/review`, `POST /api/v1/focus/{id}/review/preview|apply|revert` — добровольный разбор переключений в часы.
- `GET /api/v1/calendar/month?month=YYYY-MM` — месячная агрегация Календаря.
- `GET/POST/PATCH/DELETE /api/v1/backlog?scope=week|month&period=...`, `POST /api/v1/backlog/{id}/move-to-week` — Бэклог периода.
- `GET /api/v1/today/backlog?date=` — Бэклог недели с x/y. `GET/POST/PATCH/DELETE /api/v1/checklist?date=`, `POST /api/v1/checklist/{id}/carry-over` — Чек-лист дня.
- `GET /api/v1/reports/checklist?from=&to=`, `GET /api/v1/reports/checklist/export?format=md|csv` — Отчёт «Чек-лист».
- `POST /api/v1/projects/{id}/plan-distribution {mode}` — равномерное распределение. `GET /api/v1/planning/capacity?from=&to=` — суммарная плановая нагрузка.

## Testing Decisions

### What good tests are

- Через HTTP API + реальный Postgres (Testcontainers).
- Используют глоссарий (Цель, Сфера жизни, Идея, Заметка, Синергия).
- Сценарные: отражают user stories (недельный бюджет, промоушн Идеи, каскад ресурсов, xlsx-импорт с неизвестными).

### What is tested (0.2)

- Goals: CRUD, недельный бюджет, фактические часы (агрегация из Записей времени с Режимом учёта из 0.1).
- Life Spheres + Synergy: CRUD, влияние +/−, отображение при создании Проекта/Идеи.
- Ideas Bank: CRUD, категории, промоушн в Проект (перенос описания и синергии).
- Notes: CRUD, привязка к Проекту/Делу, фильтр по автору (user/agent), поиск по тексту.
- Agent: принудительный запуск, создание Заметки с `author=agent` (fake LLM).
- Morning Digest: состав ответа (проекты + заметки + очередь Дел).
- Gantt Forecast: зависимости, честный прогноз от скользящего среднего, месячная корректировка, каскад ресурсов.
- XLSX Import: парсинг недельной сетки, маппинг активностей по словарю, вопросы при неизвестных, статус "Неизвестно" для пустых ячеек.
- Time Capture: материализация Фокус-сессии в Записи времени **с пересечениями** (занятые слоты пропускаются, соседние куски не склеиваются, чужие Записи не перезаписываются), инвариант одной открытой сессии, отметки переключений не трогают ячейки, `parallel_slots` не ломает поведение 0.1.
- Switch Review: preview не меняет данные, apply переносит часы кратно 15 мин, повторный apply не дублирует, revert возвращает часы Главному делу.
- Calendar: месячная агрегация по дням, стык месяцев, пустой месяц.
- Backlog: миграция старых недельных бэклогов (включая путь импорта), `scope=week|month`, перенос из месяца в неделю, запрет дублей в периоде.
- Today: x/y (факт по ISO-неделе vs план элемента), CRUD и carry-over Чек-листа дня.
- Checklist Report: агрегаты по дням и периоду, дни без данных, экспорт.
- Planning: распределение по дням/будням (суммы сходятся до минуты), капасити vs `available_weekly_hours`, идемпотентность повторного распределения.

## Out of Scope

- **Очередь событий / message broker** (RabbitMQ, Kafka) — внутренний порт достаточен для 0.2.
- **Автогруппировка заметок по темам** (LLM-кластеризация) — в 0.2 только ручные теги.
- **Рефлексия по неделям** (LLM-выводы из заметок) — накопится база сначала.
- **Голосовой ввод в UI** — в 0.2 только API для транскрипта (аудио загружается файлом).
- **Multi-user, opensource-упаковка** — ADR-0001.
- **OAuth live calendar sync** — ADR-0003.
- **Push/email уведомления** — принципиально никогда (см. Further Notes).
- **AI-генерация Дел или Проектов** — агент только подкладывает материал, не создаёт сущности.
- **Drag-n-drop переносы Записей времени в месячном виде** — месяц в 0.2 только для обзора и перехода в неделю (время не выдумываем).
- **Автоматическое вычитание переключений из часов Главного дела** — перенос часов только через явный Разбор (тикет 19), никогда молча.
- **Авто-перенос невыполненных пунктов Чек-листа на завтра** — только ручная кнопка (принцип «не подталкивает»).
- **Неравномерные профили распределения** (front-load, по выходным, с учётом Ночных часов) — в 0.2 только `even_all_days` и `even_weekdays`.
- **Жёсткая блокировка при превышении капасити** — капасити только показывает дельту, ничего не запрещает.

## Further Notes

- **Принцип "тихой системы"**: WOLF никогда не уведомляет, не напоминает, не оценивает. Это не баг, а фича. UX-копирайтинг: никаких "вы пропустили", "пора", "не забудьте". Только факты и прогнозы.
- **Волна продуктивности** — норма: статистика должна показывать "медленный старт → разгон → пауза" как паттерн, не как отклонение. Никаких стриков, никаких "потерянных дней".
- **Серые техники легальны**: воронка разогрева (YouTube → лёгкий контакт → LLM-подсказки → работа) — штатный режим. Заметки могут содержать "подсмотрел у LLM, переписал руками" — это валидная запись.
- **Словарь маппинга активностей** — личный артефакт пользователя, экспортируется вместе с данными.
- **Терминология**: "Дело" (0.1) — не "задача", не "таска". "Сфера жизни" (0.2) — не "Область жизни" (0.1). Различие критично: Область жизни — дом Проектов, Сфера жизни — ось Синергии.
- **Идеи могут быть криповыми** — категория "криповые" не фильтруется и не модерируется (личное пространство).
- **Честный прогноз** — ключевая метрика продукта: пользователь должен видеть "когда реально закончу при текущем темпе", а не "когда обещал". Это снижает тревогу, а не повышает.
- **Месячная корректировка** — защита от тревожного пересчитывания: план заморожен на месяц, прогноз пересчитывается от факта. Разница видна, но не сигнализирует.
- **Коллизия имён (критично)**: в 0.1 уже есть «Режим учёта часов» (primary_only / all_projects). Новая настройка называется **«Режим фиксации времени»** (Фокус / Параллельные слоты) — другая ось. Одинаковые слова в UI и коде запрещены: `time_capture_mode` vs `hours_attribution_mode`.
- **«Главное дело» ≠ «Основной проект Дела»** (0.1). Первое — Дело, выбранное на текущий интервал; второе — Проект, помеченный основным среди прикреплённых к Делу.
- **Переименования страниц** («Неделя» → «Календарь», «Диаграмма Ганта» → «Планирование») — не косметика: они фиксируют расширение горизонта (неделя+месяц) и смену смысла (не «диаграмма», а «место, где раскладывается объём работ»). Тикеты 14 и 18 меняют роуты, меню, заголовки и тексты целиком.
- **Порядок реализации новых тикетов**: 13 и 14 независимы и стартуют сразу; 15 после 14; 16 после 15; 17 после 04, 13 и 16; 18 после 09 и 10; 19 после 13.
- **По итогам внешнего аудита (принято)**: (1) арифметика прогноза в тестах 09 исправлена — остаток делится на темп, добавлен clamp при перевыполнении; (2) алгоритм материализации Фокус-сессии описан пошагово, потому что модель 0.1 интервальная и склеивающая; (3) бэклог переезжает миграцией с переводом импорта и удалением старых таблиц; (4) тикет 17 зависит от 04, иначе кнопка «Сохранить как Заметку» упирается в отсутствующую модель.
- **Почему разбор переключений вынесен в отдельный тикет 19**: портрет пользователя требует и честных часов по каждому Проекту, и отсутствия принуждения. Ввод минут в момент переключения — принуждение. Разбор потом, добровольно, с равноправной кнопкой «оставить как есть» — компромисс, при котором ни одна из двух потребностей не приносится в жертву.
- **Тикет 18 трогает страницу тикета 09** — если оба идут параллельно, 09 мержится первым (переименование ложится поверх дорожек «план/прогноз»).
