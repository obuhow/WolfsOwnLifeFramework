# 13 — Режим фиксации времени: Фокус-сессия (главное дело + чек-лист переключений) vs Параллельные слоты

**What to build:** Настройка Пользователя **Режим фиксации времени** (`time_capture_mode`): `parallel_slots` (default — поведение 0.1: ручное управление 15-мин ячейками, подходит когда реально идёт работа над двумя проектами с переключением каждые 15–60 мин) и `primary_focus` (одно **Главное дело** на интервал + чек-лист переключений — подходит когда один проект основной, а остальные только контролируются/ревьюятся). В режиме `primary_focus` пользователь стартует Фокус-сессию на одном Деле; когда переключается на другое (ревью чужой задачи, агент дособрал результат) — ставит **Отметку переключения** в чек-листе сессии, не разрывая сессию и не редактируя сетку. По завершении сессия материализуется в Записи времени 0.1 (статус «выполнена») на свободные 15-мин ячейки Главного дела.

**Терминология:** «Режим фиксации времени» ≠ «Режим учёта часов» (0.1). Первый — **как пользователь вводит факт** (фокус vs слоты), второй — **как часы уже готовой Записи разносятся по Проектам**, если Дело привязано к нескольким (`primary_only` / `all_projects`). Оба существуют одновременно и независимо.

**Отметка переключения** сама по себе часов не двигает: она фиксирует «в 10:20 ушёл на ревью B». Превращение отметок в часы по Проектам — **отдельный добровольный шаг** (тикет 19), чтобы момент фиксации оставался в один тап и без бухгалтерии.

**Blocked by:** None — can start immediately (расширяет 0.1).

**Status:** ready-for-agent

## Настройка и сессии

- [ ] Настройка `user_settings.time_capture_mode` enum (`parallel_slots` default | `primary_focus`)
- [ ] `GET/PUT /api/v1/settings/time-capture-mode` — переключение не мигрирует и не удаляет прошлые данные, доступно в любой момент дня
- [ ] Таблица `focus_session` (id, user_id, delo_id, started_at, ended_at NULL, note)
- [ ] Инвариант: не более одной открытой Фокус-сессии на пользователя → повторный старт при открытой = 409
- [ ] `POST /api/v1/focus/start {deloId, startedAt?}`, `POST /api/v1/focus/{id}/stop {endedAt?}`, `GET /api/v1/focus/current`
- [ ] Забытая открытая сессия: при старте новой предлагается закрыть предыдущую временем последней активности; авто-обрезания «за нарушение» нет, время правится вручную
- [ ] Таблица `focus_distraction` (id, focus_session_id, delo_id NULL, text NULL, at, minutes NULL)
- [ ] `POST /api/v1/focus/{id}/distractions {deloId | text, at?, minutes?}` — отметка (все поля кроме одного из deloId/text опциональны), `DELETE` — снятие
- [ ] Отметка переключения **не** создаёт Запись времени и **не** занимает ячейку в рамках этого тикета
- [ ] Режим `parallel_slots`: focus-endpoints → 409 `TIME_CAPTURE_MODE_MISMATCH`, поведение 0.1 неизменно

## Материализация сессии в Записи времени (пересечения)

Модель 0.1 хранит **непрерывные интервалы** и склеивает соседние одинаковые — поэтому алгоритм закрытия сессии описан явно, чтобы не было трёх разных реализаций.

- [ ] Нормализация: `start` вниз до границы 15 мин, `end` вверх до границы 15 мин
- [ ] Запрос занятых 15-мин слотов пользователя в диапазоне (любая существующая Запись времени, любой статус)
- [ ] Вычитание занятых слотов → набор **максимальных непрерывных свободных отрезков**
- [ ] На каждый свободный отрезок — **одна** Запись времени «выполнена» на Главное дело
- [ ] **Запрет склейки через пропущенный слот**: отрезки, разделённые занятым слотом, остаются отдельными Записями, даже если Дело одно и статус один
- [ ] Склейка допустима только с непосредственно **примыкающей** существующей Записью того же Дела и того же статуса (правило 0.1 сохраняется)
- [ ] Пересечение — **не ошибка**: ответ 200, существующие Записи не перезаписываются и не сдвигаются
- [ ] Ответ `stop`: `{materialized: [{startAt, endAt}], skippedCells: ["2026-08-15T10:15:00"], sessionMinutes}`
- [ ] Диапазон занят полностью → 200, `materialized: []`, полный `skippedCells`, сессия сохранена как факт
- [ ] Сессия короче 15 мин → Записи не создаются, `materialized: []`, сессия сохраняется; в UI нейтральный текст («короткая сессия — записана как есть»), без «слишком мало»
