# Контракт разбора заметки в сущности WOLF

Type: grilling
Status: resolved
Blocked by:

## Question

Что именно бот извлекает из свободного текста, и где проходит граница между «однозначно» и «нужно подтверждение»?

## Answer

### Граница «однозначно / требует подтверждения»

**Правило: подтверждения требует всё, кроме самого факта «здесь есть Дело».** Бот определяет, что текст описывает активность, которую нужно создать как сущность — это единственное, что пишется без спроса. Всё остальное (название, длительность, время, тип, связанные Проекты) идёт в карточку предпросмотра на подтверждение. Это не ослабляет принцип «WOLF не додумывает» — додумывание существует только внутри одной предложенной карточки, ничего не попадает в БД без явного принятия пользователем.

### Пример А — разбор

- Факт «это Дело» — создаётся черновик карточки, не пишется в БД.
- Название «Тренировка в спортзале» — додумано, показано в карточке, редактируемо.
- Длительность 1 час — додумана по общему правилу (см. ниже), редактируема.
- «Эллипс 15:00 1.03» рядом с «17:00» — распознаётся как содержание тренировки (15 минут, 1.03 — доп. параметр), попадает в описание слота, а не в время начала. Показывается в карточке как есть, без отдельного подтверждения формата — но карточка позволяет поправить весь текст описания.

### Правило длительности

**«Час, если не указано иное» — общее правило для всех Дел**, не только тренировок. Бот не использует контекст типа активности, чтобы выбрать другую длительность по умолчанию — это внесло бы скрытую логику вне карточки.

### Год без указания в дате

**Подставляется ближайшее прошедшее** относительно текущей даты. Если сегодня 23 августа, а в заметке «22 августа» без года — это 22 августа текущего года (только что было). Если бы дата была «22 декабря» при сегодня 23 августа, это тоже был бы ближайший прошедший (прошлого года ещё нет смысла — здесь работает базовое «прошедшее ближе, чем будущее»); точное правило: дата в пределах последних 300 дней от сегодня трактуется как прошедшая, иначе уточняется у пользователя через карточку (год — редактируемое поле).

### Пример Б — горизонт повторения

**«На год вперёд» — часть правила повторения**, не техническое ограничение бота. Правило `RecurrenceService` создаётся с явной датой окончания (сегодня + 365 дней), а не как бесконечное. Совпадает с моделью `RecurrenceService`, которая уже поддерживает конечные правила.

### Что бот создаёт помимо Дел

**Всё, что может быть извлечено**: Дела, Проекты, Рутины, слоты расписания — без ограничения только Делами. Прямое следствие: если пользователь пишет «Начал проект ремонта кухни, бюджет 200 часов» — бот предлагает создать Проект (с Областью жизни, если удаётся определить/предположить — додумывание тоже в карточке). Это расширяет полномочия бота относительно XLSX-импортёра (который никогда не создаёт Проект/Область автоматически) — осознанно: бот работает в диалоге с подтверждением на каждом шаге, импортёр работает пакетно без него, отсюда разная степень доверия.

### Формат подтверждения (чат-панель)

**Карточка предпросмотра с редактируемыми полями.** Каждое додуманное поле показано и может быть исправлено до принятия. Кнопки: Принять / Отклонить. Редактирование — inline в полях карточки, не отдельный диалог.

### Занятый слот времени

Предлагается выбор из четырёх действий:
- **Заменить** существующую запись
- **Сдвинуть** новую запись на ближайшее свободное время
- **Создать поверх** — параллельный слот (WOLF это уже поддерживает через `PARALLEL_SLOTS`)
- **Отменить разбор** — не создавать ничего

### Провал разбора

Если текст не удаётся разобрать вообще (ни одной сущности не распознано), он **сохраняется как обычная Заметка в Личной базе знаний**. Пользователь ничего не теряет, бот не задаёт уточняющих вопросов и не молчит без следа.

### Несколько сущностей в одном сообщении

**Одно подтверждение на всё сообщение** — карточка со списком всех распознанных сущностей (например, пять активностей за день), пользователь принимает или отклоняет пакетно. Отдельного подтверждения на каждую сущность нет (иначе многострочная заметка о дне превращается в пять последовательных диалогов).

### Отмена после записи

Не поднято отдельным вопросом в этом раунде — оставлено в Not yet specified карты для тикета 10 (архитектура бота), так как зависит от того, как хранится история диалога.

### Формулировка принципа

«WOLF не додумывает» переформулируется как: **WOLF никогда не пишет в БД додуманное значение без явного акта подтверждения пользователем.** Импортёр XLSX и AI-бот оба подчиняются этому принципу, но по-разному: импортёр отклоняет неоднозначные строки целиком (нет диалога), бот показывает додуманное в карточке и ждёт принятия (диалог есть). Это не исключение из принципа, а два способа его соблюдения при разной форме взаимодействия.

## Итоговая таблица «случай → обработка»

| Случай | Обработка |
|---|---|
| Факт, что текст описывает Дело/Проект/Рутину/слот | Создаётся черновик карточки без подтверждения |
| Название сущности не указано в тексте | Додумывается, показывается в карточке, редактируемо |
| Длительность не указана | Час по умолчанию (общее правило для всех Дел), редактируемо |
| Дата без года | Ближайшее прошедшее (эвристика 300 дней), редактируемо |
| Горизонт повторения не указан явно | По умолчанию год (365 дней), редактируемо |
| Слот времени занят | Выбор: Заменить / Сдвинуть / Создать поверх / Отменить |
| Текст не разобрался | Сохраняется как Заметка в Личной базе знаний |
| Несколько сущностей в сообщении | Одна карточка со списком, одно подтверждение |
| Проект без явной Области жизни | Область додумывается/предлагается в карточке, редактируема |

Готово к использованию в тикете 10 (архитектура бота) и спецификации 0.7.
