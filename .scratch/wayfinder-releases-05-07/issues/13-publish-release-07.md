# Опубликовать релиз 0.7 — AI-импорт записей

Type: task
Status: resolved
Blocked by: 02, 09, 10

## Question

Написать `.scratch/release-0.7-ai-import/spec.md` и завести его тикеты.

## Answer

Опубликован `.scratch/release-0.7-ai-import/spec.md` (`ready-for-agent`) + 4 тикета вертикальных срезов, в порядке приоритета каналов:

- `01-import-parser-service.md` — общий `ImportParserService`, таблица уверенности (правило «час по умолчанию», подстановка года, горизонт повторения ≤ `RecurrenceService.MAX_HORIZON_WEEKS`), structured output + одна повторная попытка при невалидном JSON.
- `02-chat-panel-channel.md` — канал чат-панели, карточка предпросмотра, три варианта разрешения занятого слота.
- `03-telegram-channel.md` — `TelegramLink`, deep-link связывание, webhook-изоляция, `daily-limit-per-user`.
- `04-max-channel.md` — `MaxLink` по аналогии с Telegram, общий счётчик лимита между каналами.

Переформулированный принцип «WOLF не додумывает» зафиксирован явно в `## Implementation Decisions` spec.md: для файлового импорта (XLSX/CSV) действует без изменений (WOLF валидирует целиком извне подготовленный файл); для бота — додумывание ограничено таблицей уверенности на уровне поля, всегда явное и предъявляемое пользователю до записи, не тихое.

Повторяющиеся Дела — явный пункт Out of Scope запрещает материализацию 52 записей; используется существующий `RecurrenceService`. Тесты по всем четырём сценариям (оба примера-фикстуры, занятый слот, невалидный ответ модели, попытка записи в чужой аккаунт через канал) заданы в Testing Decisions spec.md и продублированы в тикетах 01/03.

Тихий контракт — «бот не инициирует диалог» зафиксирован явным пунктом Out of Scope в spec.md и повторён в тикетах 03 и 04.

Канал Max: research дал положительный вердикт (публичное bot API существует) — канал остался в скоупе релиза, реализуется тикетом 04, третьим по приоритету после чат-панели и Telegram, а не вынесен в Out of Scope.

Лимит LLM-расхода на гостей — числовой параметр `wolf.import-bot.daily-limit-per-user` в конфигурации (не в коде), общий на пользователя между каналами.
