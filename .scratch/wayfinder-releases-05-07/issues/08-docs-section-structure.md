# Раздел Документация: структура и Сценарии использования

Type: grilling
Status: resolved
Blocked by: 04, 07

## Question

Как устроен раздел `/docs` внутри приложения, и что в нём лежит кроме Манифеста?

## Answer

### Соотношение с `docs-site`

**Оба существуют параллельно.** `docs-site/` (отдельный статический сайт) остаётся как публичная витрина для тех, кто ещё не получил инвайт — маркетинговая точка входа. Внутри приложения `/docs` — своя копия содержимого для авторизованных пользователей, встроенная в интерфейс, без ухода со стенда. Содержимое не обязано быть побайтово идентичным (разная аудитория, разный контекст), но методология (Манифест) — одна и та же по сути.

### Формат хранения

**Захардкоженные Vue-компоненты.** Не markdown-файлы, не записи в БД. Раздел версионируется вместе с кодом фронтенда, правки требуют пересборки — это осознанный выбор в пользу единообразия вёрстки (типографика, оглавление, якоря) над гибкостью редактирования без деплоя.

### Сценарии использования

**= демо-профили как текст.** Сценарии — это истории трёх персонажей (наёмный работник / фрилансер / художник) из тикета 05, пишутся **вместе** с ним, чтобы не расходиться: профиль — данные, сценарий — текстовое повествование о том же персонаже. Отдельного контента про рабочие приёмы («как я планирую неделю») в Сценариях нет — эта информация, если нужна, живёт в Манифесте (Реализация с примером) или отдельно не специфицируется в этой карте.

### Технические инструкции

**Только про самохостинг.** docker compose, требования к серверу, шаги развёртывания у себя — прямое продолжение выводов research-тикета 01 (правовая модель и минимальный дистрибутив). Инструкции по работе с системой (импорт XLSX, настройка времени) в этот раздел не входят — они либо остаются встроенными подсказками в соответствующих экранах, либо не специфицируются здесь.

### Разделение аудиторий

Разрешено явно: Манифест и Сценарии — для методологической аудитории (гость, оценивающий подход), Технические инструкции — для другой аудитории (тот, кто решил развернуть у себя). Оба живут в одном пункте меню «Документация» с тремя подпунктами — раздел общий, читатели разные, это не проблема, а осознанная структура.

### Доступность без входа

**`/docs` виден неаутентифицированному посетителю.** Продаёт методологию до получения инвайта — это отдельный вход в мир WOLF помимо `docs-site`, либо `docs-site` и есть публичный рендер того же `/docs` (техническая реализация уточняется в тикете 11 при публикации спецификации 0.5; продуктовое решение — публичный доступ есть).

### Навигация внутри раздела

**Оглавление + якорные ссылки внутри каждой страницы.** Не три голые плоские страницы, не полноценный поиск. Оглавление слева или сверху, якоря ведут на разделы длинного текста (актуально для Технических инструкций).

### Визуальный контракт для длинного текста

**Узкая колонка (~680–720px)**, типографика тихого регистра 0.3: графитовые чернила, тонкие нейтральные линейки, без акцентных цветов, без карточек с тенями. Заголовки — стандартная иерархия h1/h2/h3 без декоративных элементов. Цитаты и код (для Техинструкций) оформляются в рамках того же тихого контракта — без ярких фонов подсветки синтаксиса.

### Язык

**Только русский.** Английский дубль для opensource-перспективы не делается на этом этапе.

## Итоговая структура раздела `/docs`

| Подпункт | Содержимое | Формат | Публичный доступ |
|---|---|---|---|
| Манифест WOLF | 5 из 6 пунктов Манифеста (см. тикет 07) | Vue-компонент, узкая колонка | Да |
| Сценарии использования | Истории трёх персонажей = текстовая версия демо-профилей (тикет 05) | Vue-компонент, оглавление + якоря | Да |
| Технические инструкции | Самохостинг: docker compose, требования, шаги (по выводам тикета 01) | Vue-компонент, узкая колонка, код-блоки | Да |

Готово к использованию в тикете 11 (публикация релиза 0.5).
