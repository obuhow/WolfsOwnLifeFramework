WOLF — это **персональный фреймворк управления жизнью** с открытым исходным кодом. Одно тёплое
место, где работа, здоровье, семья, деньги и отдых живут вместе, а не разбросаны по десятку
приложений. Данные хранятся **у вас** — на личном сервере или VPS, под вашим полным контролем.

> Проект создан для тех, кто сам строит свой день: предпринимателей, фрилансеров, художников
> и инженеров. Никаких корпоративных «рабочих пространств», подписок и телеметрии — только ваша
> жизнь, оцифрованная на ваших условиях.

## Питч проекта

**Проблема.** У предпринимателя, фрилансера, художника или инженера жизнь не делится на
«рабочие задачи» и «личное». Время, проекты, здоровье, семья и деньги переплетены — но
существующие инструменты либо корпоративные (Jira, Monday), либо узкие (календарь, трекер
привычек), либо замкнуты в чужом облаке с подпиской и слежкой.

**Решение.** WOLF — это **ваш собственный фреймворк**: вы self-hostите его на своём сервере,
а он даёт единый язык для описания жизни — от 15-минутной ячейки календаря до многолетнего
проекта и сферы жизни. Поверх данных работают лёгкие AI-ассистенты, которые **не требуют
привязки к конкретной модели**: подключайте Grok, Claude, GPT или локальную модель на свой
выбор.

**Почему open source и self-hosted.** Ваши данные о жизни — самое интимное, что есть у
человека. WOLF не продаёт их, не анализирует и не держит в чужом облаке: код открыт под
AGPL-3.0, развёртывание — на вашем железе, экспорт/импорт — в обычный XLSX.

| **Инженер** | Чистая слоистая архитектура, package-by-feature, DTO-как-records, порты и адаптеры, Testcontainers-покрытие — приятно читать и расширять. |

## Архитектурные принципы

WOLF спроектирован вокруг пяти принципов, зафиксированных в [ADR](docs/adr/).

1. **Персональные данные — одному пользователю** ([ADR-0001](docs/adr/0001-personal-single-user-data.md)).
   Каждая область жизни, проект, дело и запись времени принадлежат ровно одному владельцу. Нет
   общих workspace, семейного шаринга или кросс-юзерного назначения — пространство данных
   изолировано per-user.

2. **Self-hosted, данные под контролем пользователя.** Развёртывание — Docker Compose на
   личном сервере/VPS. База PostgreSQL целиком у вас; резервное копирование и восстановление —
   через версионированный XLSX-воркбук с предпросмотром и применением
   ([ADR-0004](docs/adr/0004-data-synchronization-backup-restore.md)).

3. **LLM-независимость.** AI-ассистенты (заметки + агент) общаются с моделью через порт
   `AssistantPort`; реализация выбирается профилем (`HttpNotesAssistantAdapter` вне тестов,
   `FakeNotesAssistantAdapter` в тестах). Можно подключить Grok, Claude, GPT или локальную
   модель — без изменения бизнес-логики.

4. **Слоистая архитектура: тонкий MVCS + точечные порты и адаптеры**
   ([ADR-0005](docs/adr/0005-layered-architecture-mcv.md)). Контроллер — только HTTP
   (маршрутизация, `@Valid`, маппинг в DTO, `ResponseEntity`), **не инжектит Repository**.
   Сервис несёт бизнес-логику и `@Transactional`, резолвит пользователя по
   `authentication.getName()`. DTO — Java **records** с ручным фабричным маппингом
   (`XxxResponse.from(entity)`). Существующие сфокусированные сервисы не поглощаются, а
   становятся зависимостями новых тонких сервисов фичи.

5. **Единый язык домена.** Глоссарий в [`CONTEXT.md`](CONTEXT.md) — единственный источник
   истины по терминам (Дело, Запись времени, Область жизни, Проект, Фокус-сессия…),
   чтобы модель, UI и документация говорили на одном языке.

## Чем WOLF полезен

- **Целостная картина жизни.** Работа, здоровье, семья, деньги и отдых — в одной системе,
  сгруппированы по Областям жизни, а не по разрозненным приложениям.
- **Честный учёт времени.** 15-минутная сетка календаря + записи времени со статусами
  (неопределено / запланировано / выполнено). Два режима фиксации: «параллельные слоты» и
  «фокус» с одним главным делом и отметками переключения.
- **Планирование без принуждения.** Дорожная карта (Гантт) с плановыми часами проектов и
  Планом нагрузки — показывает дельту план/факт, ничего не блокируя.
- **Лёгкий вход и миграция.** Импорт дел и проектов из CSV/XLSX (Apache POI), готовые
  демо-профили (`worker-class`, `wise-freelancer`, `free-artist`), экспорт/восстановление
  данных в XLSX.
- **AI-помощь по вашему выбору.** Ассистент по заметкам и агент запуска задач работают поверх
  подключаемой LLM — данные не уходят к вендору без вашего решения.
- **Ваш контроль = ваша приватность.** AGPL-3.0, self-hosted, без телеметрии и подписок.

## Сценарии использования

**Утро предпринимателя.** Вход открывает «Утренний обход» (`/morning`) — точка сбора дня:
что запланировано, что важно, где перегруз. Один экран вместо пяти вкладок.

**День фрилансера.** В «Ежедневнике» (`/calendar`, `/today`) — 15-минутная сетка. Режим
«Фокус» фиксирует одно главное дело и отметки переключения одним тапом; в конце дня —
разбор переключений в часы по делам. Вечером — Гантт и План нагрузки показывают, хватает ли
часов на проекты недели.

**Процесс художника.** Дела создаются ad-hoc без проекта (валидная рутина/личное), группируются
по Сферам жизни и Компетенциям (`/competency`, вкладка «Синергия») — без корпоративных тегов и
эпиков. Ночные часы автоматически подставляют «Сон», скрывая сетку в спокойное время.

**Неделя инженера.** Бэклог недели и месяца — отдельные «корзины» намерений, явно раскладываемые
по записям времени. Повторяющиеся правила (дни недели + окно) создают будущие записи на
ограниченный горизонт. Код системы читаем и расширяем благодаря слоистой архитектуре.

## Быстрый старт

Соберите артефакты на хосте, затем соберите runtime-образы и запустите Compose:

```bash
# 1. API (bootJar)
cd api && ./gradlew bootJar --no-daemon && cd ..

# 2. Web (сборка в dist/)
cd web && npm ci && npm run build && cd ..

# 3. Образы и запуск
docker compose build api web
docker compose up -d --no-build
```

Production-workflow собирает образы на VPS внутри Docker: на удалённом хосте не нужны Java,
Gradle, Node.js или npm — только Docker Compose и доступ к базовым образам. Развёртывание
автоматизировано через GitHub Actions (`.github/workflows/deploy.yml`, push в `main`).

После запуска:

- UI: http://localhost
- API: http://localhost:8082
- Health: http://localhost:8082/api/v1/health
- Документация: http://localhost:8090
- Postgres: `localhost:5434`, db/user/pass — `wolf` / `wolf` / `wolf`

## Статус и дорожная карта

`develop` (релиз 0.9 — миграция API на слоистую архитектуру завершена, тикеты 01–11).
