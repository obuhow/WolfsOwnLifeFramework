# Ручные тест-кейсы WOLF Release 0.2

Набор ручных тестов для проверки тикетов релиза **0.2 — Methodology Layer**.

## Область проверки

- Источник требований: [`../.scratch/release-0.2/spec.md`](../.scratch/release-0.2/spec.md).
- Тикеты: `01–22` из [`../.scratch/release-0.2/issues/`](../.scratch/release-0.2/issues/).
- Формат: тематические Markdown-файлы; тест-кейсы имеют идентификаторы `TC-0.2-<ticket>-NN`.
- Тесты рассчитаны на ручной прогон через UI. Если для сценария нужен административный или отсутствующий в UI endpoint, это отмечено как **API-only**.

## Предусловия

1. Запущен WOLF Release 0.2, доступны web/API stack.
2. Есть тестовый пользователь и выполнен вход.
3. Для тестов с датами использовать диапазон, согласованный с окружением; ожидаемые недели — ISO.
4. Подготовлены тестовые сущности: Проекты, Дела, Цели, Сферы жизни и Записи времени.
5. Для импорта использовать чистый профиль либо заранее зафиксированное состояние.

## Общий формат кейса

- **ID / Приоритет / Тип** — идентификатор, приоритет и UI/API-only пометка.
- **Предусловия** — данные и состояние перед стартом.
- **Шаги** — действия тестировщика.
- **Ожидаемый результат** — проверяемый результат.
- **Фактический результат / Статус** — заполняются при прогоне.

## Общая регрессия Release 0.2

После тикетных сценариев проверить:

- старые маршруты `/week` и `/gantt` ведут на `/calendar` и `/planning`;
- `parallel_slots` сохраняет поведение календаря Release 0.1;
- «Режим фиксации времени» не смешан с «Режимом учёта часов»;
- плановые часы не создают Записи времени;
- Сфера жизни не смешана с Областью жизни;
- система не показывает push/email-уведомления, красные предупреждения, стрики или оценочные формулировки;
- экспорт не содержит секреты, JWT, пароли и внутренние технические идентификаторы;
- данные одного пользователя недоступны другому.
