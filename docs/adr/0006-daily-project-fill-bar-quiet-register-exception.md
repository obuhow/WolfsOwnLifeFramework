# 0006 — Исключение из quiet-register для полосы заполнения проекта (Ежедневник)

- Статус: **Черновик** (2026-08-31, релиз 1.1) — ожидает финальной приёмки владельца
- Контекст: WOLF 1.1, доработка Ежедневника (бэклог справа). Решение владельца из
  grill-with-docs зафиксировано в `.scratch/release-1.1-planning-daily-ux/grill.md` (реш. A).
- Связано: `.scratch/release-0.3-ui-design/spec.md` (визуальный контракт «тихого реестра»),
  `.scratch/release-0.3-ui-design/issues/01`, `.../03`, `.../05`, `.../09`;
  тикет `.scratch/release-1.1-planning-daily-ux/issues/06-daily-project-fill-bar.md`.

## Проблема

Релиз 0.3 ввёл строгий визуальный контракт «тихого реестра», в котором **явно запрещены**:

- прогресс-бары и проценты (`issues/09` п.1: прогресс-бар с процентами в Утреннем обходе
  был удалён как «прямое нарушение запрета на прогресс-бары и проценты», заменён на `x / y ч`);
- использование зелёного (`--wolf-done-surface`) где-либо, **кроме выполненного факта**
  (`issues/01` DoD: «зелёный не становится generic CTA»; `issues/05`: fact-полоса
  `--wolf-done-surface` только при `factHours > 0`, класс `has-fact`);
- красный/тревожный сигнал перегруза (`issues/09`: дельта капасити — нейтральным текстом).

Заявка Павла (релиз 1.1, Ежедневник п.2) требует под каждым Проектом в бэклоге **полосу
заполнения**: доля недельного плана Проекта тёмным акцентом (зелёным) для уже выполненного
факта и светло-зелёным для запланированного. Пример: «Курс английского», 60 ч всего, 8 ч
в плане на неделю; 2 дела «Урок английского» по 1 ч (пн, ср); 1 ч в пн уже выполнен, 1 ч
в ср запланирован → полоса: 1/8 тёмно-зелёным (факт), 2/8 светло-зелёным (план).

Это **дважды** конфликтует с контрактом 0.3: (1) сама шкала-полоса как индикатор доли;
(2) зелёный для **плана** (зелёный зарезервирован только за фактом).

## Решение

Принять **точечное исключение** из контракта 0.3 для одного элемента — «полосы заполнения
проекта» в бэклоге Ежедневника — по прямому решению владельца:

- полоса допускается **только на этом экране** (бэклог Ежедневника), не распространяется на
  Утренний обход, Гантт, Бэклог недели и прочие реестры, где запрет 0.3 остаётся в силе;
- цветовая семантика: **тёмный зелёный акцент = выполненный факт**, **светло-зелёный =
  запланированное**, относительно недельного плана Проекта;
- проценты как **текст** по-прежнему не показываем — доля выражается длиной сегментов полосы,
  не числом «%»;
- перегруз (план+факт > недельного плана) не кодируется красным — при переполнении
  визуализируем нейтрально (тексто­вая подпись/штриховка), как принято в 0.3 для дельты капасити.

Термин закреплён в глоссарии: `CONTEXT.md` → «Полоса заполнения проекта».

## Последствия

- `+` пользователь получает быстрый визуальный сигнал недельной загрузки Проекта прямо в
  бэклоге, не считая часы глазами.
- `−` контракт 0.3 перестаёт быть абсолютным: появляется первый санкционированный зелёный
  вне факта и первая шкала-доля. Риск «расползания» — снимается тем, что исключение
  **явно ограничено** одним элементом одного экрана и зафиксировано этим ADR; любое
  повторное применение зелёного-для-плана требует ссылки сюда или нового ADR.
- Референсная реализация — тикет 06 релиза 1.1 (`issues/06-daily-project-fill-bar.md`).

## Отвергнутые альтернативы

- **Нейтральная полоса (graphite факт / светлый graphite план).** Сохраняет 0.3 дословно,
  но владелец счёл зелёную семантику факта/плана существенной для узнаваемости — отклонено
  в grill-clarify (реш. A).
- **Только текст `x / y ч`** (как в Бэклоге недели). Не даёт мгновенного визуального
  сравнения факт/план/лимит, ради которого доработка и заводилась — отклонено.
