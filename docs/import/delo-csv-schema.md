# Подготовленный импорт → Дела и Проекты

WOLF не обогащает исходный файл и не принимает доменные решения при импорте. Рабочий процесс:

Формат CSV использует обычные запятые `,` как разделители колонок. Точки с запятой `;` не требуются. Если в описании есть запятая, её можно оставить без кавычек в legacy-файле: импортёр соберёт лишние поля обратно в `description`; в новых файлах предпочтительнее заключать такое описание в двойные кавычки.

1. Исходный файл подготавливается внешней LLM.
2. LLM приводит данные к этому шаблону и проставляет Области жизни, Проекты и остальные поля.
3. WOLF проверяет формат, обязательные значения и принадлежность указанных сущностей текущему Пользователю.
4. Только после успешной проверки всего файла WOLF сохраняет данные в одной транзакции.

WOLF **не должен**:

- угадывать Область жизни или Проект;
- автоматически создавать отсутствующие Области жизни или Проекты;
- подставлять значения по умолчанию, кроме явно разрешённых форматом;
- молча пропускать неизвестные ссылки или частично импортировать файл.

## Импорт Дел

Endpoint: `POST /api/v1/delos/import`.

Запрос — `multipart/form-data`:

- `file` — подготовленный CSV в UTF-8;
- `addToCurrentWeek` — boolean, по умолчанию `false`. Если `true`, импортированные Дела добавляются в Бэклог текущей ISO-недели.

Колонки:

| Колонка | Обязательна | Формат |
|---|---:|---|
| `title` | да | название Дела, не более 200 символов |
| `date` | да | дата в формате `YYYY-MM-DD` |
| `startAt` | да | время начала в формате `HH:mm` |
| `endAt` | да | время окончания в формате `HH:mm`, позже `startAt` |
| `description` | нет | описание |
| `executionMode` | да | `SELF`, `DELEGATABLE` или `AUTOMATABLE` |
| `projects` | нет | названия Проектов через `|`; отсутствующие Проекты создаются |
| `lifeArea` | условно | точное название существующей Области жизни; обязательно, если указаны новые Проекты |

Существующий Проект разрешается повторно использовать. Если Проект отсутствует, он создаётся с указанной `lifeArea`. Область жизни должна уже существовать у текущего Пользователя и не создаётся автоматически. Один Проект может относиться к двум и более Областям жизни; для этой схемы новая связь создаётся с указанной областью.

Пример:

```csv
title,date,startAt,endAt,description,executionMode,projects,lifeArea
"Разобрать входящие письма",2026-08-15,09:00,09:30,"Проверить почту",SELF,"WOLF|Личный план",Работа
"Обновить документацию",2026-08-15,10:00,10:30,"Описание API",DELEGATABLE,"WOLF",Работа
"Тренировка",2026-08-15,18:00,19:00,"30 минут",SELF,Спорт,Здоровье
```

Если Проект не найден или недоступен текущему Пользователю, импорт отклоняется с номером строки. Импорт одноразовый: CSV не синхронизируется с каталогом после загрузки.

## Импорт Проектов

Проекты импортируются этим же подготовленным файлом отдельным endpoint импорта проектов.

Колонки проекта:

| Колонка | Обязательна | Формат |
|---|---:|---|
| `projectTitle` | да | название Проекта, не более 200 символов |
| `projectDescription` | нет | описание |
| `lifeAreas` | да | точные названия существующих Областей жизни через `\|`; минимум одна |
| `parentProject` | нет | точное название существующего родительского Проекта |
| `startDate` | нет | `YYYY-MM-DD` |
| `endDate` | нет | `YYYY-MM-DD` |
| `totalPlanHours` | нет | неотрицательное число |

`lifeAreas` не создаются автоматически. Все указанные Области жизни должны существовать у текущего Пользователя. Один Проект может иметь несколько Областей жизни.

Пример:

```csv
projectTitle,projectDescription,lifeAreas,parentProject,startDate,endDate,totalPlanHours
"WOLF","Разработка Life OS","Работа|Личное",,,120
"Документация","Технические документы","Работа|Обучение","WOLF",2026-08-01,2026-08-31,16
```

Успешный ответ импорта содержит количество созданных записей. При любой ошибке файл отклоняется целиком.
